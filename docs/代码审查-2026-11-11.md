## 一、确认的 bug

### P1（错了但不炸，用户可感知）

**P1-1 [助手] 附件 chip「点开看 / 画掩码」对新拖附件 100% 失效：把 File 对象当地址递给了 RefView**
- 位置：`web/features/chat.js:951`（`openFileView` 的 `src: f.file || f.src`）配合 `web/ui/ref-view.js:209/189/191`。
- 触发：助手抽屉拖入任意图片 / 视频 / 音频 → 点附件 chip。
- 为什么：`addFiles`（chat.js:778-780）给每条新附件设 `file: f`（真 File）**并** `rec.src = URL.createObjectURL(f)`；
  `f.file || f.src` 永远先取到 File 对象。RefView 把 `item.src` 直接当 URL 字符串用
  （`im.src = item.src` / 拼 `src="' + …"`），File 被字符串化成 `"[object File]"` →
  图片必然走「地址读不出来」、视频 / 音频是死播放器，掩码画布根本出不来。
  `attachMedia`（chat.js:931）写法相同但能用，因为 `TextAI._mediaDataUrl`（text-ai.js:1360）显式认 File——RefView 没有这层。
- 影响：四处接线里只有助手这一处坏；掩码链在助手侧断头（`f.mask` 恒空），发送本身不受影响。
- 建议修法：`src: f.src || f.objUrl || ''`（addFiles 已造好 blob: 地址，不要 revoke——芯片那排还在用）；
  或在 `RefView.open` 入口统一把 Blob / File 换成 objectURL。
- 复核：两个独立探查片各自发现，本人对照 addFiles / openFileView / ref-view 三处源码确认。
  本批的一次性探针走的是建模台 / 工作台入口（src 本就是 URL），恰好没踩这条——见「判据盲区」①。

**P1-2 [建模台] 涂鸦开着时 Ctrl+Z 跨页生效：吞掉导演台撤销，并在看不见的另一页悄悄撤掉一笔涂鸦**
- 位置：`web/pages/model.js:2645-2650`（`onSketchKeydown` 不判页面是否激活）、`model.js:3678`（document 捕获阶段注册）、
  `model.js:3689-3694`（onDeactivated 只停播放，不撤监听不关涂鸦）；受害方 `web/director/engine.js:469-476`（document 冒泡阶段 Ctrl+Z → undo()）。
- 触发：建模台开涂鸦且画过 ≥1 笔 → 切到导演台（KeepAlive 页面池，组件活着、监听还在）→ 按 Ctrl+Z。
- 为什么：捕获阶段先于导演台的冒泡监听；`view.sketchUndo()` 返回 true 后 `preventDefault + stopPropagation`，
  导演台的 undo 收不到事件，建模台的 `sketchMarks` 在用户看不见的页面上被 pop 一笔。
- 建议修法：`onSketchKeydown` 开头加 `if (!active.value) return;`；或在 onDeactivated 里 `toggleSketch(false)`（顺手把生命周期也收干净）。
- 复核：本人确认监听注册 / 注销时机、onDeactivated 内容、engine.js 监听无 capture 标志。

**P1-3 [建模台] follow 轨道上「取当前姿态 / 在播放头打关键帧」把世界坐标写进 key，采样再叠一次 follow → 双倍偏移**
- 位置：`web/pages/model/dock.js:247-258`（`currentPose` 读 `wrap.position`，即视口世界坐标，已含 follow 基准）
  → 写进 key（`dock.js:263-271` addKey、`dock.js:316-351` keyFromView 同路）
  → 播放时 `web/model3d/anim.js:315-318` 对 `tr.follow` 再 `add3(s.at, base)`。
- 触发：AI 给节点轨道配了 `follow`（契约明确支持），用户对该轨打帧或「取当前姿态」；该帧起对象瞬间跳出约两倍跟随偏移。
- 说明：旧 `addKey` 早有此病，本批新增的 `keyFromView`（#25）把同一条错路复制进了新功能，故列入。
- 建议修法：写 key 前对 follow 轨道减掉 `baseAtOf(tr.follow)`（或直接采 `A.sampleTrack` 的局部值）。
- 复核：本人对照 currentPose / addKey / anim.js follow 分支三处确认。

**P1-4 [建模台] 逐帧表单改 scale 一格，另外两格被钉到 1 而不是「此刻看起来的样子」**
- 位置：`web/pages/model/dock.js:289-312`（`baseVecOf` node 分支只处理 at / rot，scale 落到 `dock.js:311` 的 `[1,1,1]` 兜底）；
  消费方 `dock.js:369-371`；覆盖语义 `web/model3d/view.js:494-497`（key.scale 是绝对覆盖，不是叠加）。
- 触发：节点静态 `scale ≠ [1,1,1]`（AI 摆件放大、镜像件很常见）且轨道无 scale 关键帧 → 逐帧表单只改 scale 的一格。
- 为什么：`baseVecOf` 的注释承诺「另外两格就是『此刻看起来的样子』」，但无 scale 键时 `sampleTrack` 的 `s.scale` 为 null，
  node 分支又不读 `node.scale`，兜成 [1,1,1]——该帧 y/z 从 2 塌到 1，视觉跳变。
- 建议修法：node 分支补 `if (node && field === 'scale' && Array.isArray(node.scale)) return node.scale.slice();`。
- 复核：本人确认 baseVecOf 全文与消费方。

## 二、可完善优化点（非 bug）

1. **点开看 / 掩码链落成常驻 e2e**：本批的 12 项浏览器探针是一次性脚本，没有进 tests/；
   且它走的是 src 为 URL 的建模台 / 工作台入口——恰好漏掉 P1-1 那条 File 路径。建议补一条
   `tests/e2e/ref-view.cjs`：四处接线各点一次 + 画掩码 + 回传 + 助手拖新图这条特殊路。
2. **掩码的真机效果验证**：JPEG 振铃（P2-18）、掩码与原图各自独立压缩后的逐像素对齐、
   上游模型对「图后紧跟掩码图」的注意力行为——静态读码只能确认顺序与标注正确，效果要真发请求验（会产生费用，先问）。
3. **涂鸦标注的持久化取舍**：marks 仍是会话级（不进 doc、刷新即丢、换库即清）。这是本批「换场景清空」
   有意选择的方向，但如果用户开始依赖标注，下一档是进 doc（可撤销、随场景走）——需要产品决策，先记录。
4. **`reg()` 的 60s TTL**：writableKeys 借它缓存，不构成每轮网络请求；唯一小缝是 60 秒内新建的供应商
