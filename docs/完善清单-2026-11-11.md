### 1.2 本轮新确认 · P1

**P1-5 [设置/型号] 旧版型号偏好槽（`sk_model_prefs` 里不带 `:text` 后缀的 `<kid>` 键）在被第一次写新槽时，typed / off 被静默清空**
- 位置：`web/domain/gen-forms.js:183-195`（`_set` 的 `const cur = all[k] || {}` 只从**新槽**带 typed/off/got/media）+ `gen-forms.js:145-152`（setGot）、`:173-182`（setMedia）；旧槽兜底只在 `of()` 且新槽不存在时生效（`gen-forms.js:102-113`）。
- 触发（三条真实路径，已核对调用点）：
  ① 设置页每次 `paintTextCards` 对文字槽跑 `forgetTextOff`（`settings.js:1028-1041`）——旧槽有 off 记录时 setOff 会经 `of()` 合并写出（安全），但**只有 off、没有 typed** 的旧槽不会被触碰；
  ② 点「获取型号列表」→ `ModelPrefs.setGot`（settings.js:1090）；
  ③ 改某型号输入能力覆盖 → `setMedia`（settings.js:1137）。
  ②③ 建出新槽后 `of()` 的旧槽兜底从此失效：v24 前手填的型号、勾掉的隐藏，界面上永久消失。数据在 JSON 里还在，但 `customDrop → ModelPrefs.drop()`（gen-forms.js:255-267）会连旧槽一起删，届时真丢。
- 为什么 setOff/addTyped 安全而 setGot/setMedia 不安全：前者从 `of()` 现算值整份写出（等于顺带迁移），后两者的 patch 只有 got / media，typed / off 落到 `_set` 的新槽空底座上。
- 建议修法：`_set` 建新槽时先取一次 `this.of(prov)`（含旧槽兜底）作底座再打 patch；或 `migrate()` 同站把旧槽 `<kid>` 摘到 `<kid>:text`（照 `sk_text_models_` 的纪律：搬完不删，留兜底）。改前可先加一条「读到旧槽且有 typed 时 console.warn」探针确认存量面。

**P1-6 [切片/胶片格] `framesByMb` 定点分支没有超时——`grab()` 注释里点名的那个「永远等下一包」挂起，会在切片主链上复刻，该素材的切片预览永久卡死、解码器泄漏**
- 位置：`web/media-backend.js:356-389`（定点档 `sink.canvasesAtTimestamps`，时刻表封顶 `dur - 0.02`，dur 来自 `computeDuration()`）；调用方 `web/director/engine/frames.js:481` `await mb.frames(...)` 无 race / 无 timeout。
- 触发：本机素材且缺帧数不足包数 1/4（长素材几乎必然走定点档）+ 「算出来的时长比真实视频长一点」的文件——`media-backend.js:544-548` `grab()` 的注释**明说** mediabunny 对这类文件 `canvasesAtTimestamps` 永远不返回；`grab()` 自己用 12 秒 race 防了同一坑并退 `<video>` 兜底，切片主链这条却裸奔。
- 后果：挂起后 `finally { input.dispose() }` 走不到（Input + 解码器 + 网络源常驻）；而 frames.js 注释明说「slicePump 保证同一素材一次只有一趟活」——这一趟不结束，该素材之后所有切片 / 胶片格请求全部排队，界面永久斜纹。
- 建议修法：给 `framesByMb` 套与 `grab()` 同款的可中止 race（超时 dispose 并返回 `{mode:'fallback'}`，让 indexPass 现有 fallback 分支退 `<video>` 分块）；或定点档时刻按 `grab()` 的尾帧算法退 `1.5/帧率`，从源头不越界。同根的还有 P2-13（见下）。
