# 实施：文案硬约束（组件自述）（2026-11-19）

## 目标

把「尽可能减少文案，让组件本身体现功能」写成**硬约束**并全项目巡检（范围 = **所有文案所有组件**，
不止素材磁贴）：

- 组件自述：数量 / 大小限制写在素材磁贴上（「已有 N / max · 单位 · 大小」），全部现读能力声明，
  与提交拦截同一把尺；组件能自述的（档位收哪些素材、上限是多少）不另配组件外的说明行。
- 硬约束判据 `tests/copy-guard.mjs`（进 npm run test 常驻池）：
  ① 已删的组件外说明行（「这一档收：」「放哪一批素材就是哪一种请求」「换模式只改」）与
     `comboScopeNote` / `modeHead` 标识符不回归（整个 web 层含注释）；
  ② 磁贴数量句两头写死（`已有 3 / 9` 这种字面量对）即红 —— N 现算、max 现读
     （`sl.max` / `ic.maxRef` / `ic.roleMax`），与提交拦截同一把尺；
  ③ 磁贴渲染层（`web/director/engine/panel.js` / `web/pages/studio.js`）非注释行不得把
     「≤ … MB」大小文案写进字符串 —— 大小只有 `ruleText` / `fmtBytes` 一份出处。
- AGENTS.md「文案」节写入这两条规矩与判据指针。
