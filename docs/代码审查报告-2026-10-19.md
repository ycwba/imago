## 1. P0：必须优先修

> 判据：会造成重复扣费、数据丢失、功能完全不可用、或可被外部利用。建议全部在下一批提交内修完。

### P0-1 【已复现】「选择文件夹」功能完全不可用，每次请求必 500

- **位置**：`server/routes/pick-dir.js:5`（解构）、`:65` `:67` `:70` `:93`（使用）、`server/app.js:3741`（构造）
- **现象**：设置页点「选择…」→ 始终报错。`createPickDirRoute` 只解构了 `{ spawn, log, cap120, firstLine }`，但函数体用了 `readBody`（第 70 行）、`path`（65/77/114/115）、`fs`（67/77）、`ROOT`（93）—— 四个标识符都是自由的、未定义的。第 70 行 `readBody(...)` 同步抛 `ReferenceError`，被 `makeServer` 的 `.catch` 兜成 500。
- **根因**：路由拆分时只搬了函数体，没搬依赖声明；`app.js:3741` 也没在构造参数里补 `readBody` / `root`。
- **改法**：
  ```js
  // pick-dir.js:5
  const { spawn, log, cap120, firstLine, readBody, root } = ctx;
  const fs = require('fs'), path = require('path');
  // :93  cwd: root || process.cwd()
  // app.js:3741
  createPickDirRoute({ spawn, log, cap120, firstLine, readBody, root: ROOT })
  ```
- **为什么没被发现**：`tests/` 全库无一处提到 `pick-dir`（只有 `metrics-baseline.json` 的文件名清单里有它）。

### P0-2 【已复现】生成工作台「存回本机」永远显示 0 条，按钮等于死的

- **位置**：`web/pages/studio.js:2477-2489`（`pullScope`）、`:1771-1786`（`entryToItem`）、`:1788-1800`（`localAudioItem`）
- **现象**：右栏「存回本机」按钮上永远是 `0`，点击只回一句「这一屏还没有可存的产物 / 本机都已经有了」。
- **根因**：
  ```js
  return (mergedBatch || mergedItems()).filter(e => {
    if (!e || e.kind !== 'asset') return false;   // ← mergedItems() 返回的 Item 没有 kind 字段
  ```
  `mergedItems()` 的每一项都来自 `entryToItem()` / `localAudioItem()`，两者都没有输出 `kind`；`kind` 是**入参 entry** 的字段，只被用来算 `isAsset`。于是过滤第一行就把所有条目丢掉。
- **改法**：二选一 —— ① `entryToItem` 里补 `kind: isAsset ? 'asset' : 'task'`；② 判据改为 `if (!(e.assetId || e.media || e.raw)) return false;`。推荐 ①，并给 `pullScope` 补一个覆盖「服务器产物」与「刚提交的 adoptBuf 任务」的单测。

### P0-3 【已复现】语音合成超时被判「失败」，用户点重试 = 第二次付费

- **位置**：`web/pages/studio.js:1730-1734`、`:1761-1764`（`submitAudio` 的 catch）、`:1915-1918`（`loadAudioTasks`）
- **现象**：TTS 请求超时 / 5xx / 断连时，任务卡直接显示「合成失败」并出现「重试」；刷新页面时，所有 `creating` 状态的本地语音任务会被批量改成「页面刷新导致中断，可重试」。
- **根因**：`catch` 没有判 `Api.maybeSubmitted(e)`。同一文件的图片 / 视频路径在 `trackSubmit` 里做了这道判断，**唯独语音这条漏了**；`loadAudioTasks` 同样把所有 `creating` 一律当失败。
- **改法**：
  - catch 里先 `if (Api.maybeSubmitted(e)) { t.status = 'uncertain'; … }`，文案改成「结果未知，先去列表核对」，不渲染「重试即重发」。
  - `loadAudioTasks` 对刷新时仍在途的记录置 `uncertain`，只有平台明确回失败才置 `failed`。
  - 平台已成功但 `saveLocalAsset` 失败要单独标注，不能混进「可重试的创建失败」。

### P0-4 画布生成失败未过 `maybeSubmitted`，重试即第二次扣费

- **位置**：`web/pages/canvas.js:594-598`（`runNode` 的 catch）
- **现象**：节点生成视频/图片时创建请求超时或 5xx，节点被写成 `status:'error'`，提示「这一条失败了」，用户点生成就是第二次请求。
- **根因**：全站「提交不知道平台收没收到」的唯一判据是 `Api.maybeSubmitted`，工作台与导演台都用了，画布这一处没用。
- **改法**：catch 里先判 `Api.maybeSubmitted(e)`，是则写 `uncertain` + 「结果未知，先刷新核对」，不提供普通重试、不自动重提。

### P0-5 【已复现】资产库「取消任务」假成功：吞掉错误还把状态改成失败

- **位置**：`web/pages/assets.js:530-537`
- **现象**：点「取消任务」，平台回 403/404/500 时，错误被 `.catch(() => {})` 吞掉，随后无条件执行 `it.status = 'failed'`。轮询器因状态已失败而不再扫这一条 —— 平台上的任务仍在跑、仍可能计费，界面却永久显示「生成失败」。
- **根因**：取消结果没区分成功/失败；失败后错误地改了本地状态。同页的「取消全部」(`:1007-1013`) 反而判了 `Api.canCancel`，两条路径口径不一致。
- **改法**：`await cancel` 成功后才改状态；失败 `Toast.err` 并**保留 running**，让轮询继续跟踪；整段改用 `Wb.cancelTask`（`web/ui/workbench.js:2430`）一处实现。

### P0-6 资产库「重试」无提交锁：双击 = 两条付费任务

- **位置**：`web/pages/assets.js:539-549`
- **现象**：快速双击重试，两次 `AssetLib.retry()` 并发；重试请求超时/5xx 时页面只说「重试失败」，没有 `maybeSubmitted` 分支。
- **改法**：进入时**同步**禁用按钮并置 `retrying` 标记，`finally` 释放；失败判 `Api.maybeSubmitted`，提示先刷新核对，不要呈现成普通可重试失败。

### P0-7 工作台生成按钮的 `disabled` 会被 `Wb.ready` 重新打开

- **位置**：`web/pages/studio.js:1595-1607`（`$('go').onclick`）、`web/ui/workbench.js:2407-2411`（`__rdRun`）
- **现象**：点「生成」后按钮被置 `disabled`，但只要用户动一下提示词/参数/类型，`Wb.ready` 的 `__rdRun()` 就按 `submitBlockReason()` 重写 `btn.disabled`；提示词合法时按钮被**重新启用**。此时若还在上传参考素材（`pendingSubmits` 尚无记录），再点一次会真的发出第二份创建请求。
- **根因**：`Wb.ready` 把「就绪」与「提交中」混成一个 `disabled` 标志；`onclick` 顶部没有 `submitting` 守卫。
- **改法**：把「提交中/有未决提交」并入 `submitBlockReason`；`onclick` 第一行加同步守卫 `if (submitting) return;`，整个提交流程 `finally` 复位。

### P0-8 一次生成多条时，未决提交记录会被第一条完成「解开」

- **位置**：`web/pages/studio.js:1383-1414`、`:1625-1637`、`:1665-1677`
- **现象**：`draw > 1` 或 `total > perReq` 时，循环里把**同一个 `rec` 对象**反复传给 `trackSubmit`。第一个请求完成即把 `rec.state='settled'`，`pendingSubmits` 里其余项指向同一对象，`unresolvedSubmit()` 立刻返回 `null`，界面不再拦截 —— 而第二个请求可能仍在途。
- **改法**：每次 `trackSubmit` 创建独立的 `{ state, at, … }` 记录；`unresolvedSubmit` 按「仍有任一 inflight/uncertain」判断，不按对象状态。

### P0-9 【已复现】转发闸排队中的创建 POST，客户端已断开仍会发出去

- **位置**：`server/app.js:3530-3537`（`start`）、`server/routes/relay.js:219-238`
- **现象**：批量生成占满某平台名额时，创建请求进入 `g.queue`；用户刷新/关页后，名额释放时 `start()` 仍执行 `onSlot(release)` → `once(false)` → `up.end(body)`，POST 真的打到上游并创建任务（可能计费）。
- **根因**：`relayTake` 的 `start()` 只做 `g.inflight++` 和看门狗，**没有把「请求是否还活着」传进去**。重试分支 (`relay.js:202`) 明明有 `if (res.destroyed || res.writableEnded) { release(); return; }`，队列分支漏了同一道检查。
- **改法**：
  ```js
  const start = () => {
    if (res.destroyed || res.writableEnded || req.aborted) return;   // 不占名额、不发请求
    …
  ```
  同时给排队加 `RELAY_QUEUE_TIMEOUT`，release 时若队列项已死直接跳过。

### P0-10 【已复现】云同步的提示词归档名可路径穿越，任意写 `.md`

- **位置**：`server/cloud-store.js:71-76`（`parseDavList`）、`:160-170`（`cloudSyncPrompts` 落盘）
- **现象**：WebDAV 上存在名为 `..%2F..%2Fevil.md` 的条目时，拉取会写到 `PROMPTS_DIR/../../evil.md`。
- **根因**：
  ```js
  const name = decodeURIComponent(href.trim().replace(/\/+$/, '').split('/').pop() || '');
  if (md) { if (!/\.md$/i.test(name)) continue; key = name; }   // ← 只校验后缀
  ```
  **先 `split('/')` 再 `decodeURIComponent`**，所以 `%2F` 解码后才变成分隔符，绕过了 pop() 的分段。随后 `fs.writeFileSync(path.join(dir, name), …)` 只用了 `flag:'wx'`（防覆盖，不防越界）。数据键那条分支有 `DATA_KEY_RE` 保护，md 分支完全没有。
- **改法**（两条都要）：
  ```js
  const dec = decodeURIComponent(...);
  if (dec !== path.basename(dec) || /[\\/:*?"<>|\u0000-\u001f]/.test(dec)) continue;
  const full = path.resolve(dir, name);
  if (!full.startsWith(path.resolve(dir) + path.sep)) continue;
  ```

### P0-11 【已复现】`GET /data` 目录读失败返回空清单，客户端会全量补传覆盖服务器

- **位置**：`server/data-store.js:25-42`（`dataList` 外层 `catch { return [] }`）、`web/ui/datasync.js:326-337`
- **现象**：`.data` 被 ACL / 杀毒 / 同步盘短暂拒绝，或 `DATA_DIR` 在网络盘掉线时，清单变成 `[]`；客户端 `pushAll` 看到「服务器什么都没有」，把本地所有键写回服务器 —— 正是第 33 行注释要防的「云端较新那份被顶掉」。随后还会进云同步。
- **根因**：内层单文件 `stat` 加了保护，外层 `readdirSync` 仍吞异常并伪造「空」。这与 AGENTS.md §6.2「读不出来绝不等于本来就没有」直接冲突。
- **改法**：只有 `ENOENT` 才返回 `[]`；其余错误让路由回 500（或带 `degraded:true` 让客户端**跳过补传**）。

### P0-12 【已复现】CSP 拦截内联 `onerror`，裂图/占位永远收不掉

- **位置**：`web/pages/assets.js:452`、`web/pages/studio.js:602`、`web/domain/asset-picker.js:374-375`
- **现象**：图片 404 时裂图一直挂着；控制台出现「Refused to execute inline event handler」的 CSP 报错。
- **根因**：`shell.html:5` 的 CSP 是 `script-src 'self'`，内联事件处理器一律被拦；这些 `mediaAttrs` 又被原样拼进 `<img>`。
- **改法**：删掉所有 `onerror=`，在 `Wb.thumbs.bind` / 卡片创建后用 `addEventListener('error', …)` 统一处理（`Wb.thumbs.bind` 已经是唯一的缩略图绑定入口，加一段即可覆盖全站）。
- **附带**：`tests/e2e` 要求「必须检查控制台错误(CSP 违规)」，但这几条只在图片加载失败时才触发，所以 e2e 没抓到。建议加一条契约测试：对已知失效的图源调一次 `bind`，断言没有 CSP 报错。

## 6. 架构

> AGENTS.md §17 已明确「导演台保持命令式、`engine.js` 是大文件」是决定，不在建议范围内。

### 6.1 高

1. **`server/app.js` 名为组合根，实际承载 6 个域约 3300 行**（`264-1462` 供应商注册表、`1463-1683` HTTP 基建、`1776-2420` 本机资产、`2432-3262` 渲染队列、`3310-3610` 闸与体检、`3774-3888` 分发）。
   证据：`routes/save.js:8-13` 从 app 注入 17 个函数、`routes/render.js:8-25` 注入 18 个 —— 路由只是 HTTP 适配器，规则仍在 app。与 §12「每个路由只在自己的 routes/*.js 里实现」不符。
   建议原样搬出 4 个文件（`registry-config.js` / `local-assets-store.js` / `render-jobs.js` / `relay-gate.js`），目标压到 600 行内；`handleRequest` 的 if 链改 `[match, handler]` 表。
   **额外收益**：`tests/providers-validate.cjs:5-20` 现在只测 fixture，搬出来就能直接校验真实 `REGISTRY`。

2. **三个巨型闭包没有命名空间边界**：`assetlib.js` 一个 IIFE 里塞了 10 个公开面（`Api`/`AssetLib`/`ModelPrefs`/`AiGen`/`AdvParams`/`AdvExtras`/`TtsAdv`/`CharLimits`/`VoiceNote`/`AiStream`）；`ui.js` 塞了 15 个（`Chips`…`DatePicker`）；`chat.js` 里 `TOOLS`/`ACTS`/schema/会话/看护/UI 全在一个闭包。
   建议按**已有的** `window.<Name>` 面切文件（不改调用点），顺序：`Api` → `AssetLib` → 表单族。

3. **生成前校验有两套**：页面 `studio.js:1140-1158`（`submitBlockReason` + `shapeGaps` + `blockedSlotKinds` + `advExtras().bad`）与助手 `chat.js:1121-1260`（`checkParam` + `genCheck`）。两边都读 `Capabilities`，但组合方式与文案各写一套，新增一条规则要改两处且没有一致性测试。
   建议抽 `web/domain/gen-rules.js` 的 `whyNot(...)->{code,args}|null`，两侧只做文案翻译；补一致性测试。

4. **动作注册表 fail-open**：`chat.js:2902-2907` 动态 import 失败时 `actionReg = null`，`:4749` / `:3537` 接着直接调 `table[name].check` / `ACTS[name].run` —— 一旦加载失败，所有写动作**绕过** planToken、幂等键、串行锁与超时中断。
   同一处的默认值也会骗人：`:2855` `ACTION_EFFECT[id] || 'read'`，新动作忘登记就被当成只读（不标 irreversible、不画撤销、花钱动作没有 cancel）。
   建议 fail-closed + 注册时缺 `effect` 直接抛错。

5. **错误通道三分裂**：`Toast`（用户动作回执）、`ErrBanner`（只接 `window.error`/`unhandledrejection`）、服务端健康账（`health.js`，只在内存、重启清零）互不连通。页面 boot 的 catch 只写局部状态（`director/index.js:120`、`assets.js:1029`、`studio.js:2693`、`chars.js:1972`），页面空着而服务端一无所知；`app.js:196` 的 Vue errorHandler 也不进 ErrBanner。
   建议 `web/core/report.js` 的 `Report.fatal/warn` + `POST /client-error`（进 LOCAL_ONLY + 限流 + `noteFault`）。

6. **资产/任务写入口不唯一**：服务端 4 个写索引的入口只有 1 个加锁；客户端 `assets_cache_v1` 有 5 处写、`studio_tasks_cache_v1` 1 处，两份缓存覆盖同一批任务；身份键有 4 把（`entryKey` / `selKeyOf` / `assetKeyOf` / `taskKey` / `itemKey`）。
   建议 `index-store.js` 提供 `update(fn)` 串行队列；缓存写入移进 `AssetLib.load` 的回调；页面键统一调 `AssetLib.entryKey` / `Wb.taskKey`。

7. **架构护栏只看得见 ESM**：`tests/architecture.cjs:33-41` 的 `importsOf` 只收 `.` 开头的 spec，24 个 IIFE 经典脚本完全没有 import，所以「分层方向正确」在这半边是空断言。实测反例：`domain/assetlib.js:2059/2088` 读 `window.Confirm`、`ui/workbench.js:534/1242` 读 `window.AssetLocal` —— 按测试自己的矩阵 `ui` 不准依赖 `domain`、`domain` 不准依赖 `ui`，两个方向都违反，测试却全绿。
   建议扫 `window.<Global>=` 建符号→层表，再扫读取点，按同一张矩阵判红。

#### ① `tests/routes-smoke.cjs` —— 一次性防住「路由缺依赖」这类

// 对 server/routes/*.js 的每个工厂：造一份 ctx（真实依赖 + Proxy 兜底），
// 用假 req/res 走一遍 happy path，断言不抛 ReferenceError、有响应、状态码合理。
const ctx = new Proxy(realCtx, {

});
