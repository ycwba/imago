# AI 创作工作台

本地网页工具集：**导演台**（视频分镜生成 + 手动剪辑 + 导出成片）、**生成工作台**（文生视频 / 生图 / 语音合成合并成一页，左栏创作、右栏三种类型合在一起的历史）、**拍短剧**（一句故事 → 分场剧本 → 认角色 → 预演 → 成片，全部在本机串起来）、**素材库**、**资产库**、**我的收藏**、**用量与余额**、**设置**，
外加一个活在外壳层的 **AI 助手**（悬浮球 + 抽屉）。

> 给协作方（含 AI 助手）：动手前先看 **[`AGENTS.md`](AGENTS.md)** —— 那里列了必须遵守的约定
> （统一路由、能力驱动、公共模块复用、密钥与用户数据、改完必须自测）与已知的平台事实。

## 使用

1. 安装 Node.js（https://nodejs.org）
2. 双击 `启动.bat`（或手动运行 `node proxy.js`）
3. 浏览器会自动打开主页（导演台），地址里那个端口就是**这份代理真正跑起来的端口**

默认端口 6200，可以在项目目录的 `.env` 里写一行 `PORT=xxxx` 固定下来（改这里要重启代理）。
Windows 的 Hyper-V / winnat 开机时会保留走一段连续端口，撞上时启动报的是 `listen EACCES`
（不是「端口被占用」，`netstat` 上也看不见那个号）。`启动.bat` 因此会真 bind 一次试探可用的号，
换了端口会在屏幕上说明换成了哪个；实际用的号记在 `.proxy-port`，所以「停止 / 重启 / 退出」关的都是
**真的那个端口**（选 4 退出前也会把服务停掉，不再留一个后台窗口占着端口）。

## 导演台功能

- **分镜管理**：场景 → 镜头两级结构；镜头可复制、删除、拖拽排序；「贴剧本，一键拆分镜」把多行剧本自动变成镜头。
- **生成**：每个镜头按「生成条数」创建多条候选；实时显示排队位置 / 进度 / 报价；第一条成功的自动选用。
- **画面素材**：开头画面（首帧）、结尾画面（尾帧）、最多 9 张参考图（单张 ≤ 5 MiB）、参考视频（MP4 ≤ 200MB，需含音频轨）、参考音频（MP3/WAV ≤ 50MB）。上传图片自动压缩（最长边 1600），节省本地存储。
  **「首帧」也能直接选视频**：选中后在本机浏览器里取该视频的**最后一帧**当首帧图（常见用法：把已有视频接着往下生成），全程不经过服务端。
- **素材入口随模型能力动态变化**：能上传什么由所选模型的能力声明决定（上游 `/models` 的 `modes.inputs` 优先，registry 的 `modes` 兜底）。
  同一声明里属于**不同请求模式**的输入不能同时提交（例如首尾帧 ↔ 参考素材，见 `Capabilities.conflictMap`）：
  传到其中一组后，另一组槽位自动变灰点不动（鼠标悬停/点击会说明原因），清空已选的那一组即可切回；两组都有的历史数据在生成时会被明确拒绝。
- **选用与剪辑**：候选中「用这条」；入点/出点截取片段；时间线分「本镜 / 全片」；「▶ 播放成片」按顺序连播所有已选用镜头；「⬇ 导出成片」实时连播并录制为 webm 文件（含声音与剪辑区间）。
- **撤销 / 重做**：`Ctrl+Z` 撤销、`Ctrl+Y`（或 `Ctrl+Shift+Z`）重做，最多 50 步（输入框内仍用浏览器原生撤销）。
- **导入 / 导出**：导出为 JSON（含图片素材）；导入时作为新短片并入工作区，不覆盖现有项目。
- **本地视频**：导入的本地视频文件本体存 IndexedDB，刷新页面后仍可播放 / 剪辑 / 导出。
- **URL 过期自愈**：vgenv 签名地址过期后，播放/导出前自动重新拉取最新下载地址。

## 生成工作台（视频 / 图像 / 语音合并成一页）

`studio.html`（侧边栏 → 生成工作台）。左栏顶部一条类型分段开关（视频 / 图像 / 音频）在左、模型下拉在右；
换类型时下面换成那一类自己的表单（提示词框、AI 润色、素材槽、高级设置），右栏始终是**三种类型合在一起**的历史。

- **类型也写在地址栏里**：`studio.html?t=video|image|audio`。侧栏只保留一个入口，别的页面（资产库「复用」、AI 助手）
  跳转时用这个参数直接落到对应类型；直接手输旧的 `/video.html`、`/image-gen.html` 也会被代理转到这一页并带上类型。
- **模型下拉按平台分组**（`optgroup` 是平台名、选项文字是型号原始名，如 `minimax/h3`、`img-2-5s`）。
  视频 / 图像 / 语音三类都按平台分组（语音台以前只服务一家，2026-10 起也按平台分组了 ——
  加第二家语音平台时它在下拉里根本选不到）。每一类各自记住上次选的型号。
- **素材槽按能力声明渲染**：视频有首帧图 / 尾帧图 / 参考图 / 参考视频 / 参考音频，图像只有参考图，语音是参考音频。
  首帧槽可以直接选视频（浏览器内取它的最后一帧）。素材从统一选择器挑，也能**把右栏卡片直接拖到左栏**落进对应槽位。
- **右栏就地播放**：视频卡片直接内嵌播放器（缩略图当封面，不再强制放大），音频同样可就地播放；
  要看大图点卡片上的「放大」。
- **任务卡片一律来自平台接口（语音除外）**，本地不留图片 / 视频任务记录；首屏先用本机列表缓存画出来，再等平台列表覆盖。

### 语音那一栏

- **接口全部来自注册路由**：`/registry` 里 `kind: 'audio'` 的平台会被自动识别，页面不认识具体厂商。
- **产物直接进资产库**：平台同步返回的音频（base64）由代理落盘成「本地资产」（`.assets/`，见 `POST /local-assets`），
  资产库按条目自己的大类型（`图片` / `视频` / `音频`，代理按落盘扩展名与 mime 现算）展示与筛选，
  可试听、下载、另存、被视频的「参考音频」选用（也可用于音色复刻）。
- **音色复刻**：参考音频支持「资产库」或本地文件（mp3/wav ≤10MB），随请求以 `data:` 形式提交。
- **pcm16 裸流**会自动封装成 WAV（24kHz 单声道 16bit），浏览器可直接播放。
- **模型列表与费用都是动态的**：模型下拉读平台的 `/v1/models`（按 `modelsFilter` 过滤，新模型自动出现）；
  费用按 `pricing` 声明计算（`per_1k_chars` 配模型上的 `price.per1kChars` 才显示预估），
  平台没给价格就显示「平台未提供价格」；每次合成的**真实用量**（tokens）取自接口响应并显示在卡片与详情里。
  没有声明单价时页面不会自己编价格。

### 添加一家新的语音平台（只改一处）

在 `proxy.js` 的 `REGISTRY.providers` 里加一条即可（不需要动任何页面代码）：

```js
{
  id: 'xxx', name: 'XX 语音', displayName: 'XX', kind: 'audio', relay: '/xxx',
  base: 'https://api.xxx.com', keyEnv: 'XXX_API_KEY',
  endpoints: { create: '/v1/tts', list: 'local:/local-assets' },   // list 指向本地资产库
  models: [{ id: 'tts-1', name: 'TTS-1', modes: ['text_to_speech'] }],
  tts: {
    voices: [{ id: 'v1', name: '音色1', lang: '中文', gender: '女' }],
    formats: ['wav'], textRole: 'assistant', styleRole: 'user',
    audioParam: 'audio', responsePath: 'data.audio',   // base64 音频在响应里的点路径
    mime: { wav: 'audio/wav' }, maxChars: 3000,
  },
  list: { dataField: 'data', statusMap: { succeeded: 'done' }, selfAsset: true,
          media: { by: 'media_type', videoPrefix: ['视频', 'video'], imagePrefix: ['图片', 'image'], fallback: '音频' } },
  create: { endpoint: 'create', template: { model: '{{model}}', text: '{{text}}', voice: '{{voice}}', format: '{{format}}' } },
}
```

`create.template` 里 `{{字段}}` 由工作台填（值为空则整项省略）；转发的 relay 前缀由通用转发自动接管，密钥从页面或 `.env` 注入。

`responsePath` 取到的音频默认按 **base64** 处理；平台给的是十六进制就加 `encoding: 'hex'`
（minimax `t2a_v2` 就是，页面会先按十六进制解码，认不出来再退回按 base64 试一次）。
一家平台同时做文字与语音时给两条 provider 同一个 `keyId`，设置页就只出一张密钥卡。

### 添加一家「同步返回」的生图平台（只改一处）

OpenAI 兼容的生图接口（OpenAI 自己、硅基流动、大批中转站）形状都一样：
`POST {base}/images/generations` **当场把图返回**，没有任务号、没有轮询。这类平台在注册表里这样声明：

```js
create: {
  endpoint: 'create',
  idempotencyKey: false,                    // 没有幂等键约定 → 不自动重试（重试 = 重复扣费）
  sync: { items: 'data', url: 'url', b64: 'b64_json' },   // 产物数组在哪、地址字段、base64 字段
  body: { model: 'model', prompt: 'prompt', image_size: 'size', n: 'count' },
  //            ↑ 键是**上游字段名**、值是**标准字段名**（写反了字段会被静默丢掉）
},
list: { /* 与语音一样指向 local:/local-assets */ },
```

页面照 `create.sync` 取产物、**把字节取回来存进本机资产库**再刷列表 —— 这类外链一般只有一小时有效
（硅基流动官方写明），直接摆进列表明天打开就是一排裂图。产物存好后卡片上的平台名按**条目自己记的**
`provider` 归属（本机资产库是多家平台共用的一条列表来源，否则先读到的那家会把别家的产物标成自己）。

画幅参数有**两套**，别混发：比例（`16:9`，标准字段 `ar`）与「宽×高」（`1024x1024`，标准字段 `size`）。
平台认哪套就在 `options.sizes` / `options.aspect_ratios` 里声明哪套，页面据此显示对应那一列。
（视频那几栏现在也共用同一个「尺寸」下拉：SiliconFlow 视频只认 `1280x720 / 720x1280 / 960x960`，
传比例写法必被拒 —— 声明了 `options.sizes` 的型号就出这一列，没声明的不出现。）

### 添加一家「产物只给文件号」的视频平台（只改一处）

有一族平台**不给可播放地址**，只给一个 `file_id`，要再换一次接口才拿得到真的产物
（MiniMax 的 `/v1/files/retrieve` 就是这一族，很多平台的「文件下载」接口也是）。这一族以前只能整个不接：
产物字段永远空着，任务卡在「生成中」。现在注册表里用两处声明表达它，**页面与轮询器只调一个入口**：

```js
endpoints: {
  create: '/video_generation',                      // POST {model, prompt}
  poll: '/query/video_generation?task_id={id}',    // GET → {status, file_id}
  retrieve: '/files/retrieve?file_id={id}',        // ← 这一族专用的第三个端点
},
retrieve: { idFrom: 'file_id', urlFrom: 'file.download_url' },
list: {
  map: { id: 'task_id', status: 'status', fileId: 'file_id', error: 'status_msg',
    /* outputUrl 不用声明 —— 换回来的地址写进条目的 __url，parseItem / normalize 读不到产物地址时兜底用它 */
  },
  statusMap: { Success: 'done', Fail: 'failed' },
},
```

`Api.resolveItem(prov, raw)` 在轮询与列表两条路上各换一次（同一轮里同一个文件号只问一次，60 秒短缓存 ——
换回来的多半是带有效期的签名地址）。没换到就照原样判成「生成中」，下一轮再换；**不猜字段、不按平台 id 补判据**。

已接的三家视频平台：`minimax-video`（走 retrieve）、`siliconflow-video`（产物地址直给，但**只有 10 分钟有效** ——
正是「产物自动存本机」要解决的那一族）、`zhipu-video`（`/async-result/{id}` + `video_result` 数组那一族）。
注意这三家的响应字段路径是按公开资料声明的，**注册表 v9 之后尚未用真实密钥跑通过一次**。

## 产物自动存本机 + 地址三级回退

产物地址的有效期完全在平台手里（SiliconFlow 视频 10 分钟、批量 OSS 签名 1 小时、平台清理任务后连 id 都不认）。
设置 →「外观与界面」里有两档开关：

| 开关 | 键 | 默认 | 作用 |
| --- | --- | --- | --- |
| 产物自动存本机 | `sk_media_local` | 开 | 生成完的图像 / 视频 / 语音**当场把字节存进本机资产库**（`.assets/`，与同步生成的语音/生图同一张索引），任务详情（参数、费用、耗时、状态、平台原话）随文件一起留底 |
| 优先用本机文件 | `sk_media_prefer` | 开 | 卡片直接读本机副本；关掉则仍直连平台地址（平台 CDN 更快，代价是地址一过期就什么都没有） |

显示地址按三级回退，**判据全在代理与一个全局监听里，页面一行都不用改**：

1. **能看的地址过期了 → 用本机那份。** `AssetLib.normalize`（全项目唯一产出条目的地方）给每个资产条目查本机镜像索引，
   勾了「优先用本机」就把 `src` 换成 `/asset/<本机号>`。
2. **本机文件被删了 → 自动回源平台。** `/asset/<id>` 在本地文件不在、而索引里记着 `upstream` 时 302 到
   `/getv?url=…`（绕一跳而不是直指外链，页面因此始终同源）。
3. **两边都没了 → 明写「已丢失」。** `AssetLocal` 装一个 `document` 捕获阶段的 `error` 监听：
   卡片、列表、灯箱、详情面板一次全覆盖，试过两边仍挂就插一个「已丢失」角标，而不是留一张裂图让人猜。

单个文件超过 200 MB 不自动存（界面上照常用平台地址显示）。索引本身只是「哪条产物在本机、对应哪个本机号」的指针
（`sk_local_mirror`，上限 2 万条，与代理的 `LOCAL_INDEX_MAX` 对齐），**不同步到云端** —— 另一台机器上那些文件不存在。

## 架构

**页面只能访问下面这些本地路由**（完整说明见「统一路由（硬性约定）」）：

```
浏览器 ──> proxy.js (localhost:5175) ──> 各生成平台 API
             ├─ /registry          API 注册路由：提供商 / 模型 / 能力声明
             ├─ /capabilities      能力接口：按平台取回模型能力（页面只认这一条）
             ├─ /sparkcine/*       生图 / 视频接口转发（relay 前缀，按 registry 声明）
             ├─ /vgenv/*           VGENV 视频接口转发
             ├─ /mimo/*            MiMo 语音接口转发
             ├─ /siliconflow/*     硅基流动（文字、生图、视频共用一把密钥）接口转发
             ├─ /minimax/*         minimax（文字、语音、视频共用一把密钥）接口转发
             ├─ /zhipu/*           智谱 CogVideoX 视频接口转发
             ├─ /textai/*          文字 AI（OpenAI 兼容，DeepSeek）转发
             ├─ /openrouter/*      文字 AI（OpenAI 兼容，OpenRouter，默认供应方）转发
             ├─ /asset/<id>?v=2    平台图片字节直出（永不过期）
             ├─ /getv?url=         外链媒体中转（支持 Range：播放 / 抽帧 / 量体积）
             ├─ /fetch?url=        下载中转（dl=1 带下载头）
             ├─ /getfile?url=      取字节中转（上传 / 转存用）
             ├─ /s3put?url=        存储直传中转（预签名地址，绕过跨域）
             ├─ /local-assets      本地产物落盘 / 清单（语音等）
             ├─ /render*           成片合并 / 导出（服务端 ffmpeg）
             ├─ /data /prompts /cloud   数据落盘 / 提示词归档 / 云同步（只允许同源）
             ├─ /env-status      密钥来源状态（只报有没有、尾号，不泄露明文）
             └─ /sys-status      本机环境体检（代理版本 / ffmpeg 与 ffprobe 能不能跑 / 三个落盘目录可写性）
```

- **统一路由是硬性约定**：页面里的任何请求都只能打到本地代理（同源相对路径），**不直连任何外部域名** ——
  完整规则、全部路由与自查命令见下面「统一路由（硬性约定）」一节。
- **为什么要代理**：浏览器同源策略（CORS）会拦截页面直连生成平台的请求；代理把跨域请求变成服务器对服务器。密钥也由代理注入，页面不接触明文。
- **外部媒体一律走本地路由**：上游给的产物地址是**带签名的外链**（如 VGENV 的 OSS 地址），
  页面里的 `<img>/<video>/fetch` 统一经 `Api.mediaSrc()` 换成 `/getv?url=…`（代理取回、支持 Range，
  播放 / 抽帧 / 量体积 / 下载都同源）；`AssetLib` 规范化条目时就把 `src` 换好，所以资产库、收藏、作品库、
  视频台任务卡、导演台播放器都不会直连外部域名（实测各页 0 条直连外链）。
- **静态服务安全**：只放行工作台自己的前端资源（允许的扩展名），**点开头的文件一律拒绝**（`.env` / `.gitignore` / `.assets` …），
  另外显式挡掉 `proxy.js`、`proxy.log`、`proxy.out.log`、`启动.bat`，并拒绝路径穿越。`proxy.log` 超过 2 MiB 自动截断（运行中也会轮转，不只启动时查一次）。
- **代理的护栏**：所有出站请求带 60 秒超时（上游挂起不会再永久占用连接）；请求体有上限（超限回 413）；
  单个请求出错不会拖垮进程（分发层包了 try/catch + `clientError` 兜底）；Ctrl+C / 退出时会杀掉所有 ffmpeg 子进程；
  渲染走队列（默认并发 1，排队上限 20），任务记录 30 分钟回收、`.renders` 只保留最近 20 个成片。
- **接入新的生成 API**：在 `proxy.js` 的 `REGISTRY.providers` 里加一条配置（转发前缀、上游地址、端点、模型、输入 role 与上传字段命名），
  客户端会自动按「当前素材需要的输入 role」过滤模型下拉。视频模型要声明 `inputRoles`（role → `{ max, group }`）：
  `first_frame` / `last_frame` 一组（`group: 'frame'`），`reference_image` / `reference_video` / `reference_audio` 一组（`group: 'ref'`）；
  图片模型声明 `reference_image` 即可。上传接口的字段名（含 `sha256` 发不发）用 `create.uploadFields` 声明 ——
  SparkCine 是 `filename/content_type/byte_length` 且 **`sha256` 必填**，VGENV 是 `fileName/contentType/sizeBytes` 且
  **拒绝未知字段**（多发一个 `sha256` 就 400），以前写死无条件发 `sha256`，VGENV 的每一次上传都失败。
- **素材输入与互斥都由能力声明推导**（`assetlib.js` 的 `Capabilities`，四个工作台共用）。
  判定顺序（`specs(model)`）：
  1. **平台自己的能力声明**（`/models` 的 `modes.inputs`）优先 —— 平台说这个模型收哪些参考素材，
     界面就只出现哪些入口。例如 SparkCine 的 `h3-video` 只声明了 `reference_image` 与 `reference_audio`，
     于是视频台 / 导演台上只有「参考图 / 参考音频」，首尾帧与参考视频的入口不出现（不赌它支持）。
  2. 平台没有能力接口（VGENV）或接口只声明了一部分时，用 registry 的 `models[].inputRoles` 兜底
     （`{ role: { max, group } }`），这也是 VGENV 能出现全部五个入口的原因。
  3. `inputRoles` 在同名 role 上还能**收紧上限**：平台可能写着 `reference_audio.max = 3`，
     但提交模板是单个 `{asset_id}` 对象，就以 1 为准（界面不会放开到 3 个却只发出去一个）。
  - 判断「模型不支持」用 `Capabilities.specs(model).some(s => s.role === R)`；视频台的文件输入、
    拖放、语音台的音色输入、图片台的参考图入口都按它**显隐或拒收**（`canAddRef()` / 槽位不存在即拒绝），
    输入框的提示文案也只列当前模型真的支持的素材类型。
  - `Capabilities.specs(model)` → 该模型接受哪些 role、上限多少；`modelsFor(providers, needRoles)` 按「这次要用到的 role」挑模型。
    模型下拉不再按 mode **名字**过滤 —— 上游各家的 mode 名不一样（SparkCine 是 `image_to_video`/`multimodal_reference`，
    页面自己用的是 `first_last_frame`/`reference_images`），按名字过滤会让「加了首尾帧之后支持它的模型反而从下拉里消失」。
  - **互斥按 `group` 判**：`first_frame`/`last_frame` 是 `frame` 组，`reference_image`/`reference_video`/`reference_audio` 是 `ref` 组，
    不同组不能同时用（一次请求只能选一组）。界面在**添加素材的那一刻**就把另一组置灰并就地说明，
   `Capabilities.blockedRoles` 供槽位禁用，`illegalPairs(model, 已用role)` 判断「已经同时用上了」（导入 / 历史数据），
   `unsupportedRoles(model, 已用role)` 判断「换模型后留下的、新模型不接受的素材」。
  - 这三件事在**提交前都会再拦一次**（`submitCandidate` / `submitBlockReason`），不静默丢掉用户选的素材。
- **能力统一走一条本地路由：`GET /capabilities?provider=<平台>`**（`proxy.js` 的 `handleCapabilities`）。
  页面不需要知道每个平台的能力接口地址、密钥和返回格式 —— 代理负责找端点（registry 的 `endpoints.models`）、
  注入密钥、请求上游、**失败或没声明就回退到 registry 声明并附上原因**，返回
  `{ source:'api'|'registry', models:{id:原始模型}, registryModels:[...], note }`；服务端缓存 60 秒（`&noCache=1` 强制回源）。
  接入新平台只要在 registry 里写 `endpoints.models`，能力的读取、回退、展示全自动。
  设置页每个声明了能力端点的平台旁边有一个「↻ 能力」按钮：点一下强制回源（`&noCache=1`，绕过 60 秒缓存），
  就地显示「✓ 上游 N 个模型」或「✓ 平台声明」，悬浮能看到来源说明 —— 上游上了新模型时不用等缓存过期。
- **每次选择模型都会再问一次能力接口**（四个工作台都已接入：视频 / 图片 / 语音 / 导演台）：
  视频台与图片台先按现有声明立刻渲染（不阻塞），接口回来后再按真实能力重画参数与上传槽位；
  语音台与导演台在切换模型时等接口回来（状态栏显示「正在读取模型能力…」）再重画，不打断输入。
  界面上有一行小字标明来源（「能力来自上游接口」/「按平台声明兜底」/「该平台没有声明能力接口…」）。
  能力刷新只更新**用户没动过**的参数，手选的 1080p 不会被接口返回的默认值冲掉；语音台的音色方式
  （预设 / 设计 / 复刻）也是先看能力接口返回的 `modes`（`voice_design`/`voice_clone`），没有才退回 registry 的 `ttsMode`。
- **模型下拉按 API 来源分组、显示原始调用名**：四个工作台（视频 / 图片 / 语音 / 导演台的分镜模型、
  画面模型、选图弹层）都用 `<optgroup>` 按平台分组（VGENV / SparkCine / MiMo …），
  选项文字就是**平台那边的 model id**（`minimax/h3`、`h3-video`、`img-2-5s`）—— 提交给上游的就是这个名字，
  排查时一眼对得上；友好名（“Minimax H3”“H3 视频（SparkCine）”）放在悬浮提示里。
  自定义下拉组件（`ui.js` 的 `Dropdowns`）因此支持了 `optgroup`（渲染成 `.dd-grp` 组标题 + 分隔线）；
  以前三个工作台各写一份自己的下拉实现，现已合并成生成工作台里的一套（同一份代码服务视频 / 图像 / 语音）——
  以前改一处漏一处，分组和悬浮名就只在部分页面生效。
  生成工作台里 option 的 `value` 是 `平台id::型号id`（选项文字仍然只写型号原始名）——三种类型共用一个下拉、
  每类各自记住选了谁，只存型号名的话「自动换到支持某槽位的那家」会因为两家同名型号而静默选不回来。
- **生成参数也全部由能力声明推导**（能力接口优先，registry 兜底），换模型时界面跟着变：
  - **有哪些参数**：只显示模型声明了的项（档位 / 画质 / 比例 / 时长）；没声明的整块隐藏，也不提交。
  - **参数取哪些值**：用上游 `allowedValues`（例如 h3-video 的分辨率是 480p/768p/960p/1080p，写死兜底会少给 960p/1080p）。
  - **声明与实测不符时可以声明 `forceOptions`**：列在里面的选项名，能力接口不许覆盖。
    目前**没有在用的**（原来锁过 SparkCine 生图的 `output_format`：上游 `/models` 声明 png/jpeg/webp，
    但早前实测提交 `jpeg` 后产物**仍然是 PNG** —— 文件名 `.png`、`mime_type=image/png`、字节头 `89 50 4E 47`，
    只有 `metadata.declaredMimeType` 记着你选过 jpeg；后来按需求把这个选项恢复成可选，改由界面如实显示平台声明的三个值，
    真出不了别的格式时看产物就知道）。要再锁回 png，把 `forceOptions: ['output_formats']` 加回那两个模型即可。
  - **下拉里不写死任何选项**：「格式」那一列的选项清空、整栏默认隐藏，全部现算，并在 hint 里写明
    「几个值 · 平台默认哪个 · 来自上游 /models 还是本项目兜底」—— 避免「能力没回来时的假列表」或
    「被锁成一种后整栏消失」让人误以为格式是写死的。
  - **默认值用平台的**：上游 `parameters.*.default` 会被采用（h3-video 默认 768p / 6 秒 / 16:9）。以前界面落到下拉第一项，
    会变成 480p / 4 秒 —— 出片质量和平台默认对不上。
  - **布尔参数自动出现**：上游声明成 `valueType: "boolean"` 的参数（目前是 `generate_audio`「生成音频」）会在界面上生成一个「开 / 关」，
    并随请求一起提交（`parameters.generate_audio`）；平台以后声明新的布尔参数，界面会自动多一行，页面和 registry 都不用改。
  - 提交走 `Api.createBody` 的泛型 `params`：按 registry 声明的嵌套位置放进 `parameters`（VGENV 这类扁平请求体则放顶层）。
- **registry 的兜底声明要和上游对齐**：没有能力接口的平台（如 VGENV）只有兜底可用，所以兜底写错界面就跟着错。
  `sparkcine-video` 的兜底已按实测的 `/models` 结果修正（补上 960p/1080p、参考音频、`generate_audio`、以及默认值）。
- **生成按钮会按「能力 + 必填 + 互斥」预禁用**（四个工作台都有，按钮下面一行小字写明原因，鼠标悬浮也有）：
  提示词太短、没有可用模型、素材互斥、有当前模型不支持的素材、语音台缺必填的风格描述 / 参考音频 —— 都不让你点下去再报错。

## 统一路由（硬性约定）

**规则：页面（`*.html` 的内联脚本 + 公共 `*.js`）不得访问任何外部域名。**
所有外部请求只能打到本机代理的同源相对路径（`http://localhost:5175/…`）——
端点、密钥、转发、字节取回全由 `proxy.js` 负责。**这条规则没有例外**，写新页面 / 接新平台时先过它一遍。

按用途分的全部本地路由：

| 用途 | 路由 | 说明 |
|---|---|---|
| 平台注册表 | `GET /registry` | 提供商 / 模型 / 能力声明（页面按它渲染，不认厂商） |
| 模型能力 | `GET /capabilities?provider=<id>` | 代理找端点、注入密钥、失败回落 registry；服务端缓存 60 秒（`&noCache=1` 回源） |
| 生成 / 列表 / 详情 / 取消 / 余额 | `/<relay>/*`（`/sparkcine`、`/vgenv`、`/mimo` …） | relay 前缀 + registry 的 `endpoints.*`，页面不拼上游地址 |
| 文字模型 | `/openrouter/*`、`/textai/*` | OpenAI 兼容中转（默认 OpenRouter，备用 DeepSeek；两者都能在设置页换自定义兼容地址），同样不直连 |
| 外链媒体 | `GET /getv?url=` | 上游签名地址（OSS/S3）经它取回，**支持 Range**：播放 / 抽帧 / 量体积 / 下载都同源 |
| 下载 / 取字节 | `GET /fetch?url=`、`GET /getfile?url=` | `dl=1` 带下载头；取字节用于上传 / 转存 |
| 存储直传 | `/s3put?url=` | 预签名地址的直传中转（绕过跨域限制）；**流式转发并回传真实上传进度**（NDJSON 帧，见下节） |
| 平台图片字节 | `GET /asset/<id>` | 永不过期直链（`?v=2` 预览、`?dl=1` 下载） |
| 本地产物 | `/local-assets` | 语音等同步产物与「产物自动存本机」的镜像落盘 + 清单（registry 里写 `local:` 前缀端点） |
| 取型号列表 | `POST /custom/models` | 设置页「添加自定义供应商 → 获取型号列表」：把用户自己的地址 + 密钥递到 `{base}{模板的 models 端点}`，返回勾选列表（**只允许同源 + 只许 POST**，body 里带密钥）。地址仍过公网 https + DNS 判据（`guardOutboundUrl`），另加一道 25 秒墙钟（`upRequest` 的空闲超时管不到域名解析那一步） |
| 渲染 / 导出 | `/render*` | 服务端 ffmpeg 合并成片，素材也由代理下载 |
| 数据 / 归档 / 云同步 | `/data`、`/prompts`、`/cloud` | **只允许同源调用**（跨站 403）：里面可能有密钥与工作区 |
| 本机素材 / 环境 / 渲染 | `/local-assets`、`/env-status`、`/sys-status`、`/render*` | 同上（只服务工作台页面）：本机文件清单、密钥尾号、本机环境体检（会在代理里起一次 `ffmpeg -version`）、会吃 CPU 的渲染 |
| 清理代理缓存 | `POST /clear-cache` | 设置页「清理缓存」：清掉任务列表 / 详情 / 资产签名地址 / 模型能力这四份应答缓存，回一份清理明细（`hostGuardCache` 是 SSRF 防护的 DNS 结果，故意不清） |

**同源保护的覆盖范围**：上面这些路由之外，**relay 转发前缀（`/sparkcine`、`/vgenv`、`/mimo`、`/textai`…）与 `/asset/<id>` 也只接受同源请求**。
原因：代理在客户端没带 `Authorization` 时会自动注入 `.env` 里的密钥 —— 如果 relay 前缀不设防，
任意网页只要 `fetch('http://localhost:5175/sparkcine/…')` 就能用你的密钥建任务、扣费、读余额。
新增平台**不用改这里**：前缀从 `REGISTRY.providers[].relay` 现取（`proxy.js` 的 `RELAY_PREFIXES`）。
云同步命令必须精确写成 `/cloud/<命令>`（`/cloudsync` 这类撞名路径会 404，不会命中同源保护之外的旁路）。

取回/写穿类路由（`/getv`、`/fetch`、`/getfile`、`/s3put`）统一过 `guardOutboundUrl()`：
**只允许公网 https**——回环、内网（10/172.16/192.168/169.254…）、IPv6 本地段，以及「域名解析到内网」的写法（`nip.io` 之类）全部拒绝，避免这台机器被当成跳板。
建连时还会再校验一次解析结果（`guardedLookup`）：校验与连接之间有时间窗，只在校验阶段解析会被 DNS rebinding 绕过；
`/getfile` 跟重定向也**每一跳都重新过完整护栏**（最多 3 跳），302 到内网同样被拒。

**为什么必须这样**

1. **CORS**：浏览器直连上游会被同源策略拦下；代理把跨域变成服务器对服务器。
2. **密钥**：页面不接触明文，代理按 registry 的 `keyEnv` 或设置页填的 key 注入 `Authorization`。
3. **换平台零改动**：新平台只在 `REGISTRY.providers` 里加一条声明（`relay` / `base` / `keyEnv` / `endpoints` / `models` / `create`），页面不动。
4. **一致的护栏**：60 秒超时、退避重试、可读错误、请求体上限、访问日志都收敛在这一层。
5. **媒体同源**：外链换成 `/getv?url=` 之后，抽帧（canvas）、体积探测（Range）、缓存、下载都不再受上游 CORS 与签名过期影响。

**页面侧只能这么写**

- 调平台接口：`Api.request(prov, 'create'|'poll'|'list'|'cancel'|'credits'|…)`、`Api.create(prov, fields)`、`Api.createBody(prov, …)`；
  确实要自己拼 URL 时只用 `prov.relay + prov.endpoints.*`，**不要用 `prov.base`**（那是上游原始地址，只给代理用）。
- 媒体：一律 `Api.mediaSrc(url)`（外链 → `/getv?url=`），不要把它直接塞进 `src` / `<img>` / `<video>` / `fetch()`。
  存进本机记录的地址会过期：判过期用 `Api.mediaExpired`，批量换新用 `Api.healMedia`（换到的新鲜地址由
  `Api.mediaSrc` 自动顶上），**不要在页面里自己判 `Expires`**。
- 取字节上传 / 转存：`AssetTransfer.blobOf()` / `toAsset()` / `crossTransfer()`（内部走 `/getfile`、`/s3put`）。
- 下载：用条目自带的 `dl`（已经是本地路由），或 `Net.save(await Net.blob(Api.mediaSrc(a.src)))`。
- 新增**官方平台**（我们决定支持哪家）：只改 `proxy.js` 的 `REGISTRY.providers`，页面一行都不用动。
- 新增**用户自己的中转 / 网关**（同一种接口的另一个地址）：不改代码，在设置页上方那排类型档里挑一类，
  点「＋ 添加自定义供应商」填表单即可 —— 「供应商」选一家内置平台就照它整套走，选末尾的「自定义」再挑一个
  **接口族**（它点名照哪一家实现），条目存 `sk_custom`
  （DataSync 镜像成 `.data/sk_custom.json`），代理合并进 `/registry` 并给出一条 `/custom/<id>` 转发路由。
  这一类**没有** `keyEnv` / `defaultKey`（不会把内置平台的密钥投到你的网关），也**不认** `x-up-base`
  （地址就固定在那一条条目里）。**不设家数上限**（v11 起撤掉了 12 家那道闸）。
- `site` 这类展示用外链可以有，但只作 `<a href>` 给人点，不参与取数。

**自查（改完页面 / 接完新平台各跑一遍）**

```bash
# ① 前端文件里不该出现上游域名（proxy.js 是唯一允许写上游 base 的地方：它就是 registry 声明）
grep -rn "https\?://" *.html *.js | grep -v "^proxy.js:" | grep -v "data:image" | grep -v "localhost:5175"

# ② 媒体不该被直接赋上游地址（应包 Api.mediaSrc）—— 期望输出为空
grep -rn "src *= *[^;]*https\?://" *.html *.js
```

`②` 必须为空。`①` 的命中逐条看，只有三类是正常的：

- 设置页里的**地址预设 / 输入框占位符 / 官网链接**（`settings.html` 的 `https://api.deepseek.com`、坚果云 WebDAV 默认地址、
  平台卡片的 `<a class="site">`）—— 它们只是给人看或给人填，转发时仍由代理接管；
- `data:` 内联资源里的 `xmlns`（SVG 命名空间，不是网络请求）；
- 文档字符串。

其余命中就是漏了一条：改成 `Api.mediaSrc()` / `/getv?url=` / registry 声明。
允许的「非外部」地址只有：同源相对路径、`data:`、`blob:`。除此之外都要走代理。

## 密钥与安全

- 密钥来源（优先级从高到低）：**设置页填写**（存浏览器 localStorage）> **系统环境变量** > **同目录 `.env`**。
  变量名：`SPARKCINE_API_KEY`、`VGENV_API_KEY`、`DEEPSEEK_API_KEY`、`MIMO_API_KEY`（接入的新平台用它声明的 `keyEnv`）。
- **推荐只用 `.env`**：现在四把密钥都放在 `.env` 里（Windows 用户环境变量里原有的 `SPARKCINE_API_KEY` / `VGENV_API_KEY`
  已挪进来并删除，避免"密钥藏在系统里、换台机器就找不到"）。`.env` 已被 gitignore（规则是 `.env*` + 放行 `.env.example`），
  备份文件（`.env.bak` 之类）也不会被误提交。
- **源码里没有任何内置密钥**。以前 `proxy.js` 里写了两把 `*_live_*` 默认密钥，等于随源码一起泄露（本文件进版本库），
  已移除；现在没有配密钥时启动会打印一条提示，告诉你缺哪个平台的密钥、去哪儿填。
- `.env` 支持热加载（改完不用重启），也支持 `KEY=` 空值主动清空；填法：`KEY=VALUE` 一行一个，`#` 开头是注释。
  改完 `.env` 无需重启：代理每次请求都会重读（只有在**改 `proxy.js` 本身**时才需要重启）。
- **密钥文件不会被浏览器读到**：静态服务只放行工作台自己的前端资源（`.html/.js/.css/图片`），
  并显式挡掉点开头的文件与 `proxy.js`、日志、启动脚本。以前 `GET /.env` 能直接拿走全部密钥（配合代理的
  `Access-Control-Allow-Origin: *`，任意网页都能跨域读），现在已经封掉，回归测试见「自检」一节。
- 数据存储：多短片工作区存 IndexedDB（`director_db`），生图/视频/语音历史与收藏、设置存 localStorage，
  本机生成的产物（配音、短剧末帧、AI 助手的附件）落盘在 `.assets/`。

## 供应商与密钥（设置页那一卡）

按**生成类型**分开的四档（图片 / 视频 / 语音 / 文字），一档一档配，不是十来个平台混成一串：

- **没有「选供应商」下拉**：选中一个类型档，下面**直接列出这一类的全部供应商**，一家一张卡（内置在前、
  自定义在后）。想看哪家没配密钥一眼就看完，不用点进去才知道。
- **按「存密钥的那一格」（`keyId`）归并**：一家平台同时做图片与视频时共用一把 `sk_key_<keyId>`，
  只出现一张卡 —— 不会出现同一 kid 两个输入框互相盖值。
- **「接口地址」输入框按注册表的 `baseEditable` 声明渲染，不按类型写死**：内置的 OpenRouter / DeepSeek
  留了自定义兼容地址那一项（`sk_base_<kid>`，OpenAI 兼容中转的常见用法），其余内置平台与自定义条目都没有
  （自定义条目的地址住在它自己那条记录里，请求也不带 `x-up-base`）。
- **「供应商与密钥（按生成类型分开）」只列本机在用的那几家**（v11 起）：自己添加进来的，和密钥已经有着落的
  （这张卡里填了，或 `.env` 里有服务端密钥）。**一把密钥都没有的内置平台不列** ——
  想用它就点右边的「＋ 添加自定义供应商」把它接进来，它会作为自定义那一家出现在卡片上，自带编辑 / 删除。
  上面那排类型档的小数字是「**现在列着几家**」，注册表里一共几家可选写在汇总行里。
  侧栏的余额列表用的是**同一份判据**，所以「这张卡上没有的一家」在侧栏也不会挂着一张余额卡。
  每张卡下面都写明**这一把密钥现在是从哪来的** —— 密钥其实有三个来源：在卡上粘过并保存的那把
  （存在 `.data/sk_key_<keyId>.json`，与 `.env` 无关）、`.env` / 系统环境变量、以及还没保存的草稿。
  以前只有一个密码框，填过的人自己都忘了填过，于是「`.env` 里明明没有 DeepSeek，它怎么还列着」
  只能靠猜；现在卡上直接写着，点「清除」才是真的没有。
- **添加自定义供应商**：一张共用表单（不是四类各抄一份），三样东西 —— **供应商**（末尾一项「自定义」）、
  **接口形状**（只有选「自定义」才出现）、显示名 + 地址 + key + **型号清单**。
  **接口地址会自动填好所选那一家官网的地址**（选了内置供应商就填它的 `base`，选了某一族接口形状就填那一族的
  模板 `base`），**你自己敲过地址之后它就不再自动替换**。落盘后代理合并进 `/registry`，转发路由是 `/custom/<id>`，
  密钥进 `sk_key_<id>`。按钮旁边随时写着「合计已接 N 家」（不设上限，按钮也不会被禁用）。
  供应商下拉里**只写平台名**，不缀「（N 个型号）」——那一栏窄，拖着括号会把长名字截掉；
  型号数量点「获取型号列表」现问就行。
  这一格是**点添加就生效**（它改的是「本机有哪几家平台」，
  等「保存全部设置」会让工作台的型号下拉一直是旧的）；其余设置项仍然全部「点保存才生效」。

  三层的分工（**类型 / 供应商 / 接口形状互不替代**）：

  | 一格 | 是什么 | 取值 |
  | --- | --- | --- |
  | **类型** | 这一家**能做什么** —— 生成工作台按它分栏（图片台 / 视频台 / 语音台 / 文字 AI），型号清单也只从这一类取。**它不在表单里选**：在上方那排类型档点「＋ 添加自定义供应商」，加出来的就是那一类 | 图片 / 视频 / 语音 / 文字（顶部那排档） |
  | **供应商** | 照哪一家**内置平台**整套走（能力声明、上传流程、端点、retrieve 环节全继承），只换你的地址与密钥 | 当前类型下的全部内置平台 + 末尾一项**自定义** |
  | **接口形状** | 你跑的是**哪一套协议**，与厂商无关。**选了内置供应商就不用挑这一格**（整行收起来）；只有「供应商 = 自定义」才出现 | 注册表 `interfaceShapes` 里按类型列的**接口族** |

  接口族清单（`proxy.js` 的 `REGISTRY.interfaceShapes`，每一族点名照哪一家实现）：

  | 类型 | 接口族 |
  | --- | --- |
  | 图片 | OpenAI 兼容生图（当场返回图片）／ 任务 + 资产号（按资产号换签名地址取图） |
  | 视频 | H3 兼容接口 ／ VGENV 兼容接口 ／ **文件号 + retrieve 两段式** ／ 提交 + 状态两段式（结果地址可能只管几分钟）／ 异步结果（结果在数组里） |
  | 语音 | OpenAI 兼容对话 + 音频参数 ／ 专用 TTS 接口（音频是十六进制） |
  | 文字 | OpenAI 兼容对话（`/chat/completions` + `/models`）—— 市面上绝大多数中转站跑的就是这一套 |

  清单里额外记了 `prov`（选了哪家内置）与 `shapeId`（选了哪一族），只是为了**编辑时原样还原**；
  代理只读 `shape`（模板 id），所以清单的实质格式没变、老条目照样认。
  **用一家内置平台的官方地址去添加它自己，现在是被允许的**（v11 起）—— 那正是「我要用这一家」；
  真正被拦的只有「拿 A 家的官方地址配 B 家的接口形状」这一种必然失败的组合。
- **内置那几家不是「默认展示出来」，而是当供应商 / 接口形状用的**：加一家照样能跑，继承的只是接口。
- **显示名默认给「图片1 / 视频1 / 语音1 / 文字1」**，按类型各自编号、重名自动顺延（只数这一类已有的）。
  显示名就是型号下拉的分组名与收藏里的筛选项 —— 一次加三家却都叫「我的中转」，那三组永远分不开。
  换类型档时这个自动填的名字会跟着换（视频1 → 语音1），**但你手打过的名字不会被覆盖**。
- **这张卡里自带一份「已添加」清单**，每条后面就是编辑 / 删除：供应商那张卡上也有这两个按钮，
  但那是按类型分档画的（语音那一档加的只有切到语音才看得见），删一家要在四档之间来回找。
  删掉一条后这份清单当场少一条（计数与供应商卡一起刷新），不用重新展开这张卡。
- **「＋ 添加自定义供应商」一定是新增**：先编辑了某一家再点它，按钮会复位成「添加这一家」并对上你当前那一档类型。
- **型号一律现取，不预填模板里那份硬编码的清单**（那份是「内置那一家」的声明，照抄给用户的中转站就等于替它编型号）：
  填好形状 / 地址 / key 之后点「**获取型号列表**」，代理按 `POST /custom/models` 真去问那一家
  （端点取模板的 `endpoints.models`），回来的 id 落进一个**可勾选列表**（每项标着来源：已保存 / 接口返回 / 手填，
  新拉回来的一律不勾，由你自己挑）。这一类平台没有型号列表接口时，用旁边的「自己填 id」手写。
  勾选状态按**「已保存 ∪ 手填」**算 —— 重新拉一次不会把你上次勾的冲掉。
- **会被当场拦下来的三种填法**：明文 http / 内网地址（代理只放行公网 https，它要替你把密钥转发过去）、
  没写显示名、没勾型号；再就是**填成内置平台的官方地址** —— 撞别家的会说清它列在哪一档，
  撞模板自己那家的直接拒（内置是默认的，不需要添加，两家同名同地址以后说不清用的是哪把密钥）。
  代理侧对同样的判据再兜一次（备份还原 / 换机器带进来的清单），坏条目不进注册表，原因摆在卡片列上面。
- **删一家**会把它的 `sk_key_<id>` 与「暂时不用」勾选一起清掉，不留死数据。
- **文字 AI 的一切都在「文字」这一档里，一家一张卡**（不再有单独一张「文字 AI 模型与识图」卡 ——
  两处管同一家供应方必然对不上：在 A 卡改了地址、型号却在 B 卡上选，界面看着都对、发出去是错的）。
  每张卡上是：密钥 → 接口地址（按 `prov.baseEditable` 声明渲染，自定义条目自动不显示）→
  **型号下拉 + 「获取型号列表」/「测试」+ 自己填一个型号** → **识图能力**。
  卡上多一个单选框「作用文字 AI」，勾哪一家就用哪一家（落盘键仍是 `sk_text_prov`）；
  **识图开关是全局一项**（对所有文字供应方生效），所以只画在当前那一家下面。
  型号按供应方各存各的（`sk_model_<keyId>`），顺手给别家挑好的默认型号也会存下来，不会丢。
  **自己填的型号只属于填它的那一家**（存 `sk_text_models_<keyId>`）：以前认不出这家时会兜底写进 DeepSeek 的键，
  于是填在 OpenRouter 的型号跑到了别家的下拉里；现在所有读写入口都先过同一个判据（`TextAI.hasProv`），
  认不出就明说，绝不落到别家的键上。
  加完自定义文字供应方，它会立刻出现在「文字」这一档里。
- **内置的文字 AI 供应方有 9 家**（OpenRouter / DeepSeek / OpenAI / Kimi / 智谱 GLM / 通义千问 / 硅基流动 /
  火山方舟 / minimax），全都是 OpenAI 兼容形状，所以新增一家只要在注册表里加一条（地址 + 密钥变量 + 兜底型号），
  页面、设置、润色、识图、用量全都不用改。**型号清单不写死**：这些平台改型号太频繁，写死会立刻过期，
  设置页点一次「获取型号列表」就是它自己的 `/models`。
- **每一类都能显示侧栏余额**：注册表里声明了 `credits`（余额 / 配额）端点的家都能勾「侧栏余额」，
  语音、文字与生成类型一样对待 —— **不要按 kind 写死谁有余额**。
  **反过来也成立**：平台没提供余额接口的，勾选框照样画（只是压暗，鼠标停上去写明「这家平台没有提供余额查询接口」），
  免得想开的人找不到入口。已接上真实余额接口的有 OpenRouter（需管理密钥）、DeepSeek、Kimi（人民币），
  其余不编 —— 问不到余额与余额为 0 是两回事，界面上照实说「问不了」。

### `ui.js` 的图标（`ICONS` / `icon` / `iconSet` / `btnText` / `fillIcons`）

全站按钮上的符号**只有一份几何**：`ui.js` 的 `window.ICONS`（56 颗，16×16、统一 1.5 描边、跟随文字颜色）。
`🗑 ▶ ⏸ ⏮ ⏭ ⬇ ↻ ✧ ✎ ⧉ 📷 ♪ ✕ ⤒ ⤵` 这些字符已经全部换成 SVG —— 各平台的 emoji 字形不一样、
在 Windows 上会渲染成彩色位图，和旁边的线描图标放一起像两套东西。

```html
<!-- 静态标记：fillIcons() 在页面加载时一次性填上 -->
<button class="tool"><span class="ic" data-icon="sparkles" data-size="15"></span>AI 帮我完善</button>
```

```js
// 模板字符串里用 icon()（drama.html / drama.js 里有个薄封装 ic()，默认就带上 <span class="ic">）
'<button class="tool mini danger">' + icon('trash', 13) + ' 删掉这一段</button>'
```

`data-icon` **只能写在静态标记里** —— `fillIcons()` 只在加载时跑一次，模板字符串里的它永远不会被填上。
动态片段一律调 `icon()`；`icon()` 遇到不认识的名字返回空串（不抛），所以新加一颗图标后记得核对名字在 `ICONS` 里。

**带图标的按钮，文字不能靠 `textContent` 改** —— 那会把图标一起抹掉，不报错，只是图标忽然不见了。
结构固定成 `<span class="ic">…</span><span class="tx">…</span>`，改文字走 `btnText(btn, txt)`、
换图标走 `iconSet(btn, name)`：

```js
btnText(btn, '下载中…');     // 只改 .tx，图标留着
iconSet($('cPlay'), 'pause', 15);  // 只换 .ic（没有 .ic 时整颗换掉）
```

**分工**：可点的动作（按钮 / 文字钮 / 芯片 / 加号）用 SVG；`⚠ ✓ ✗ ● ?` 这类**句子里的状态标记**
留在文字层 —— 它们出现在 `toast()` 和提示条的 `textContent` 里，换成 SVG 只会显示成标签源码，
而且本来就和提示气泡里那颗圆形色块、勾选框是同一套语言。

### `Drama` —— 拍短剧（`drama.html` 的全部业务逻辑）

| 能力 | 说明 |
|---|---|
| 短剧读写（`Drama.list/get/put/remove`） | 键 `dramas`（跟着云同步走）。数据模型：短剧 → 角色 / 场景 / 分段（`shots`）→ 每段的每一次拍摄（`takes`） |
| `Drama.Shots` | **段落列表本身的编辑**：`moveShot(drama, id, dir)` 上下移、`duplicateShot(drama, id)` 复制（只带写法，不带 takes）、`dropShot(drama, id)` 删段、`resequence(drama)` 把 `no` 重排成 1..n。三条都按 shot id 定位，返回改完之后那一段在数组里的下标 |
| `Drama.Lib` | **素材库**（键 `drama_chars`）：脸、声音、角色资产跨剧复用。`adopt` 存进库、`pullInto` 拉进当前剧、删角色只动库不动这一集。`staleIn(drama)` 是「库里那份与这一集已经不是同一份了」的判据 —— 素材库页是**就地编辑**、不碰这一集，用户在库里换了脸改了描述，回到拍短剧看到的还是旧的、拍的也是旧的。**角色与场景各查各的**（`adoptAll` 存进去的就是两类），只比会真的影响拍摄的字段：角色看 `预览图 / 外貌 / 音色 / 音色描述 / 参考音频`，场景看 `预览图 / 描述 / 时段`；库侧字段为空不算「不一样」 |
| `Drama.SET` | **这一页的设置项只在这一处点名**（键 `dr_*`）：整集时长目标（分钟）、两个 AI 自主权开关（自己改时长 / 逐位定音色）、做下一集默认沿用范围。入口页的文案、真的发给 AI 的那份参数、设置页的控件、AI 助手的可改白名单**都读这张表** —— 写两份就会出现「界面说会、其实没发」 |
| `Drama.Subs` | **字幕组件**（见下） |
| `Drama.libFor(drama)` / `Drama.libPickOf(drama)` | **这一集点名要用素材库里的哪几条** —— 只有这一份判据，`castNote`（喂给文字 AI 的那份）与入口页那行摘要都读它。`libPickOf` 读 `opts.libPick`（存 lib id，一律按**字符串**比）；`libFor` 返回实际还在库里的那几条。空 = 没点名 = **整个库**都是候选（AI 按剧情自己认名字，这是以前唯一的行为）；点名了 = 只给这几条；点名的 id 在库里已经没了就当没有，**不退回整个库**（悄悄换一批人正是「界面上写着 A、实际发出去的是 B」）。入口页那颗「挑角色 / 挑角色组」与第 2 步的素材库框是**同一个** `openLibPicker`（`pick:true` 模式），交回名单即关窗 |
| `Drama.Pipe.lineSec` | 这一段台词念多久：有真配音就用 `take.lines[].dur` 累加，没配过才按字数估（`from: 'dub' \| 'est'`）；右栏那句「台词含收尾约 X 秒 · 这一段拍 Y 秒」与选时长档位用的是同一份估算。**台词在拍完之后被改过时（`lineDrift`）一律退回按字数估** —— 那串真实时长是旧台词的，拿它配新长出来的句子，「比平台最长的档还长，话会被截」那道闸就永远不响 |
| `Drama.Pipe.lineDrift(shot, take)` | **台词有没有在拍完之后被改过**。配音与字幕都是拍摄那一刻的快照（`take.lines[]`），所以改 `sh.lines` 改不到已拍好的那一条，成片里说、烧的仍是原来那几句。判据 = 去掉空句之后 `(说话人, 文本)` 的序列对不上（`take.lines` 为空 = 这段本来没台词，不算）。三处都读它：右栏台词区顶上的提示条、`edlCheck.warns` 里一条 `kind:'lines'` 的告诫（**只报不拦**）、`lineSec` 的秒数回落 |
| `Drama.Pipe.lineSpeaker(drama, line)` | **这一句到底是谁在说**：先按 `line.whoId` 在角色表里找人，找不到再按 `line.who` 的名字兜一层（早期数据与从素材库拉进来的角色可能只有名字），两个都认不出返回 `null`。**全站判「这一句归谁」只有这一份** —— 右栏说话人下拉、配音（`dubShot`）、开拍前的前置条件（`prereqs`）、导出的剧本文字都读它。以前这几处各判各的：配音只认 `whoId`、前置条件只看 `whoId`、右栏还会在 `<select>` 没有选中项时默默显示第一位，于是界面上写着「琪琪」、发出去的是旁白的声音。**认不出就摆「未指定（按旁白念）」，别让它落到列表第一项** |
| `Drama.Pipe` | 拆剧本（`TextAI.chat` + `parseJson`）→ 画脸 / 角色资产 / 场景图（`AiGen.image`）→ 逐句配音（`Api.create` + `Api.saveLocalAsset`）→ 拍这一段（`Api.createBody` + 首帧/参考图）→ 出成片（`/render`） |
| `Drama.Pipe.scriptText(drama)` | **整集剧本（纯文本）**：抬头 + 角色表（人设 / 外貌 / 声音）+ 场景表 + 分段（场景 · 出场 · 画风 · 开头画面 · 台词 · 逐条镜头）+ 你写的故事。底栏「剧本」按钮用它导出 `.txt`（第 3、4 步都有），文件名与成片 / 字幕 / 单段同一套 `fileSafe` 规则。**纯读**：不提交任务、不碰平台、不花钱，所以不走花钱闸门；成片 mp4 拿在手里就只剩画面了，「这份片子到底是什么」得靠这一份才留得下来 |

**音色是真从注册表取的**（`Drama.Pipe.voices(REG)`：模型 `options.voices` → `prov.tts.voices`），
没配语音平台就明说「还没配语音接口」，不会摆三个假的「声音 1/2/3」——
编出来的 id 平台根本不认，要到提交时才报错。试听与正式配音走同一个 `ttsOnce`，参数完全一致。

**下拉里存着的值不许被静默改掉**（入口页高级设置的画幅 / 画质）：`<select>` 里一项 `selected` 都没有时，
**浏览器默默显示第一项**，`readOpts()` 读到的也是第一项 —— 换一个只声明 9:16 的平台，用户上一部设的 16:9
就这么没了，而摘要那句还在念旧的 16:9，两处自相矛盾。现在 `sel()` 自己兜底：当前值不在清单里就
**照实列出来并选中**，后面括一句「这一家没声明，拍的时候自动对齐」。
注意这跟「场景被删了 / 说话人被删了」那种要摆**「未指定」兜底项**的情况不是一回事：
前者是**值还有效、只是这一家没声明**（要留住它），后者是**值已经失效**（要摆一个诚实的空项）。
两种都别用同一种做法套两头 —— 那是 `<select>` 兜底这一类 bug 反复出现的原因。

反过来也不许有**多个** `selected`：浏览器是「**最后一个赢**」，
所以 `presets.map(s => \`<option ${cond ? '' : ' selected'}>\`)` 里只要 `cond` 不看循环变量，
整列就全被选中、最后一档静默胜出。整集时长那个下拉踩过这一条 ——
上一部存的是 1 分钟，界面上却摆着「5 分钟」，点「开始」真按 5 分钟建剧，而旁边的摘要还写着「1 分钟」。
所以凡是 `.map(…)` 画出来的 `<option>`，`selected` 的条件里必须出现那个循环变量。

还有一条同源的：**「现算出来的那一行字」在依赖没就绪时不能先摆兜底值**。
入口页「开始」旁边那句「整集目标 X」是现读下拉算出来的，而能力声明还在后台取时**下拉整个还不存在** ——
读不到就全落兜底，于是那一行会先摆出「整集目标 4 秒」（视频平台最短的一档），
一个用户从没选过的数，还比真值小十几倍。`paintOpts()` 有「还没取到就先别画」的守卫，
`paintSecs()` 当时漏了同一句。**读界面控件算出来的显示，守卫要一起加。**

**每一位角色自己决定「声音从哪来」**（`Drama.Pipe.ttsWays` 现算这一家到底支持哪几种方式，只列**真有型号**的那几种）：

| 方式 | 靠什么 | 落在哪个型号 |
|---|---|---|
| `preset` | 平台声明的预设音色清单（`voices()`），id 只能从清单里挑 | 当前选中的语音型号 |
| `design` | 写一段音色描述，型号照描述造嗓子 | 这家声明了 `ttsMode:'design'` 的那个型号 |
| `clone` | 角色身上有**本人参考音频**（本机 IndexedDB，`refAudio` 只存键） | 声明了 `ttsMode:'clone'` 的那个型号 |

- **「✧ 让 AI 给每位角色定声音」**（`Drama.Pipe.assignVoices`，设置项 `dr_ai_voice` 可关）：文字 AI 读人设 / 外貌 /
  有没有本人参考音频，**逐位**回 `{name, way, voice, note}` —— 带本人参考音频的那位走复刻，其余出镜角色走音色描述
  （旁白也写描述，只是要写成适合念白的那种），这一家没有描述型号时才退到预设清单里挑一个。
  AI 说了 `clone` 但这一位没有参考音频、或这一家根本没有描述型号，**当场降级**并把原因写进小结（不等到配音时炸）。
  音色 id 只认真清单里那一些，清单里没有就退到第一个并写明「存的『X』不是这个型号的声音，这次按『Y』念」。
- **方式记在角色身上**（`char.voiceMode`），配音时由 `voiceWay` 现校验；降级必须显示出来，不然界面说的是复刻、实际发的是预设。
- **型号下拉是按平台分组的二级菜单**（`Drama.Pipe.modelGroups` / `modelSelectHTML`，与生成工作台同一套分组方式）：
  `<optgroup>` 给平台名，选项文字是型号原始名，不再把「平台 · 型号」拼成一个字符串塞进列表。

**AI 拆出来的剧本照它写的落地，不替它改**（`normalizeScript`）：两处以前是「静默换一个」——
段里引用的场景名没在 `scenes` 里声明过时一律落到**第一个场景**（提示词写的是剧情里的地方、界面上那个下拉显示着第一个场景，
而「接不接上一段末帧」又是拿这个 `sceneId` 判的）；时段不在 `深夜/白天/黄昏/清晨` 这四档里时一律改成「深夜」。
场景名现在查三级：**完全相同 → 互相包含**（「暴风雨」对「场景二：暴风雨」，只做精确匹配会多建一个几乎同名的场景）
→ **都没有就当场建一个**；名字真的是空才留空（界面上有「不指定场景」这一项）。时段照 AI 写的存，
由那个下拉照实列出来让你自己改回表里的档。同名的角色与场景仍然复用「做下一集」带过来的那一份（脸 / 音色 / 场景图都跟着走）。

**字幕不是视频平台生成的**（那边出的片子没有字幕），而是这一条链：

```
台词 → Drama.Subs 按「每句配音的真实时长」排成字幕轨
     ├─ 预演：叠在播放器画面上（pink 旁白 + 白字，随 currentTime 切）
     ├─ 导出：POST /render 的 clips[i].subs → 代理生成 ASS → 本机 ffmpeg 的 ass 滤镜烧进画面
     └─ 单独下载 .srt（要改台词 / 配别的播放器时用）
```

`clips[i].subs` 的时间**相对该段起点**，整片偏移由代理用 ffprobe 量真实时长累加（客户端自己加会漂）；
有字幕时画面要重新编码（叠滤镜与 `-c copy` 互斥），没有字幕仍是原来的直拼。
**配音同样进成片**（与字幕同一套时间约定）：导出时每一段带上 `clips[i].voices = [{src,start,dur,vol}]`，
代理把每句按 `start` 延迟后与该段原声混成一条统一规格的音轨（`buildClipAudio`：anullsrc 静音底 +
各句 `adelay` + `amix normalize=0` + `apad/atrim` 对齐本段长度），再与画面一起拼。三个要点：

- 短剧的台词是逐句合成的，所以 `clips[i].volume` 传 **0** 压掉视频平台自己生成的人声（两路人声叠一起串味）；
- 只要有配音，**每一段都铺音轨**（没原声就垫静音底）。以前是「所有片段都有音轨才保留，否则整片静音」，
  一段有声一段无声就会把配音整段抹掉；
- `start` 相对该段起点，绝对偏移由代理按 ffprobe 出来的真实时长决定（和字幕一样，客户端自己加会漂）。

实测：两段 4 秒画面 + 每段两条配音 → 成片 8.04 秒、video+audio 双轨，0.3s 与 4.2s 两处分别落位，
句间空隙是 −91dB 的真静音（`volumedetect` 量过）。

**预演不生成视频**：它是「开头画面 + 配音 + 字幕」在本机实时合成的（不占一次视频生成、也不用等模型），
真正出片才调视频平台。

**「待补条件」只在开拍前拦**：脸/人物/服装/画面/镜头这类没法在本机判定，所以**拍完不做任何自动判定**（2026-10 去掉质检）—— 一条片子像不像那个角色只有你自己看得见，让文字 AI 识图打分给的是一句没人能核对的结论；
声音与台词更没得判（配音就是用该角色音色逐句合成的、字幕轨按这些配音的真实时长排，没有听辨模型就别假装听得出台词念错没）。
于是 `prereqs` 成了**唯一**一道「配齐了才准花钱」的闸门：角色还没定音色就先拦在开拍之前，不会出现
「拍完才发现不过、重拍必然还是不过、让人反复拍同一条」这种最没意义的浪费。
现在 take 只有两种结局：`已出画面`（`done`）与 `没拍成`（`failed`）。**每点一次「拍这一段」只发一条任务、
失败不自动重拍**，拍片记录里一次一个数单独留着；要再来由你自己点「再来 N 次」（上限 `maxTakes`），
拍坏的那次可以在记录里删掉。原来那个「自动 / 手动」开关已删除（它唯一的作用就是「没过就自动重拍」，
与「不自动重试花钱动作」直接冲突）。

**要花钱的入口都会先说清楚会发出几条**：单段一次连拍、重拍没成的那几段、以及底栏「开始拍」
（整集连拍，一次 = N 段 = N 条真任务、各自计费）—— **多于一条就会先弹一次确认**，写明总数、
并发还是串行、以及拍完怎么逐条看、逐条删掉重拍、中途怎么停。只有一段时不问（一段就是一条任务，
界面里数得出来，多问一次只是骚扰）。前置条件不齐时**先开清单、不谈钱**：那时一段都拍不了，
先问「拍 N 段吗」只会更让人糊涂。

**关掉网页也会接着拍**：提交那一刻就把平台任务号写进这一集的数据里，重新打开时用任务号接着等结果，
**不重新提交**（重新提交会重复扣费）。视频平台的产出有三种给法 —— 外链、本机直链、**资产号**
（SparkCine 的产出是资产号、没有外链），本机一律转成自己的地址再播；三种由 `takeVideoSrc` 一份判据转换，
拍摄与断点续拍走同一个函数（以前只有拍摄认资产号，续拍回来会拿到空地址：钱花了、画面却全黑）。

**「还没配 X 接口」这句话只在能力声明取回来之后才会说**：页面先出、注册表后台取，那之前
`ttsWays` / `videoChoices` 会落到「没有这一家」的兜底分支，说出来的「还没配语音接口」是假的 ——
你其实配了。入口页的模型下拉、那一行时长、以及底栏的前置条件提示**各有一道闸**；
被压住的那条会给一句中性说明（「先不报缺」），不会假装通过。

**舞台上的快捷键**：空格 = 播放 / 暂停，`←` `→` = 上一段 / 下一段（到头/到尾就停在原地，不吵你）。
有四种情况一律不抢按键：焦点在能打字的地方（输入框 / 文本域 / **下拉** —— 方向键是在换选项）、
带 `Ctrl`/`Alt`/`Meta`、焦点在按钮上（刚点过「删掉这一次」时按空格应该是**确认删除**，不是播放）、
灯箱开着或有弹窗（`← →` 在灯箱里是翻候选）。中文选词上屏那一下还会再触发一次 keydown，一并放行。
走带按钮点完会 `blur()`，否则焦点留在钮上、空格会去重新点它而不是播放。

**配乐**：底栏「配乐」从资产库 / 收藏 / 本地上传里挑一段（也可以试听、换一段、取消）。
导出整集时它会**自动循环铺满**整集，原声压低到 35% 与它混音 —— 混音是本机 ffmpeg 做的。
**导出前先问一句本机**：`Drama.Pipe.render` 在提交 `/render` 之前读一次 `/sys-status`（取法与文案只有 `Api.sysStatus` /
`Api.sysTool` 这一份，设置页那一栏与助手体检念的是同几句话），**探明**ffmpeg 不能用才停下，
并把代理给的**具体那一种**写出来（没装 / 不在 PATH / 装的是 Windows 商店那个占位壳 / 一跑就卡住）——
以前这三种都只在等了几十秒之后汇成一句「无法启动 ffmpeg」。
**这一问本身失败就不拦**（旧代理没有这个接口、或它超时断连）：代理那一步本来就会报它自己看到的错，
多一道闸只会把「体检读不到」说成「你 ffmpeg 坏了」。

**导出时带不带配音、烧不烧字幕**（底栏第 4 步的两颗芯片，默认都要）：「配音：开/关」「字幕：开/关」，
点一下切换。关掉配音时**会把视频平台自带的人声放回来**（逐句配音本来就是靠压掉它才听得清的，
再压着会得到一条又没配音、也没原声的哑片）；关掉字幕就是出干净画面，台词随时能单独下载 SRT。
这两个开关**只影响成片**：预演照旧是画面 + 配音 + 字幕，下载的字幕文件照旧是完整台词。
导出按钮上的那行提示会照这次的开关现算（带几句配音 / 用平台原声、烧不烧字幕、有没有配乐）。

**成片之后**：底栏给「下载成片 / 下载字幕 / + 做下一集」。「做下一集」**先问一句沿用多少**（角色和场景都沿用 /
只沿用角色 / 全新，默认值就是设置页那一项 `dr_next_inherit`），然后**当场把新的一集建好**并回到入口页挂着它 ——
顶部那条「下一集已经建好」写明带了哪几位角色、几个场景，并给一个「不要它，另起一部」的出口。
写完故事点「开始」就落在这同一集上（记在 `nextDraft`），于是 `castNote` 那份「已经定下了这些人 / 这些场景」
**真的喂给文字 AI**：它照同名往下写，`normalizeScript` 就复用那一张脸、那一个声音、那一张场景图。
画幅 / 画质 / 模型 / 配乐照上一集沿用，剧本与分段是空的。以前这里是「清空角色停在『认角色』等你重写故事」，
而新建一集的动作在「开始」里 —— 拷过来的角色成了孤儿，界面说的「接着用」根本没生效。
还没存进素材库的角色会在这行提醒一句，并给一个「都存进素材库」。

**看预演那一步的「开始拍」**：出完预演自动落在第 3 步，那里才是开拍的入口（预演本身在本机合成，不生成视频）。
前置条件没齐时按下只会弹出还缺哪几项（哪些角色没定音色、哪一段还没有台词），不会直接开拍。

**弹窗与组件都走公共库**（`ui.js` 的 `UiDialog` / `Confirm` / `PromptForm`，
`ui.css` 的 `.ghost` / `.tool` / `.ui-seg` / `.ui-pill` / `.ui-tag` / `.ui-note` / `.ui-hint`），
页面里没有第二套弹窗外壳、也没有第二份组件样式。

**画幅 / 分辨率 / 单段时长按视频平台自己声明的取值**：入口页那几个下拉也是按**当前选中的视频模型**
的声明渲染的（换模型，下拉跟着变），不写死一张表。两家视频平台声明的是
`resolutions: 480p/768p/960p/1080p` 与 `durations: [4, 15]`，界面只显示并发送**吸附后**的档位，
底栏照实写「768p · 每段 4 或 15 秒」。台词装不下时选**装得下的最小那一档**，
比最长的档还长时在右栏明说「拍出来话会被截」。

**整集时长：常用档做成下拉，选「自定义…」才露出分钟框**：入口页那一栏是一个下拉（`1 / 2 / 3 / 5 分钟`
这类档位只列视频平台声明区间内的），选到「自定义…」才在旁边露出分钟数字框（步长 0.5）+「分钟」两个字。
下拉面板的宽度按**选项自然宽度**来（`ui.css` 的 `.dd-list`），不跟着窄按钮一起缩 —— 以前面板 = 按钮宽，
80px 里「1 分钟」折成两行、「自定义…」被裁掉。界面上按分钟、数据里一律存秒，换算与夹取只有 `Drama.durationFromMinutes`
一份 —— 上下限来自视频平台声明的**单段**最短一档到 `DUR_MAX_SEC`（30 分钟），超界时 `onchange` 吸回来并
如实说一句「这一集的长度取不了 X 分钟：按能拍的范围算作 Y」，存进数据的始终是夹好后的秒数。
这个数只是**目标**：`{duration}` 发给文字 AI，它按剧情密度可以在顶层回一个 `duration`，`normalizeScript`
采纳它并把你那一个留在 `opts.durationAsked`（`durationBy:'ai'`），底栏那句就写成
「AI 定的 3 分钟（你写的是 2 分钟）」—— 不是悄悄改。设置项 `dr_ai_dur` 关掉就一直按用户写的走。

### `Net` —— 所有请求的唯一出口

```js
await Net.json(url, { timeout: 8000, retry: 2 })   // 取 JSON（超时/重试/非 JSON 都有可读错误）
const b = await Net.blob(url)                       // 取二进制：**先判 HTTP 状态**再转 blob
Net.save(b, '文件名.mp4')                           // 触发下载并回收 blob URL
```

- 默认超时与重试次数可在「设置 → 网络与刷新」里改（`sk_net_timeout` / `sk_net_retry`），改完即时生效。
- 只有网络错误与 5xx/429 会重试；4xx 是请求本身的问题，不重试。
- **POST 默认不重试**：只有带幂等键（`Idempotency-Key`）的 POST 才重试——服务端会按键去重，重试不会建出第二条任务。
  哪些平台支持幂等键由 registry 的 `create.idempotencyKey` 声明（SparkCine true、VGENV/MiMo false），
  没有去重保证的 POST 一旦「请求已到、响应超时」时重试，就会重复建任务、重复扣费。
- 以前全站没有超时机制（一个挂起的请求会让按钮永久禁用），下载也不判状态码（404 页面会被存成 `.mp4`）。

### `Kv` —— IndexedDB 的唯一一份读写层（`ui.js`）

导演台工作区与本地视频帧、收藏的文件本体、音色复刻的参考音频、缩略图缓存
都存在 IndexedDB。以前这些地方各写一份开库与事务的代码（导演台、设置页、资产库页、收藏、
缩略图等 6 份），只有导演台那份带「库存在但没有仓库就补建」与「连接复用」，别的地方一旦碰到
被不带版本的 `open` 凭空建出来的空壳库就直接抛 `object stores was not found`。现在只有一份
（库 / 表名只在 `ui.js` 的 `Kv.TARGETS` 点名一次，页面只写登记名）：

```js
const favKv = Kv.at('fav');                       // 登记表里的名字，库/表字符串只写在 ui.js 的 TARGETS
await favKv.get(fileKey)                          // 读一条（没有则 undefined）
await Kv.at('ws').put('workspace', o)             // 写一条（ws = director_db/kv）
await Kv.at('fav').del(fileKey)                    // 删一条（fav = fav_db/files）
await Kv.at('thumbs').all()                        // 整表值（thumbs = wb_thumbs/thumbs）
await Kv.at('ws').entries()                        // 整表 [键, 值]（备份/恢复用）
await Kv.at('blobs').tx('readwrite', st => { st.put(v, k); st.delete(k2); })  // 一个事务里混着写
```

- 四个登记名：`ws`（导演台工作区与本地视频）、`fav`（收藏的文件本体）、`blobs`（音色复刻的参考音频）、
  `thumbs`（缩略图缓存）。要带哪几个库进整包备份也来自这张表（`backup: true` 的那几项），
  `DataSync.IDB_TARGETS` 由它现算，不再抄一遍库/表名。
  （原来还有第五个 `dir`，存本机下载落点的目录句柄 —— 随「下载位置 / 另存为」那一层一起删了。）
- 连接按**库名**复用（一个库一个连接），别的标签页要升级版本时自动让路并重开。
- 仓库缺失时用 `version+1` 补建一次；**任何地方都不许写死版本号**（`open(db, 1)` 在库被补建到 v2 之后永远打不开）。
- 打开失败不缓存那个失败的 Promise（隐私模式 / 被占用时，下一次调用还能重试）。
- 要「读不到就算了」自己加 `.catch(() => null)`，要「写不进就算了」自己加 `.catch(() => {})` —— 容错策略留给调用方，公共层不静默吞错。

### `workbench.js` —— 三个工作台的公共任务层

三个页面 80% 的行为是同一件事（拉任务、轮询状态、渲染卡片、取消/重试/删除、保存产物、分页搜索、本地历史）。
以前各写一套，于是同一个功能出现三种行为：**「取消」只有视频台有、「重试/删除」图片台没有、历史条数上限
三个台分别是 150/60/80 且超限静默丢弃**。现在收敛成一份：

```js
Wb.ST / Wb.isRunning(t) / Wb.isFailed(t)     状态文案与判定（三台同一套）
Wb.actsHTML(t, o) / Wb.bindActs(el, t, o)    卡片那排按钮（详情·放大·下载·取消·重试·删除记录）
Wb.History.read(kind) / write(kind, list)    本地历史：统一走 Store 信封、上限 200、写不进去会提示
Wb.Blobs.put/get/del                         大文件存 IndexedDB（如音色复刻的参考音频）
Wb.blob/save(url,name)                       产物下载（先判 HTTP 状态，再走浏览器默认落点）
Wb.poller({...})                             轮询器：没任务不发请求、连续失败会提示并退避、切走标签页自动暂停
Wb.lbBar.init({fileName, urlOf}) / show(item) 灯箱底部操作条：下载 · 详情（见下）
Wb.fmtSize(bytes) / Wb.mediaSize(src)        体积文案 / 实测媒体体积（只发 Range 探测，不下载正文）
Wb.lbDetail.init({render}) / show(item)      灯箱里的「详情」（见下）
Wb.thumbs.mediaHTML(src, {key,type,mediaAttrs}) / bind(wrap, media, src)
                                             视频缩略图：首帧缓存 + 懒加载；`.tph` 占位层与 data-thumb-key
                                             由它生成，页面只提供 src 和包装 class（见下）
Wb.detail.init({prompt,status,provider,taskId,rows,refs,openRef,actions}) / render(item, host)
                                             任务卡片的「详情」面板（资产库与三个工作台共用一份，见下）
Wb.cards.create({box,keyOf,sigOf,paint,emptyHTML,notesHTML}) / paint(items)
                                             右栏卡片列表：按键复用 DOM、指纹变了才重绘、空态与提示条
Wb.pager.create({mode,pageSize,items,hasMore,fill,render,searchQ})  分页 / 动态加载 / 跳页 / 滚到底续拉
Wb.lightbox.init({list,keyOf,srcOf,nameOf,kindOf,info,detail}) / open(item[, list]) / step / close
                                             灯箱预览（图片/视频/音频/进行中占位），DOM 由它自己创建
```

**视频缩略图（`Wb.thumbs`）**：视频卡片不再直接用 `<video preload="metadata">` 当缩略图 —— 那样每开一次页面、
每翻一页都要重新取一次元数据（还要经代理去上游解析签名地址），几十张卡一起发请求，观感就是「又慢、又每次都重新加载」。
现在：出画后用 canvas 抽一张 92px 的 JPEG 存进 IndexedDB（`wb_thumbs`），下次直接当 `<img>` 用（秒出、零请求）；
没有缓存时用 IntersectionObserver 懒加载，滚到附近才发请求，出画前有占位层。四个页面（导演台 / 图片 / 视频 / 资产库 / 收藏）
共用这一份实现。缓存键会做归一化 —— VGENV 的产物是 `/getv?url=<OSS 签名地址>`，签名每次刷新都变，
只取内层 host + path（加稳定 query）当键，否则永远命不中（这就是「每次都重新加载」的根因）。
归一化只在 `assetlib.js` 的 `Api.mediaKey` 有一份，`Wb.thumbs.keyOf` 与过期回源的去重都用它。

**签名外链过期自愈（`Api.mediaExpired` / `Api.healMedia`）**：那种签名地址只管一天，一旦被**存进本机记录**
（收藏 `fav_items`、导演台工作区 `workspace`），第二天放进 `<video>` 就是 403 —— 表现是「这条视频的缩略图
永远加载不出来、点开只回一句 Format error」，而真实原因完全看不出来。现在公共层兜住：
`Api.mediaExpired(url)` 只看地址里的 `Expires` 判新旧（不发请求），`Api.healMedia(recs)` 按平台分组
用 `Api.pollMany` **一次列表请求换回整批**新鲜地址，并把结果按素材身份记进内存表；
`Api.mediaSrc(url)` 会查这张表，所以页面不用改一行 —— 播放器、缩略图抽帧、灯箱、下载链接都用上新鲜地址。
落盘由调用方在 `onFresh` 里做（导演台开机后台跑 `healStaleUrls()`，收藏页渲染后跑 `Fav.resignSome`，
短剧的每条 take 由 `Drama.Pipe.healTakes(drama, onFresh)` 扫 `shots[].takes[]` 里带 `taskId` 且已过期的那条
—— 页面 `healTakeUrls()` 在开机 1.2 秒后跑一次，换到就 `Drama.put` 落盘并重画播放器；播放地址只能经
`Drama.Pipe.takeVideo(drama, shot, take)` 取，它内部再过一次 `Api.mediaSrc`），
换到的新地址写回工作区时还要走 `DataSync.mirrorWs` 才会进 `.data/workspace.json`。

**三个工作台的灯箱（预览）现在完全一致**：底部那排是 `数量 · 信息 · 下载 · 详情`。

- 按钮由 `Wb.lbBar` 统一生成、样式只在 `ui.css` 的 `#lbBar` 一段里定义，所以三台**不可能再长得不一样**。
  以前图片台是两个 `<button>`（有 hover），视频/语音台是一个 `<a>`（带下划线、没有 hover），
  而且点了只是浏览器下载。现在三台都走 `Wb.save(url,name)`，与卡片上的「下载」是同一套实现
  （先判 HTTP 状态，再交给浏览器存到它自己的默认位置）。
- 「详情」按钮点开就是完整详情面板 —— 提示词、模型与参数、积分/费用、耗时、任务号、资产 ID，
  和卡片上的「详情」是**同一个渲染器**，信息完全一致；换上一张/下一条会自动收起。
  外观沿用资产库那套（深色半透明浮层 + 浅色正文，其中提示词仍是白底卡片，两种主题都可读）。
- **这一份「详情」现在也归 `Wb.detail`（`workbench.js`）**：资产库、图片、视频、语音四页以前各写一份
  `renderDetail / fmtDetail / promptBlockHTML`，同一个字段四种解释（比如「耗时」：VGENV 完成的任务没有
  `completed_at`、只给 `updated_at`，只看前者会把已完成的显示成「进行中」）。现在四页只提供适配器
  （提示词 / 状态 / 平台 / 任务号 / 页面专有行 / 参考图 / 额外动作），渲染与刷新逻辑只有一份：
  同名行自动去重、进行中的任务耗时每秒更新、拿到的详情缓存 60 秒（避免卡片重绘时反复打接口）。
- **详情只显示「这条任务真的有的字段」**：空值、空数组（例如没有资产 id 时的「资产ID」）、
  平台的占位值（`none` / `auto`）、已经用别的方式表达过的原始时间戳（`created_at` / `queued_at`…）、
  已完成任务的「进度 100%」都不再占一行；字段取值**以上游详情为准**（它给的是实际请求值），
  本地记录只在没有上游详情时兜底 —— 所以「创建时间 / 完成时间 / 时长」不会再出现本地与接口两套数字。

**图片台 / 视频台的卡片来自接口，本地不留任务卡**：创建成功后按任务号把那条任务从接口取回来插进列表
（取不回来就整表刷新），所以不会再有「生成中」的本地占位卡、也不会出现「本地卡与平台卡对不上」。
语音台是例外 —— MiMo 是同步合成、上游没有任务号，本地记录就是它的唯一凭据。

**三个工作台的上工具条已经统一**（图片台原来把「跳页」放在翻页按钮前面、按钮文字也不同）：

```
[搜索框] [搜索]    ‹ 上一页   第 N 页 / 共 M 页   下一页 ›    [跳页输入] [跳转]    [刷新]
```

- 页数**永远显示**：分页模式就是当前页；「动态加载」模式（滚到底自动续拉）按已加载条数折算成第几页 ——
  文案由 `Wb.pager.infoText()` 一处生成，三个台（图片 / 视频 / 语音）与资产库、收藏页都不会各写各的。
- **平台的列表接口没有「总条数」**（只有游标与 `has_more`，实测 SparkCine / VGENV 都一样），所以「共 M 页」：
  数准之前按**已经取回本地的条数**折算并标成 `共 M+ 页`，后台把游标翻到底数完后（`Wb.tally` + `AssetLib.countAll`，
  一次 `limit=100`，101 条只要 2 个请求）变成精确的 `共 M 页`；数不完（超出请求上限 / 某来源读失败）就一直带加号，
  不假装数完了。提交与删除后重数一趟（不做 +1/-1 的猜测校正：任务完成前只算 1 条、完成后是 N 条产物）。
  搜索模式不数 —— 筛的只是本地已加载的条目，平台那个总数答非所问。
- 动态加载模式下翻页按钮隐藏（避免按钮一出一隐把右边那排挤动），其余控件位置不变。
- 卡片缩略图的光标统一为 `zoom-in`（图片 / 视频 / 音乐一致，音乐台原来漏了这条，写在 `ui.css`）。
- 没有可下载文件的条目（如图片台输入栏里的本地图）会自动隐藏这两个按钮。
- **信息行三台一致**：`数量` + `信息`，信息里都带**文件大小**（视频还会先补上分辨率，如
  `SparkCine 视频 · h3-video · 480×854px · 3.8 MB`）。体积来源分三种，都不需要下载整个文件：
  图片/语音直接读接口或本地索引里的 `byte_length`；**视频上游不返回体积**（实测 VGENV 与 SparkCine 都没有），
  用 `Wb.mediaSize()` 发一个 `Range: bytes=0-0` 的探测请求，从响应头 `Content-Range` 里读总大小后立刻断开
  （外部链接经代理 `/getv` 同源取回，所以这些响应头 JS 读得到），结果按 URL 缓存。

**耗时怎么算的**（两个台都修过）：判断任务是否跑完要看**状态字段**，不能只看有没有 `completed_at`。
VGENV 完成的任务里根本没有这个字段（它给的是 `updated_at`），以前会把已完成的任务显示成
「耗时 394 分 47 秒（进行中）」；现在完成的任务取 `completed_at || updated_at`，只有真在跑才显示「（进行中）」。

- **音色复刻的参考音频不再进 localStorage**：以前 10MB 的音频转成 base64（约 13MB）随任务一起写 localStorage，
  写爆配额时异常被 `catch` 吞掉，整批历史**静默丢失**；现在音频本体存 IndexedDB（`wb_blobs`），任务里只存键。
- 删除镜头/场景/候选时都会回收 `blob:` 地址（以前只有「删候选」「删项目」回收，删整镜/整场景会一直占内存）。

### `Store` —— 带上限的本地存储

```js
const list = Store.read('audio_tasks', []);
Store.write('audio_tasks', list, { cap: 200, label: '语音任务' });   // 失败会 Toast 提示，不静默
```

磁盘/浏览器里只有**一种格式**：信封 `{ data: 值, ts: 写入时间 }`（`ts` 给启动对账比新旧用，见下文）。
没有「读到裸数组自动当上一版接管」那套版本迁移 —— 结构变了就用一次性脚本把历史数据改成新格式
（`node 升级历史数据.cjs` 先看会改什么，加 `--apply` 才写盘；改前每个文件在 `.data/升级前备份/` 留一份原件，
**mtime 原样保留**，所以不会改变浏览器侧的新旧关系）。配额满/隐私模式下会明确告诉你哪份数据没保存。

## 数据持久化与云同步

浏览器存储（localStorage / IndexedDB）是**私有且随时可能被清掉**的：清一次浏览器数据、换浏览器、开无痕，
工作区与设置就没了（平台上的成品没事，丢的是分镜、选用、剪辑点和全部设置）。所以业务数据会**同时写一份到
项目目录的 `.data/`**，并支持推到自己的网盘。

| 机制 | 说明 |
|---|---|
| **数据落盘**（默认开） | 设置、历史、收藏列表、文字 AI 用量、**导演台工作区**都会写一份到 `.data/<键名>.json`（提示词另走「归档文件夹」，见下文）；写入是原子的（先写 `.tmp` 再改名）。内容**原样保存**——同步的键里有一半存的是普通字符串（`dir_theme=dark`、`sk_polish_*=提示词文本`、`sk_key_*=密钥`、`page_mode_=page`、`dr_dur_min=3`），所以这里不要求 JSON |
| **自动对账** | 每个页面启动时遍历「本地 ∪ 数据文件」：**只比内容**（体积先筛，体积相同但服务器更新时照样取回逐字节比 —— 等长修改也能同步回来；再逐字节比），不一样才拉回来并刷新一次；本地有而文件没有（首次启用）则补传上去。**浏览器数据被清空时也会从数据文件恢复回来**（键本身都不存在了的情况也算） |
| **浏览器持久化** | 启动时自动申请 `navigator.storage.persist()`，让浏览器不因磁盘紧张自动回收数据；设置页能看到是否已授予与当前占用 |
| **整包备份/恢复** | 设置页「导出整包备份」把 localStorage + IndexedDB（工作区、本地视频、收藏文件、参考音频）打包成一个 JSON；可选是否连本地文件一起打包，**也可选连提示词归档一起**（三选一，不叠加）。导入时归档那部分**不覆盖**本机已有的同名文件，恢复了多少、跳过了多少都会报出来 |
| **云同步（WebDAV）** | 把 `.data/` 同步到坚果云 / Nextcloud / 群晖。**「一键双向同步」**会两边都看：本机新的传上去、云端新的拉下来；**两边都改过的列为冲突不自动覆盖**，在设置页选一边（选云端前会自动留 `.bak.json`，可一键恢复）。**密钥默认不上传**（`sk_key_*` 会被跳过），要传需在设置页显式勾选 |
| **提示词归档的备份** | 归档是磁盘上的一堆 `.md`，**既不在 `.data/` 也进不了整包备份** —— 以前两头都漏，换机器就没了。现在有两条出口，都在设置页「数据与同步」里手动开：<br>· **跟着云同步走**：勾「连提示词归档一起」，归档会传到云端的 `prompts/` 子目录，跟着 push / pull / sync 一起。**只推不删** —— 归档是只增的创作历史，误删没法恢复；云端多出来的只报数量，要拿回来自己点「↓ 从云端下载」。<br>· **跟着整包备份走**：导出弹窗里选「数据 + 提示词归档」，那几百上千份 `.md` 一起打包进那个 JSON。**恢复时一份也不覆盖**本机已有的同名文件。<br>两处都会说清「这次带上了多少份、漏了多少份」；云端目录建不出来（有些网盘不允许 WebDAV 建目录）时点「测试连接」就能提前看出来，不会闷着头传一堆 404 |

### 怎么用

1. **什么都不用做**：数据已经在往 `.data/` 写了。清浏览器数据后，重开页面会自动从那里恢复。
2. 想放到云盘同步目录（OneDrive / 坚果云）：在 `.env` 里设 `DATA_DIR=D:\OneDrive\workbench-data`（绝对路径）。
3. 想直接同步到网盘：设置 →「数据与同步」→ 地址**已默认填好**坚果云的 WebDAV 入口
   （`https://dav.jianguoyun.com/dav/ai-workbench/`；换别的服务商直接改这个输入框）→ 填账号与**应用密码**
   （坚果云在「账户信息 → 安全选项」生成，不要用登录密码）→ 测试连接 → **⇅ 一键双向同步**。
   地址也可写进 `.env` 的 `CLOUD_WEBDAV_URL/USER/PASS`。
   同步完设置页会显示：上次同步时间与结果、**待选择的冲突**（逐条二选一）、以及**可恢复的备份**。
4. **首次用某个云端目录不用自己建**：代理会在上传前自动 MKCOL 建目录；万一网盘不允许建目录，
   界面会直接告诉你「先在网盘网页端手动建好这个目录」并给出完整路径（以前这种情况只会报一句
   「上传 xx 失败 HTTP 404」，很难猜到是目录不存在）。

### 说明与边界

- **`.data/` 里会有明文密钥**（和你填在设置页的一样），所以它已被 gitignore；整包备份同理，别外传。
- 安全：`/data` 与 `/cloud` **只接受同源请求**（跨站请求一律 403）。这两组接口能读写设置（含密钥）与工作区，
  代理的 CORS 又是放开的，不加这层的话任意网页都能跨域读走。
- 本地视频、收藏的文件本体、音色复刻的参考音频**存在 IndexedDB 里**，`.data/` 只同步它们的**索引**；
  要把文件本体也带走，用「导出整包备份 → 连本地文件一起导出」。
- **冲突怎么判**：靠 `.data/.cloud-state.json` 里的**基线**（上次成功同步时每个键的内容指纹）。
  只有一边变了就自动传/拉；两边都变过 → 冲突，不自动覆盖，列出来让你选。
  第一次同步（没有基线）会退回「按内容时间取较新」的旧策略，并在结果里逐条标出「自动采用较新」——
  让你知道这一次是猜的；同步成功后基线建立，之后都是精确判定。
- **远端读不下来就跳过，绝不覆盖**：云端有这份、但这次 GET 失败（网络抖动 / 401 / 超时）时，
  该键判为「读不到」并在结果里列出来 —— **不会**当成「本地独有」去 push。
  （以前这种情况会用本地旧数据覆盖云端较新的一份，还没有任何提示、云端也没有 `.bak`。）
- **删除会被真正执行**：本地删掉一个键（`localStorage.removeItem`）会镜像成服务端的删除请求，
  「立即同步」时的 flush 也会把待删除项执行掉 —— 否则服务器上那份还在，下次启动又被拉回本地。
- **后悔药**：用云端覆盖本机之前，本机那份会留在 `.data/<键>.bak.json`；设置页的「备份」区可以一键恢复。
  （`.cloud-state.json` 以点开头，属于代理内部状态，不参与清单、上传与下载。）
- **已经作废的键会被一次性清掉**：功能改了、键还留着的那种（三个工作台合并进 `studio.html` 之后的
  `page_mode_image` / `page_mode_video` / `page_mode_audio` 与三份 `page_size_`、单删掉的「文字 AI 模型与识图」那张卡
  留下的 `sk_text_provider`、不再留本机任务副本的 `video_tasks`）会在启动时清一次：
  localStorage 的本体和 `.data/` 里的镜像一起清，**清镜像走 `DELETE /data/<键>?nobak=1`** ——
  代理删东西默认留一份 `.bak`（云同步那条后悔药），但这批键已经作废，为它们留备份只会让设置页的
  「备份」区永远挂着几行没人认得出的键名。清理排在启动对账**之后**（对账会拿 `.data/` 里的文件补回浏览器，
  顺序反了等于没清）；本机一个都没有就一个请求都不发。
  `audio_tasks` **还在用**（语音台的历史仓），别跟着一起清。

- 类型 / 时间 / 平台 / 模型 / 任务号 / 参数…

- **接在哪**：`Api.request(..., 'create')` 与 `Api.create()` 里统一挂钩（`assetlib.js` 的 `PromptLog`），
  所以四个工作台都自动归档；页面可以通过 `log: { type, meta, prompt }` 指定类型、文件头参数与要存的提示词原文
  （导演台提交的是平台语法的描述，归档的是原始描述），`log: false` 表示页面自己归档。

  设置页「提示词归档」可改（支持 `~` 与绝对路径，目录自动创建），那一项只存本机、**不参与云同步**（换机器路径不一样）。
- **本地路由**：`POST /prompts` 写文件、`GET /prompts` 列清单 + 索引、`GET /prompts/find?id=&provider=` 按任务号取回
  （一次返回**按该任务号匹配到的全部归档**：`provider` 只决定优先把哪一份当正文；索引里没有这条时会按文件头扫一遍目录，
  确实没有才回 404 —— 客户端每个任务只发这一个请求）、
  `POST /prompts/open` 在系统文件管理器里打开目录；只接受同源请求（跨站 403）。
- **索引**：目录内的 `_index.json`（平台 + 任务号 → 文件 / 提示词前 300 字）在每次写入时更新，丢了会自动按各文件头部重建；
  资产库就是靠它给「平台不返回提示词」的任务（VGENV）补显示（补回来的提示词直接当正常提示词显示，
  界面上**不再**挂「本地归档」小标签 —— 那个标签和卡片上「（该平台接口不返回提示词）」那行字重复、又占位置）。
- **标题**：由文字 AI 起（一句 8–16 字短标题，同一次会话同一个提示词只问一次）；没配文字 AI、超时或返回不可用时，
  自动退回「提示词前 10 个字」。文件名里不能出现的字符（`\/:*?"<>|`）会换成 `-`，重名自动加 `-2`。

## 任务状态是怎么来的（轮询 / 列表 / 缓存）

任务卡上的状态来自三处，优先级从低到高：

1. **本机任务记录**（localStorage）：创建任务时先记一条，页面立刻有卡；它只是"我知道我提交过"。
2. **列表接口**：任务列表/资产库读的是各平台的列表端点（registry 的 `list` 声明）。**列表是状态的最终依据** ——
   视频台每次刷新列表都会用它校正本地任务（本地停在"排队中"而平台已完成时，自动补上状态与产物）。
3. **单条轮询**：只有本地任务会轮询（`Api.pollTask`）。默认打 `poll`/`detail` 端点；
   **端点不可用时退回列表端点按任务号找**（registry 里可写 `pollVia:'list'` 直接声明走列表）。
   VGENV 的 `/v2/videos/{id}` 实测是 404 空壳错误（只回 `statusCode/code/message`），
   只认它的后果很严重：任务永远停在"排队中"，而且那个 404 会被误判成"任务已被清理"，
   于是同一个任务在界面上裂成两张 —— 一张假的失败卡 + 列表里真实的已完成卡。

**首屏缓存只存已完成（成功/失败）的条目**：缓存里留下"生成中/排队中"的快照，
下次打开就会把早已完成的旧状态当成现状显示成一条永远不动的假任务（新数据往往还没覆盖到它，因为它在后面几页）。
未完成的状态一律等接口回来说话 —— 首屏少几条，好过显示假状态。

**这套过滤只有一份实现：`AssetLib.listCache(key, cap)`**（`assetlib.js`）。四个页面各写过一份
`readCache/writeCache` + 自己的去重键（`assets_cache_v1` / `video_tasks_cache_v1` / `audio_tasks_cache_v1` /
导演台那份），其中两份**没过终态**——正是上面那条假状态的来源。现在页面只留一行：

```js
const LIST_CACHE = AssetLib.listCache('assets_cache_v1');   // 上限默认 200 条
LIST_CACHE.read();          // 只回终态条目；localStorage 写不进去时退到 sessionStorage
LIST_CACHE.write(assets);   // 写盘前再滤一次，缓存里不可能留下"生成中"
AssetLib.mergeEntries(base, add);   // 按 assetId/id/genId 去重合并（同一份键规则）
```

## 跨平台素材转存（AssetTransfer）

不同 API 之间素材不互通：A 平台生成的视频、外部链接的视频，想作为 B 平台的输入（参考图 / 参考视频 / 参考音频 / 首尾帧），
都要先「取回字节 → 上传成 B 平台资产 → 拿到 asset_id 再引用」。这套流程已抽成公共模块，**新平台接入不用写业务代码**。

```
AssetTransfer.blobOf(source)                 取字节：File/Blob ｜ dataURL ｜ blob: ｜ /asset/xx ｜ 外部 https（经代理 /getfile）
AssetTransfer.uploadTo(provId, blob, name)  上传成该平台资产（按 registry 声明驱动）→ 返回 asset_id
AssetTransfer.toAsset(provId, source)       一步到位（同一素材+平台自动去重，不重复上传）
AssetTransfer.crossTransfer(from, to, src)  跨平台转存的显式写法（语义清晰，带进度回调 onStage）
```

**新增平台只需两步**（无需改任何页面代码）：

1. `proxy.js` 的 registry 里给该平台声明上传端点：
   ```js
   endpoints: {
     uploads:  '/api/open/v1/uploads',                 // POST，返回 { upload: { url, headers }, asset_id }
     complete: '/api/open/v1/uploads/{id}/complete',   // POST，标记上传完成（{id} 自动替换）
   }
   ```
   端点名**只有 `uploads` / `complete` 这一套**（没有「老写法也认」的归一层）。
   改名就是改结构：同时把 `REGISTRY.version` +1，跑着的旧代理会被页面的「本地代理是旧版」提示点名。
2. 业务里调用 `AssetTransfer.toAsset('该平台id', 素材来源, { name, contentType })`。

**用户在设置页自加的中转平台不用改 registry**：`buildCustom` 是**整条克隆模板**（只摘掉 id / relay / base / keyEnv /
defaultKey / pricing / mediaProviders 那几项），`endpoints.uploads` / `complete`、`uploadFields`、`inputTemplates`
都跟着继承，所以 `AssetTransfer` 与能力接口天然认得它 —— 这也是「同一套接口形状的第三方中转，页面零改动就能用」的依据。

**外部链接为什么要经代理**：浏览器直连外部 CDN 会被 CORS 拦，代理的 `/getfile?url=` 通道负责取回字节（跟随一次 302、原样回传 content-type），
`/s3put?url=` 通道负责把字节 PUT 到签名地址。两个通道都在 `proxy.js` 里，只服务本工作台页面（跨站 403）。

### 上传进度（为什么由代理报，而不是 XHR）

字节上行分两段：**浏览器 → 本机代理**（回环，通常一两秒就完了）与**本机代理 → 对象存储**（真正慢的一段）。
浏览器能观测到的只有第一段 —— 拿 `XMLHttpRequest.upload.onprogress` 去量它，进度条会瞬间冲到 100% 然后继续卡住，反而误导。
所以进度由代理回传：`/s3put` 把请求体**边收边转发**（不再整块读进内存，200 MB 视频不再占 200 MB 堆内存），
同时按行吐 NDJSON 进度帧：

```json
{"t":"start","total":2097152}
{"t":"progress","sent":65536,"total":2097152,"pct":3}
{"t":"done","status":200,"body":"…"}      // 上游最终状态与响应体（对象存储的报错原因也在这里）
{"t":"error","message":"…"}
```

`AssetTransfer.uploadTo` 解析这个流并把进度报给页面：`onStage('progress', {sent,total,pct})`；
页面用 `ui.js` 的 `uploadStageText(stage, info, label)` 统一成状态行文案（含百分比与体积，
发完 100% 后显示「等待服务器确认」——那时字节发完了，对象存储还在处理）。
响应不是 NDJSON 时（旧代理）自动退回「只看 HTTP 状态」的老逻辑。

已在用：导演台（参考视频/参考图转存）、生成工作台（图像的参考图、视频的参考图/视频/音频、语音的参考音频）。

## 成片时间线、剪辑与用量

导演台的剪辑分两层：**本镜**（调当前候选的入出点）与**全片**（把全部已选用镜头合并成一整段视频）。内部的成片时间线数据（`proj.timeline.clips`）在导出/合并时按镜头顺序自动生成，手工调过的入出点/倍速会保留：

| 入口 | 作用 |
| --- | --- |
| **⬇ 导出成片** | 把**已选用镜头按拖动后的顺序**用 ffmpeg 合并成一个完整视频，保存到「设置 → 剪辑成片」目录（每段手工调过的入出点/倍速会被保留） |
| **▶ 播放成片** | 播放合并好的完整视频；还没合并或镜头有变动时会先自动合并再播放。
播放器左下浮层与播放/暂停按钮同一条：**播放/暂停 · 声音开关（记忆偏好） · 当前时间 / 总时长** |
| **✂ 剪辑 → 全片** | 全部已选用镜头一键合并成一个完整视频：重新合并 / 播放合成的视频 / 下载（保存到「设置 → 剪辑成片」目录，与生成视频、图片目录相互独立） |
| **🔍 素材检索建镜头**（左栏） | 自然语言检索资产库（关键词 / 类型 / 时长 / 生成时间范围 / 排序），AI 把命中素材整理成**场景、镜头与候选**追加到当前短片（视频→直接成为该镜的已选用候选，图片→该镜的参考图） |
| **📊 用量与余额**（侧栏独立页面） | 各 API 余额（SparkCine 积分 / VGENV ¥ / 文字 AI ¥）、逐条账单（可按平台/时间/关键词筛选）、近 14 天每日消费曲线、文字 AI 调用次数与 tokens 用量 |
| **📋 贴剧本，一键拆分镜** | 已升级为 AI 拆解：一段文案 → 场景与镜头 + 每镜提示词（未配置文字 AI 时回退到手动逐行拆分） |

- 资产库搜索支持「提示词 / 资产ID / 任务ID」模糊匹配，并可按日期筛选（快捷：全部·今天·近7天·近30天，或自定义起止日期）
- 资产库页支持「🤖 AI 检索」：自然语言（可含时间范围 / 时长 / 类型 / 排序）→ LLM 转成筛选条件就地过滤，顶部显示可清除的条件标签
- 「全片」标签页里那条分段条**可点击跳转**：点哪一段就把播放器跳到对应时间，同时左右栏切到该镜头
- 切到「全片」标签页会**自动开始合成**（无需手动点合并，状态栏与播放器空态实时显示百分比），合成完成后主栏播放器即播放合成后的整段视频

**渲染链路**：前端把 EDL（`clips[{src,in,out,speed,volume}]` + 尺寸/帧率）POST 给 `/render`，proxy 负责——下载素材（`/asset/<id>` 会用密钥换成最新签名链接；本地导入的视频先经 `AssetTransfer` 转存成资产）→ 逐段标准化到同一尺寸/帧率/编码 → concat 拼接 → 输出到 `.renders/`。进度用 `/render/status?id=` 轮询，成片用 `/render/dl?name=` 下载并保存到「设置」里的默认文件夹。

- 依赖 **ffmpeg / ffprobe** 在 PATH 中（`ffmpeg -version` 能跑即可）
- 片段音轨不一致时整片自动静音（避免拼接失败），状态栏会提示
- 支持 `src: "black"` 生成纯黑片段（片头/间隔）
- 渲染产物放 `.renders/`（已 gitignore）

### 用量与花费统计口径

- **只统计已配置的平台**：判定依据是「设置里填了页面密钥」或「服务端有环境密钥（/env-status 显示 hasEnv）」，没配的平台不显示。
- **生成平台花费**：直接取接口返回的真实积分 / 价格 —— SparkCine 用 `credits.charged`（积分），VGENV 用 `price.amount_micros`（¥，实测每条 40000 micros = ¥0.04）。统一由 `AssetLib.costOf(entry)` 归一成 `{cost, unit}`（积分优先，其次金额），账单明细、每日消费曲线、工作台任务列表、资产库详情都用同一个口径。
- **文字 AI 花费**：`模型单价 × 实际 tokens`，tokens 取自每次响应的 `usage`（本地记录，最多 500 条）。
  费用取**每次响应里平台自己报回来的** `usage` 与价格（`AssetLib.costOf`：先积分、再金额 micros），tokens 取不到就只显示调用次数并写明「平台没报 tokens」。
- **文字 AI 余额**：按平台规格表查询——DeepSeek `/user/balance`、月之暗面 `/users/me/balance`、硅基流动 `/user/info`；OpenAI / 智谱 / 通义等无公开余额接口，界面会标注「无余额接口」。

### 生成工作台的左侧输入区（视频 / 图像 / 语音）

版式统一成四段，从上到下：

1. **提示词 / 文本输入框**；
2. **动作磁贴**：`AI 润色`（强调色，固定在最左）、`一键清空` —— 同款磁贴外观（`.tool`，见 `ui.css`）；
   下面是**素材槽**：视频 / 图像 / 语音三种类型的槽位（首帧 / 尾帧 / 参考图 / 参考视频 / 参考音频）
   排成一列等大的磁贴，**样式与导演台右栏共用 `ui.css` 那一份**（`.assets-grid` / `.asset-slot`），
   这一页只管怎么排（`repeat(auto-fill, minmax(132px,1fr))` 自适应，只放一个素材的槽位那一块横跨两列）。
   磁贴上写明收什么类型、已有几张 / 上限 —— 全部来自能力声明；点开就是公共 `AssetPicker`。
   与已选素材互斥的槽位会变灰点不动（点一下闪一行说明为什么），当前型号不支持的槽位根本不渲染；
3. **素材缩略图行**：**一个素材一块缩略图**，上传几张就显示几张（图片 / 视频出画面，音频出图标 + 名称），
   每块右上角 `×` 单独移除，后面跟该类型的「＋」添加块（点它 = 打开统一选择器：资产库 / 我的收藏 / 本地上传，见 `assetlib.js` 的 `AssetPicker`）；
   弹窗顶部有一行「**本槽位规则 · 最多选 N 个 · MP3 / WAV，≤ 10.0 MB**」，计数条从打开起就是「已选 0 / 8」——
   **数量、收什么类型、单文件多大三条上限全部来自平台能力声明**（上游 `/models` 优先、`proxy.js` 的 `inputRoles` 兜底），
   点满或上传超限当场拦下并说明原因；平台没声明的就不显示这一行，绝不显示一份写死的「假规矩」。
   **能多选的槽位点几下就能攒到上限**：**点一下选一张、再点一下取消**（不用按 Ctrl —— 要的就是「点一下多选一张」），
   **Shift** 连选一整段（到上限为止，多的会提示「已选满 8 个，多的没选中」）。
   **「本地上传」传进来的文件也立刻算进同一个已选数**（不是另开一份）：传几张就写「已选 N / 上限」，
   点「确定」时**资产库里点的和本机传的会一起交出去**落进槽位 —— 这是「传了文件却加不进参考槽」的根因。
   位置不够时只收能收的那几张并说明（位置不够、类型不符、单文件超限三件事各说各的）。
   **单选槽位也是「点一张选中 → 底部确定」**，点一下不会直接关窗（选错了不用重开弹窗），**上传同样如此**
   （以前上传完直接关窗，还把刚点中的那一条无声丢掉）。
   本机传的文件**立刻出缩略图**（`blob:` 地址的字节已经在内存里，不必等滚到附近才抽帧），
   并且排在网格最上面（按上传时刻排，不按文件修改时间 —— 重传一个旧文件沉到底部，看着就像「没有缩略图」）。
   被互斥挡住的类型显示为灰色不可点（点一下就地闪出原因，见上一节）；
   **网格里的图片 / 视频不一次性全加载**：卡片先出占位格（立刻能看、能点、能多选），滚到附近才按
   「在飞请求」封顶（图 8 / 视频 2）逐张补图，缓存里已有的缩略图直接放行 —— 同一个弹窗里上百张素材时不再卡着等；
   缩略图读不出来时显示「预览读不到」占位，不会静默消失；
   从资产库选来的图片，若地址不是本平台 `/asset/` 直出（远端签名地址会过期），会自动取回字节存成本地文件，缩略图与提交都更稳；
4. **润色结果面板**（就地展开，见下）；视频台还有一个**「平台自动润色」**开关 —— 平台在创建接口里带了顶层布尔
   （SparkCine 的 `optimize_prompt`）时才会出现，开了由平台侧再优化一遍提示词；平台没这一项（VGENV）就不出现。

### 提示词润色与识图（文字 AI）

**交互统一**：润色按钮固定在**提示词输入框左下方**（导演台「AI 润色提示词」、生成工作台里三种类型各自的「AI 润色」）；
点一下，结果就**地展开在输入框下方**（`ui.js` 的 `InlinePolish`，不再弹窗）——可编辑的结果 + 「替换原提示词 / 重新润色 / 放弃」三个动作，
底部显示「原文 N 字 → 润色后 M 字」。面板在导演台里会跟着编辑器重渲染重新画出来，你改过的版本、以及切换镜头再切回来都不会丢；
「一键清空 / 清空」会连面板一起收起。

**润色前会先反问（两段式，仍在同一块面板里，不开新弹窗）**：文字 AI 先读一遍你的描述与**随附的素材**，
**它自己判断**是先问几个问题、还是内容已经够具体直接润色 —— 判据是「补上这些会不会明显改变成片效果」，
**不是按字数**（一句 30 字可能很清楚，一段 200 字也可能全是废话）。判据、要不要问、问题怎么写，
都写在指令里（`TextAI.DEF.ASK_NOTE` 的「补充信息」段 + `askPolish` 的契约段）。

要问时就地列在输入框下方让你答：每题是若干候选芯片 **+ 最后一个固定是「其他」**（点它直接在那一题里打字，
会原样发给 AI），底部是「按这些回答继续润色 / 跳过，直接润色」和「已回答 N / M 题」。
答完它把这些答案当作**硬约束**写进润色，结果面板上多一个「改回答」按钮（重画同一批问题、已选答案带回去，不重新问模型）；
没答的题按默认理解走。模型没按格式回、或这一步失败，就**跳过问答直接润色**（面板会写明「这次没能反问」），不把人卡住。

设置 → 提示词润色 → ⑥「润色前要不要先反问」三档：
**交给 AI 判断（默认）** ｜ **强制先问** ｜ **从不问，直接润色**。

**识图模型润色时会收到素材图**，并被告知「图N = 哪张素材」，据此结合画面内容润色（编号与提示词里的 `@参考图N` 对齐）：

- 导演台：`参考图 1..N`（与 `@参考图N` 同号）、`首帧（开头画面）`、`尾帧（结尾画面）`、以及尚未进参考图的 `时间切片画面（第 X 秒）`；
- 生成工作台：视频那一栏 `参考图 1..N`、`首帧`、`尾帧`；图像那一栏 `参考图 1..N`（语音那一栏只有参考音频，附不了图）。
- 图片先压到最长边 1024 的 JPEG 再发（最多 6 张），只做参考、不需要原图分辨率；读不出来的素材自动跳过，不影响润色。
- **附不了的素材也照实说**：视频 / 音频无法随消息附上，但会被明确写进系统提示 ——
  「用户已随这条消息附上：图片 ×3（图编号见消息末尾…）；用户还有**无法随消息附上**的素材：视频 ×1、音频 ×1，
  用途分别是 参考视频（沿用它的运镜和节奏）、参考音频（沿用它的节奏）。你看不到它们的内容，只能按这里的说明理解，
  **不要凭空编造画面或声音细节**。」（`TextAI.materialNote`，三个工作台共用这一份措辞。）
- **追问那一轮带同一份素材** —— 看过画面再问，问出来的才是画面相关的问题。

**算不算「能识图」由能力判定决定**（`TextAI.vision`，优先级从高到低）：

1. 设置页「识图能力」手动选择（`sk_text_vision`：自动 / 支持 / 不支持）；
2. **接口返回的字段**（主力判据）：拉 `/models` 时看模型条目里有没有多模态声明 ——
   `input_modalities` 里含 `image`、`architecture.input_modalities`、`capabilities.vision`、
   `supports_vision`、`features`/`tags`/`capabilities` 数组里的 `vision` 等。
   判定结果按「模型 → 能否识图」缓存 12 小时（`sk_model_meta_<平台>`）；回源失败**不写缓存**，沿用上次结果。
3. `proxy.js` registry 里该文字模型声明的 `vision: true/false`（接入新平台时可写死）。

三个来源都没说 → **按不支持处理**（少带图只是少一层参考，不会凭空多花 tokens），界面上会写明
「接口与平台声明都没说这个型号能不能吃图片」，要带图就手动选「支持识图」。
**刻意不按模型名猜**：`vl` / `vision` / `gpt-4o` / `claude` 这些名字会骗人 ——
开源复刻经常顶着同样的名字但不吃图，`vl` 后缀也可能是纯文本微调，猜错就是白花 tokens。

> 为什么以接口字段为准：名字会骗人。实测 DeepSeek 的 `/models` 里 `deepseek-flash` 是
> `input_modalities: ["text","image"]`（支持识图），而 `deepseek-v4-pro` 是 `["text"]`。
> 同一个前缀，一个能看图一个不能 —— 这种差别只有接口自己说得清。

判定为识图模型才附带图片（`TextAI.chat` 用 OpenAI 多模态格式提交 `content: [{type:'text'},{type:'image_url'},…]`）；
否则只发文字。用了哪些图、为什么没用图（含**依据的是哪个字段**），都写在面板标题旁的那行小字里，
设置页的识图提示也会显示 `（判定依据：接口字段 input_modalities 声明支持图片）` 这样的说明。

**所有「文字 AI 改写」的指令都能在设置里改**（设置 → 提示词润色，逐条带「恢复默认」）：

| 设置里的条目 | localStorage 键 | 用在哪 |
|---|---|---|
| ① 视频提示词润色 | `sk_polish_video` | 生成工作台「视频」那一栏的「AI 润色」· 导演台右栏「AI 润色提示词」 |

### 文字 AI：供应方与型号（设置 → 供应商与密钥的「文字」档 + 「文字 AI 模型与识图」卡）

- **供应方可多选一**（`sk_text_prov` 存 provider id）。内置两条：`openrouter`（**默认**，`https://openrouter.ai/api/v1`，
  一把密钥调几百个型号）与 `deepseek`。每家的**密钥 / 接口地址 / 型号各自独立保存**（`sk_key_<kid>`、`sk_base_<kid>`、
  `sk_model_<kid>`），换一家不会把上一家的设置搅乱。没显式选过时：**默认供应方得真的能用**（本机有密钥，或 `.env` /
  系统环境变量里配了）才轮到它，否则退到下一家有密钥的 —— 光换默认会把原来能用的润色弄坏。
- **型号可以自己填**：上面有一个「自己填一个型号」的输入框 + 「添加型号」。填进去的型号存 `sk_text_models_<kid>`（**只属于当前这家**），
  永远出现在下拉里，不依赖接口的 `/models` 有没有列它（聚合平台型号几百个，接口未必列全）；填错也不要紧，
  芯片上的 ✕ 删掉即可。点「获取型号列表」会把**这一家**接口返回的全量并进同一个下拉。
- **下拉里只有当前选中的那家的型号**，而且**完全动态**：只有「接口返回（<供应方名>）」（点「获取型号列表」拿到）
  与「自己添加」两类，**不预置任何固定清单**（registry 里那两个「平台内置」只作内部兜底，不展示）。
  切供应方时列表整体换成那家的（不会把上一家的型号混进来 —— 以前是全局一份列表，切了还串着）；
  一家都没取过时只显示它已保存的当前型号，并注明「这家接口还没取过列表」。
- **「测试」用下拉里当前选中的那个型号**（选了还没点保存也测这一支），识图提示同样跟着下拉走；
  另有一道**归属守卫**：型号不属于当前供应方就别发也别存（防止「切供应方时残留在下拉里的旧值」被写进去，
  之后每次润色都用错家）。
- 「常用接口」预设（DeepSeek / OpenAI / Kimi / GLM / 通义 / 硅基流动 / 自定义）只改**表单**，和这一卡其它项一样
  **点「保存全部设置」才落盘**；地址留空 = 用供应方自带的官方地址。
- **「验证密钥」按钮**：用余额接口的状态码判这把钥匙能不能用（不花钱）——
  `200` 有效（顺带报余额）｜`401` **无效**｜`403` 有效但这个接口要更高权限（OpenRouter 的 `/credits` 只认管理密钥，属正常）。
  **别拿「获取型号列表成功」当密钥有效的证据**：OpenRouter 的 `GET /models` 是**公开**的，不带密钥也能拉到 460+ 个型号
  （所以点完「获取型号列表」会自动顺手验一次并说明这一点）。鉴权类报错会带上「用的是：哪家 + 哪把钥匙的尾号」，
  密钥输入也会自动摘掉 `Bearer ` 前缀与空白（头是程序自己拼的，带前缀会变成 `Bearer Bearer sk-or-…`）。
- **三个按钮都只作用于下拉里选中的那家**（哪怕还没点保存）：选 OpenRouter 就打 `/openrouter`，
  不会打到已保存的那家去。识图判定同理。
- **地址与供应方必须是一家**：自定义地址按供应方各存各的，但很容易在「供应方 = DeepSeek」时把 OpenRouter 的地址填进去 ——
  请求就会带着 **DeepSeek 的密钥**打到 OpenRouter，上游只回一句 `Your api key ****xxxx is invalid`，
  界面上却像「我明明选了 OpenRouter」。**这类错配会自动被修好**：如果发现某个地址正好是
  工作台内置**另一家的官方地址**（当初点预设 / 切供应方时放错栏了），它会被挪回属于它的那一栏，
  当前这栏恢复默认，并给出「撤销这次挪动」；**第三方自建中转 / 代理网关**那种地址仍然只警告（可能是有意为之）。
  你**正在输入框里敲的内容永远不会被自动改动**。
  点「保存全部设置」时，若地址确实和供应方不是一家，会**问一次**「仍然保存吗？」（自建中转 / 代理网关就是
  合法用法）——选「仍然保存」就存，选「取消」只跳过这一项、其余照存。
  **官方地址都显式写出来**：OpenRouter 是 `https://openrouter.ai/api/v1`，DeepSeek 是 `https://api.deepseek.com`；
  「常用接口」里点 OpenRouter / DeepSeek **会连供应方一起切**（不会只换地址造出错配）。
  界面各处（地址提示、型号分组标签、保存、测试、识图提示）都以**下拉里选中的那家**为准。
- OpenRouter 的余额接口 `/api/v1/credits` **只认管理密钥**，普通 API key 会回 403（用量页会照实显示原因）；
  侧栏余额卡不画它（那边只有「金额 / 积分」两种解析形状，硬套会显示成 ¥0.00）。

### AI 助手（可拖动的悬浮球 + 右侧抽屉，`ai-chat.js`）

**这台机器上只有一份，它活在外壳层**（`shell.html` 引 `ai-chat.js`）：换页只是换 `#appFrame` 里的内容，
抽屉开合状态、对话记录、正在流式写出的那条回答都不重建。球可以用鼠标拖到窗口任意位置（松手才记进 `ai_chat_xy`，
下次打开还在那里），`Ctrl` / `⌘` + `/` 开合抽屉。**松手时球心落在窗口哪一半就吸到哪一边**——
左侧任意高度都吸到最左、右侧任意高度都吸到最右（分界线是**扣掉侧栏之后**那半张的中点，
所以侧栏展开时明显偏右的位置不会被吸到左边）；**上下不吸**，球留在松手时的高度。
拖到边上就是贴边，不用瞄准某一小段
（默认开，设置页「AI 助手」那张卡的「悬浮球拖到窗口边上时吸住」可关；键 `ai_chat_snap`，只在没勾时留 `'0'`）——
摆正之后坐标会立刻写回 `ai_chat_xy`，否则下一次按下用的是旧的松手处，球会先往左跳一截。
夹取范围**左边界让开侧栏**（读 `--sbw`：收起 66px / 展开 200px）——
球只有 `z-index:56`，侧栏是 90，停在它覆盖的那一条里就点不到了，等于把助手弄丢；存过的旧位置也在下一次摆放时挪回来。
八个内容页（index / studio / drama / chars / assets / favorites / settings / usage）也各引一行这个文件 —— 页面被**直接打开**（没套外壳）时
它自己挂载，套在外壳里时检测到 `window.top.__SB_SHELL` 就退出，免得两份实例各存一份记录、各画一个球。
外壳另外引了 `assetlib.js` / `workbench.js` / `drama.js`，所以注册表、能力声明、短剧与素材库都读得到，
查询不再取决于脚下开的是哪一页。

它问的是**这台机器与这个项目**：「哪几家平台配了密钥」「这个型号能传几张参考图」「本机几部短剧都到哪一步了」
「拍短剧还差什么才能导成片」「生图有哪些型号」「最近 7 天文字 AI 用了多少」—— 它去查，再用人话回答。

- **读：十七项查询全是本机读取或 GET** —— `overview`（本机现状一页：代理、平台、
  文字 AI 当前用哪家、各库有多少条、此刻界面上选中的下拉）、`tasks`（助手替你提交、还在等平台结果的那几条，
  **这一条会真去平台问一次状态**）、`history`（历史任务与产物，见下）、`doctor`（一键体检：代理新不新、四类平台各有几家**真能用**、哪几家被停用、
  设置页添加失败被丢掉的那几家、数据目录 / 归档 / 本机资产读不读得动、**本机能不能出成片**（ffmpeg / ffprobe 那两种「看着都像没装」的原因分开说、三个落盘目录可不可写）、云同步配没配、助手自己的三个开关与浏览器授权；
  带 `{"verify":true}` 才真去验一次文字 AI 的密钥）、`models`、`model`、`dramas`、`chars`、`fav`、
  `assets`、`prompts`、`usage`、`settings`、`credits`（余额按各家声明的单位显示，积分不折算成元）、`go`（换个页面看）、
  `files`（这次带了哪几个附件、每个还在不在）、`read_file`（真去读那一个：文本读出字，图片交给识图型号看画面，
  视频 / 音频照实说「本机没有听视频 / 音频内容的模型」）。
- **`history` 有两条路，助手必须分清**（这是「本机没有」和「平台上没有」的差别）：
  - 默认读**本机列表缓存**（生成工作台那一份，`AssetLib.listCache`）：立刻返回，但只反映「这个浏览器上次拉到过什么」。
  - `{"remote":true}` **真去平台列表接口查这个账号下的全部任务** —— 复用资产库那条 `AssetLib.load`
    （它按 `Api.listSources()` 把所有声明了 `endpoints.list` 的平台挨个拉一遍并归一成同构条目，
    助手不自己拼 URL、不写第二份归一化）。用户说「平台上还有别的吗」「我换台机器做的」「删过浏览器之后那些呢」就走这条。
  - 三件必须照实说的：**没声明 `endpoints.list` 的平台根本查不了**（上游只给单任务查询），
    那不是「那边没有任务」，不能算进空结果；列表接口动辄十几秒，所以先在对话里留一行「去问平台了」；
    拉回来的条目会顺手存进本机资产库（`AssetLocal.scan`，可在设置页关）。
  - 两条路查到的条目**直接画成卡片留在对话里**：图片能看、视频能就地播、语音能听，
    卡上带提示词、任务号、平台 / 型号 / 状态 / 时长，「去工作台看」与「下载」两个按钮。
    **卡片和助手念的那份列表永远是同一批**（画一套、念另一套比查不到更坏），按时间倒序。
- **拿不准就发选择框**（`ASK:` 指令）：像工作台的润色那样把候选摆出来等你点，
  面板直接复用 `InlinePolish.ask`（同一份芯片 UI 与状态保存）。它是**问不是动作** —— 不走确认卡片、不动任何数据，
  画完这一轮就停下等你答。选中状态存在那条消息里，所以任务出结果触发整轮重画也不会把你点了一半的候选抹掉。
- **回答按 Markdown 渲染**（`ui.js` 的 `Md`）：标题、列表、表格、引用、代码块（带复制按钮）、粗体 / 斜体 / 删除线 / 行内代码 / 链接。
  实现是**先整体转义、再解析**，产出最后再过一遍 `sanitizeHTML` —— 不认原始 HTML，图片降级成「［图：alt］」文字
  （画一个外链 `<img>` 等于让页面直连外部域名，违反统一路由）。`javascript:` / `data:` 这类 href 仍被 `safeHref` 拦掉。
- **写：两个动作，都要在卡片上点「执行」才真做**（`RUN:` → 确认卡片）——
  `generate`（往图片 / 视频平台提交一次生成任务）与 `set_setting`（改一项设置）。
  **校验在卡片画出来之前做完**：型号属不属于那家、参数取值在不在声明里、槽位上限、素材从哪来，全部过了才画卡片；
  卡片上写明「哪一家 · 哪个型号 · 什么参数 · 哪些素材从哪个地址来」，一张卡片只认一次执行（执行结果接回下一轮上下文）。
  没确认的卡片挂着时「清空」被拦住。误触一次就是真金白银的重复提交，所以没有「顺手替你提交了」这条路。
  设置页「执行前不用我点确认」（键 `ai_chat_auto`，只在勾上时留 `'1'`）只省掉那一下点击：卡片照画、
  **校验全部跑完**才自动提交，一条任务在平台那边就是一条真任务，没把握别勾。
- **助手替你提交的任务，外壳自己接着等**（`ai_chat_watch`）：拿到任务号就挂进等待清单，每 12 秒按任务号去平台问一轮状态
  （**只问、绝不重新提交**，刷新这一层之后接着等），一次最多留 12 条、超过一小时自动放弃。
  出结果那一刻：对话里多一条虚线框的「你 N 分钟前让我提交的那条任务：好了 / 失败了」（写清平台、型号、任务号、接口回的状态与产物地址），
  这条**同时进下一轮上下文、也跟着会话一起落盘**，所以接着问它「我刚那条怎么样了」不需要猜，刷新之后也不需要猜；
  正在流式写出的那条回答不会被这条结果挤掉（重画之后原样挂回去 —— 字丢了但请求还在跑、还在扣 tokens）。
  抽屉收着时球上点个数字 = 几条结果没看，展开抽屉就算看过。另外三种情况都不假装能成：接口暂时查不到、
  这一家本轮问不通、**连续三轮整轮问崩了**，都只算「还在等」，**不当成任务失败**（把网络不通判成失败就是骗人）；
  问崩了会明确说「这不代表任务失败」，然后继续按任务号问下去（绝不重新提交）。
  想要**系统通知**（桌面弹窗）就在设置页勾「助手提交的任务出结果时弹一次系统通知」并点旁边的「现在授权」——
  浏览器只允许用户点一下才给权限，所以状态那一行照实写「没这个能力 / 系统设置里禁止了 / 还没授权 / 已经可以弹」，
  不在代码里偷偷 `requestPermission()`。
- **对话分会话，可新建、可翻历史**：标题行上「＋」另开一段（当前这段留在历史里），「🕘」打开历史会话
  （浮层盖在对话区上面，不替换它 —— 点错一下不会把正在写的字换掉）。每段有标题（你说的第一句话）、时间与条数，
  点一条切过去，「✕」删掉（有内容的会先确认，至少留一段）。「清空」只清**当前这一段**。
  每段的对话**和**这一段里发生过的动作一起落盘，**刷新 / 换机器都还在**。
- **Enter 发送、Shift+Enter 换行**（中文选词上屏那一下不拦 —— 否则「刚选完字就直接发出去了」）。
  **只带文件、一个字没打也是一次完整的发送**（「把这张图看看」本来就不用打字；气泡里写明「（只带了文件，没打字）」，
  别让助手以为用户真的只说了这一句）。
- **附件分「草稿」与「这一条带的」两个状态**：输入框上那排芯片是**还没发出去的草稿**，
  按发送的那一刻拍一份快照挂到你的气泡上（`随这条发出：图片·猫.png`）并**立刻把输入框清空** ——
  「发出去的东西还挂在输入框里」会被当成没发出去，于是再发一次（等于白花一轮 tokens）。
  气泡上那份摘要跟着消息落盘，刷新后仍在；会话标题也会优先用它带的文件名。
  助手这一头能读到的附件走 `ctxFiles()`：**先看这一轮真正发出去的那份，没有才看草稿** ——
  所以发完之后接着追问「第二张里是什么」、或者拿附件当参考图提交，都还对得上，
  序号不会因为草稿被清空而指空。媒体附件存进本机资产库的那份**不删**（那是你的资产，删东西在资产库/收藏页里来）。
- **上游的安全拦截不当成回答显示**：不少供应商（含 OpenRouter 免费档）是 **200 正常返回**，
  把「User Safety: unsafe / Safety Categories: Harassment, Fraud/Deception」这样一整段直接写进
  `message.content`。照旧当成助手的回答渲染，等于**把「这一次没答成」说成「它就是这么答的」** ——
  用户以为助手答完了，模型也没机会解释或换个说法重试。`safetyBlockText()` 认出这种
  「整段正文其实就是一条 `键: 值` 通知」的形状，改报一条明说「被上游安全过滤挡住、它没有作答」
  的红色提示，并把它自己标的类别带出来。判据卡得紧（≤6 行、每行都得是 `键: 值`、
  键限 ASCII 词字符），所以**正常中文回答里提到 `content_filter` 这类设置名不会被误判**。
- **附件的凭据只有本机地址**：抽屉里拖入 / 选择的文件，图片 / 视频 / 音频会落一份**本机资产**（`/asset/la_xxx`，
  别的页面从资产库也挑得到，类型按字节现算），文本读一份截断后的快照；附件的**身份**（名字 / 类型 / 地址 / 快照）存
  `ai_chat_files`，换页与刷新都还在。字节的来源只认 `/asset/`、`/getv/`、`/local-assets/`，
  外部直链一律拒（递出去的是「这个文件在哪」，不是「随便替我访问一个网址」）。
  卡片上写的「素材 ← 附件第 0 个」按**画卡片那一刻**的身份（序号 + 文件名 + 本机地址）钉住：卡片挂着的时候你加 / 删了附件，
  点「执行」会先复核，对不上就拒掉并说清原本指的是哪一张 —— 序号会漂，漂了就不能凭它替你提交另一张图。
- **能改的设置是白名单**：界面主题、AI 润色前是否反问、文字 AI 识图、各页列表模式与每页条数、各供应方的默认型号，
  再加上**拍短剧那几项**（整集时长目标、两个 AI 自主权开关、做下一集默认沿用范围）。这一份不是手抄的清单 ——
  `writableKeys()` 现读 `window.PAGE_TARGETS` 与 `Drama.SET` 那两张表（单页被直接打开、这一页没引 `drama.js` 时
  现取一次脚本再读），所以设置页加一行、助手这边就跟着能改，不会出现「那边有、这边说改不了」。
  数值型设置只校验「是个大于 0 的数」并写明单位与**它管不了什么**（分钟数最终仍会被视频平台声明的档位夹），
  不在助手里另编一套上下限。
  `sk_key_*`（密钥）与 `sk_base_*`（自定义地址）**明确拒掉**并写明原因 —— 前者会跟着对话记录出网，
  后者容易造出「A 家的密钥打到 B 家的地址」那种必然失败的组合；这两类只能在设置页由你自己填。
- **数字一律现查现说**：平台 id、型号名、参数取值、数量上限、余额、条目数只允许来自查询结果；
  查不到就照实说「本机没有这条记录」「代理没响应」，不补一段看着像答案的猜测。
- **回答是流式的**，边收边写，中途能按「停止」（已经写出来的字保留，并写明这次断了）；流式进行中不许「清空」。
  查询次数**不设上限**（要查够为止；兜底的是上下文 —— 查询结果把上下文占满就收尾，同一个查询连问两遍还没换内容也收尾），
  每查一次在正文上方留一行灰色小条（查了什么、参数、拿到多大一份）。
- **供应方与型号在抽屉里自己选**（存自己的 `ai_chat_pick`），**不改**设置页保存的值 ——
  发请求时把选中的那家显式传进去，不会出现「下拉选了 A、实际发的是 B」。
  **「取型号 / ＋型号」两个按钮已从抽屉里删掉**（2026-10）：管文字 AI 的供应方与型号是设置页「文字」那一档的事，
  助手只是个问答抽屉，不必在这里也能改一套。抽屉的下拉照旧能用，只是不再能从这儿拉接口清单或手填调用名 ——
  这两件事去设置页做，型号是同一个键（`sk_model_<kid>` / `sk_text_models_<kid>`），不会分成两处。
- **记录与状态都在本机**：对话记录存 `Store('ai_chat')`（跟着 `.data/` 与云同步走，换浏览器也在），
  球的位置存 `ai_chat_xy`、附件身份存 `ai_chat_files`、替你等任务的清单存 `ai_chat_watch`，
  四个本机开关 `ai_chat_snap`（拖到边上吸住）/ `ai_chat_auto`（执行前不用点确认）/ `ai_chat_notice`（弹系统通知）/
  `ai_chat_off`（**这个浏览器上干脆不装助手**：关掉后右下角没有悬浮球、`Ctrl + /` 也不生效，**对话记录全留着**）
  也各存各的 —— **这七条都不进 `.data/`、不跟着云同步**（`DataSync.NOT_SYNC`）：球该贴哪条边、在等哪几个任务号、
  通知授权、「这台机器上要不要它」，全是「这一台机器 / 这一个浏览器」的事，同步过去等于把提醒弹给错的人（对话记录本身照旧同步，换机器还想接着问）。
  总开关是**默认开 = 不存键**（勾上关掉才留 `'1'`），改完刷新才生效。
  **抽屉展开与否不保存** —— 刷新之后是悬浮球，点一下才开
  （记住「上次开着」等于每次刷新都先拿抽屉糊住页面）。
  刷新 / 关掉这一层时，已经流出来的字会先落盘并写明「后面没写完」，不至于凭空消失。
- 页面要让自己的状态也能被查，注册一次 `AiChat.pageCtx(() => ({ ... }))`（它把函数写到那一页的 `window.__acPageCtx`，
  外壳那份现取；只读快照出现在 `overview` 的「当前界面」，现在只有拍短剧页注册，因为那一页的状态在闭包里、外面读不到）。
  界面上的下拉当前值**不用**注册 —— 助手自己扫 DOM，所以任何一页都能回答「我现在选的是哪个型号 / 参数」。

### 窗口尺寸自适应

- **外壳侧栏**（`sidebar.js`，收起 66px / 展开 200px）：≤1100px 算窄窗口，此时展开是**浮层**（盖在内容上、带投影，
  `--sbw` 仍是 66px，内容区不被压缩），选完页面自动收回，**点内容区也收回**；宽窗口才是 66 ↔ 200 的真让位。
  窄窗的「点内容区关闭」靠 `app.js` 的 `wb:close-sb-overlay` 通道：iframe 里的点击不冒泡到外壳，
  所以由外壳在 iframe 文档上挂捕获监听再 `window.postMessage` 通知（弹窗与灯箱里的点击不算「点内容区」；
  宽窗口下是真让位、不是浮层，收到通知也不收）。
  收起态一律 `display:none` 藏文字（不是 `opacity:0`：那藏得住字却藏不住它占的宽度，图标会偏左），
  余额卡在收起态压成小卡并**保留缩写数值**（`data-short` 的 `::after`，窄窗收起同样要有数字，不能只剩图标）。
  窗口矮时底部两块不缩也不许被裁（`flex:0 0 auto`），只让余额列表自己在 `min(34vh,260px)` 内滚，
  且 `overflow-x` 显式写 hidden —— 一轴 auto 会把另一轴也算成 auto，66px 里会冒出横向条。
  显示**哪几个接口**的余额在「设置 → 平台密钥与余额」勾选（键 `sb_bal_show`，读写只有 `ui.js` 的 `SbBal` 一份，
  侧栏靠同源 `storage` 事件就地重画，不重取余额）。
  **在设置里删掉一家自定义平台，那张余额卡当场消失**，不用等这一轮 60 秒 ——
  余额刷新是「先画 localStorage 缓存、再取数」，只等下一轮的话用户点完删除看着像没删掉。
  隐藏名单里那个已经不存在的一家的 id 也顺手摘掉（`SbBal.prune`，侧栏每次取完余额调一次）。
  **本机压根没在用的那几家不画**：注册表里声明了余额端点的平台本来会全被收进来，
  于是「没添加、没密钥」的一家也占着一张卡、内容永远是「获取失败」——
  一张永远失败的卡不是信息，是噪音。判据与设置页那张卡是**同一份**（`Api.provUsable`：
  自己添加进来的 / `sk_key_` 有着落的 / `.env` 或系统环境里有的，三档算在用）。
  配了却读不通的那几家仍然会出现、并且照样显示「获取失败」—— 那是真错误，不会一起藏掉。
- **导演台**（三档，栏宽用 `clamp()` 跟着窗口平滑缩放，不再固定像素）：
  1. **宽屏（>900px）** 三栏并排：分镜 `clamp(198px, 19%, 270px)` / 播放·时间线（吃掉剩余空间）/ 编辑 `clamp(298px, 28%, 400px)`；
  2. **中屏（620–900px）** 分两行：分镜 + 播放·时间线 并排一行（保留「边看边挑」），编辑区整行落到下面；
  3. **窄屏（≤620px）** 彻底单列，每块整行。

  注意：导演台的骨架 `.page-main` 默认是「一屏高 + 裁掉溢出」（头部固定、三栏各自滚）。
  窄窗口下必须把它放开（`height: auto; min-height: 100vh; overflow: visible`），否则堆叠出来的内容会被裁掉、页面滚不动 ——
  这条已写进 ≤900px 的媒体查询；`.page-main` 的基础规则放在主 `<style>` 里（不要在 body 后再补一条同名的，会因顺序覆盖掉媒体查询）。
  另外矮窗口（高度 ≤620px）会压扁头部与留白，并把播放器限到 26vh / 40vh，别让画面把整屏占满。
- **生成工作台**：≤960px 由两栏堆叠成单列（原本就有）；≤720px 再收紧留白、缩小磁贴（64px）与缩略图（54–56px）。
- **资产库 / 收藏 / 设置 / 用量**：≤760–820px 收紧页面留白，筛选行与日期区间允许折行，收藏网格最小列宽降到 150px。
- **弹窗 / 灯箱**：弹窗统一 `width: min(720–900px, 92–94vw)` + `max-height: 84–88vh`；灯箱媒体 `80vw × 84vh`。

### 提示与报错（导演台）

- **普通提示走顶部那行小字**（在「已保存」右边，出现几秒自己淡出）：例如「已定位到 8.2 秒」「✓ 已采用这条」。
  它们**不弹浮层** —— 以前要么被直接丢掉（看不到），要么弹成右上角的轻提示（每点一下都弹，很吵）。
- **错误与警告走顶部横幅**：出现后**一直留在屏幕上**，直到点它的「×」关掉、或被新的错误替换；
  清空状态和普通提示都不会把它顺手收起 —— 免得正在看别处时错过。

### 出错时看到的是什么

- **上游只给一句泛化提示时**，`Api.request` 会补上人能看懂的下一步。例：SparkCine 的 `VALIDATION_FAILED` 顶层只有「部分内容需要检查。」，
  界面会显示「部分内容需要检查：平台这次把提交拦下来了（上游只回这一句，实测是间歇性的：同一句提示词过一会儿就能过）——隔几十秒再来一次通常就好」。
- **上游给了字段级明细时**（`error.details.issues`），明细会被拼进同一句话，例如
  「部分内容需要检查。（inputs.0.asset_id：格式不对，不是合法的 asset id（UUID）；parameters.output_count：超过上限，最多 4）」
  —— 直接指出哪个字段不对，不用再猜。（为此提交前会先校验 `asset_id` 是不是本平台的 UUID，本地资产 / 别家平台的 id 一律改走「取回字节再上传」。）
- **创建任务必带 `Idempotency-Key`**：SparkCine 缺这个头会直接 400，而且只回上面那句模糊提示（踩过一次：合并前的生图工作台，它的 `api()` 封装漏传 headers）。
  现在这个头由 registry 的 `create.idempotencyKey` 声明决定（默认 true，SparkCine 生图/视频都是 true；VGENV / MiMo 声明 false —— 客户端不但不补，还会把页面显式塞进来的删掉，免得重试造成重复任务）。
  现在**统一路由层（`Api.request`）对所有 POST 自动兜底补一个**，页面封装漏传也不会再踩；平台不认这个头的会自然忽略它。

### 转发层的两个缓存（取图 / 详情提速）

都在 `proxy.js` 里，只影响本地代理的取数速度，不改平台行为：

- **资产下载地址缓存**（`assetUrlCache`，TTL 5 分钟）：`/asset/<id>` 以前每取一张图都要先问一次上游「最新签名地址」（实测 1–3.6s），
  签名地址本身有 ~30 分钟有效期，所以同一 id 在 TTL 内复用解析结果。实测同一张图 6.4s → 0.9s，浏览器侧仍按 `immutable` 正常缓存字节。
- **已完成任务详情短缓存**（`detailCache`，TTL 5 分钟）：单条任务详情（路径里带任务号）在「状态已完成 **且** 已经有产出」时才缓存，
  卡片/详情反复打开不用每次回源（实测 4.0s → 0.02s）；**进行中的任务、以及「刚 done 但产出还没写入」的响应都不缓存**，状态照常实时刷新。
- 改的是 `proxy.js` 的代码（不是 `.env`）时**需要重启代理**（`启动.bat` → 2 停止 → 1 启动）。

### 生成工作台 · 视频/图像的任务与提示词关联

平台的列表接口**不返回提示词**（VGENV 就是），所以提示词靠本机归档：创建任务时把提示词存成归档文件夹里的一份 md
（见下方「提示词归档」），资产库 / 工作台按「平台 + 任务号」从归档索引取回来补显示。创建请求失败或中断时不再留一张假的失败卡：

- 创建失败 → 卡片**立刻**按真实原因结掉（状态「失败」+ 卡片上直接写出错误原因，可「重试」，重试会带上还记得的输入素材）；
  只有「刷新导致创建中」的老数据才会标成「创建请求中断（未拿到任务号）」。
- 列表拉回来后，`adoptOrphanTasks()` 会把这些没拿到任务号的本地任务**认领**到平台上的那条任务上（同平台 + 创建时间接近 + 平台没返回提示词）：
  顺带把提示词按新任务号补归档一份，然后撤掉本地那张假卡片；认领不到才保持失败状态。

### 任务卡的合并规则（生成工作台通用）

历史条目来自两处：**本地占位**（刚提交、还没出产物）和**上游列表**（已出产物），两边可能描述同一条任务。
合并规则（`AssetLib.mergeEntries` 与页面里的 `upsertItem`）：

- 同一任务（`gen_id`）且本地那条还没产物 → 认作同一条，把服务端/轮询结果**补齐到本地占位上**；
- 否则按产物（`asset_id`）匹配；一条任务出多张图时（同 `gen_id`、不同 `asset_id`）**保持多条卡片**；
- 已出图的条目不会被「进行中」状态覆盖回去。

以前这里只比 `asset_id`：本地占位（无产物）+ 服务端已完成（有产物）判不成同一条，
同一张图会显示成**两张卡 —— 一张已完成、一张永远停在排队中**。
另外，轮询时若上游回 404（任务被清理 / 任务号失效），现在会直接把卡片结为**失败**并写明原因，
不再无限排队（图片台与视频台都已处理）。

### 资产库的复制与复用

- 每张资产卡上：**📋 复制提示词**（写入剪贴板）、**♻ 复用**（跳到生成工作台对应类型继续创作）
- 复用的落点按素材类型决定：图片 → 图像那一栏（作为参考图）；视频 → 视频那一栏（参考视频）；音频 / 音乐 → 视频那一栏（参考音频）
- 工作台会自动带上提示词与素材；**若当前模型不支持该参考类型，会自动切换到支持它的模型**并在状态栏说明（图像按 image_edit 过滤模型，视频按 `inputSpecs`/modes 找支持该 `role` 的模型）
- 传递方式：`studio.html?t=<类型>&reuse=1` + `localStorage.sk_reuse`（一次性载荷，工作台读取后立即清除）
- 生成工作台的右栏卡片也能**直接拖到左栏**当参考素材：整张卡可拖，落到当前模型能接收该类型的槽位上

### 搜索交互（资产库 / 导演台选图弹窗）

- 搜索框右侧有 **🔍 搜索** 按钮（点击立即筛选；输入时依然自动筛选，两种方式都可用）
- **🤖 AI 检索**：搜索框里已有内容时，**直接按该内容做 AI 检索（不弹窗）**；搜索框为空时才弹出输入框

### 资产库的多选、批量下载与加载失败提示

- **多选是开关式的**：平时卡片上没有勾选框（点卡片 = 打开预览），点工具栏的「多选」才进入多选模式 ——
  此时每张卡片左上角出现勾选框、点卡片任意位置即勾选，顶部出现批量操作条
  （全选当前列表 / 取消选择 / **批量下载** / 退出多选；按 Esc 也可退出，退出会清空选择）。
  计数会写清「已选 N 项（当前筛选下可见 M 项）」，避免筛掉一部分后误操作看不见的条目。
- **没有「批量删除」**：资产库的内容是**实时从各平台接口拉回来的**，本机没有副本可删，删了刷新还会回来。
  只有「产物就存在本机」的素材才有删除按钮 —— 目前只有语音合成（落在 `.assets/`），
  按钮文案也写明是**「删除本机文件」**，删掉的是磁盘上的文件；SparkCine / VGENV 的素材不会有这个按钮。
- **加载失败会说出来**：以前某个平台读失败时界面显示的是「没有匹配的资产」（看起来像数据没了），
  现在顶部会列出「XX 加载失败：原因」，空列表位置也会给出同样的提示。
- 列表里有进行中的任务时会**自动轮询刷新状态**（全部完成后自动停），不再需要手动点「重新加载」。

### 三个工作台的任务操作已统一

图片 / 视频 / 语音三台的卡片动作现在是同一套：**详情 · 放大(试听) · 下载 · 取消 · 重试 · 删除记录**。
以前图片台没有取消/重试/删除，取消失败还会把界面改成「已取消」（实际平台仍在生成）；保存不判 HTTP 状态，
404 页面会被存成 `.mp4` 并提示成功。这些都已修正，实现集中在 `workbench.js`。

### 用量页与设置页

- **用量页**：账单可**导出 CSV**（导出的是当前筛选出的全部，不只是表格里显示的前 300 条）；
  计数会标注「表格只列出前 300 条」与「N 条平台未返回价格」；读不到 `/env-status` 时会提示
  「本地代理可能没在运行」，而不是笼统地说「还没配置任何平台的密钥」。
- **设置页**：
  - **网络与刷新**：请求超时（默认 30 秒）、失败重试次数（默认 1 次）、任务刷新间隔（默认 4 秒）。
  - **拍短剧**（独立一张卡）：整集时长目标（分钟，自由输入）、`让 AI 按剧情自己改整集时长`、
    `让 AI 给角色定音色`、`做下一集时默认沿用什么`。控件、默认值、文案**全部从 `drama.js` 的 `Drama.SET`
    现渲染**（`renderDramaSet` / `saveDramaSet`），所以这一页不写死任何数字与键名；分钟输入框也不写 `max`
    —— 真正的上下限由视频平台声明的档位算（`Drama.durationBounds`）。
  - **外观与界面**（`ui.js` 的 `UI_PREFS.rows` 一张表现渲染，助手能改的也是这同一张表）：
    界面主题、侧栏默认展开、**资产库 / 素材库 / 我的收藏三页的默认展示样式**。
    三页的档位名现在**完全一致**（`列表` / `紧凑`）：资产库原来叫「卡片」、另两页叫「列表」，
    于是同一个概念在设置里要写两种词、还漏了素材库那一项 —— 统一成 `list` / `compact` 之后，
    设置页、页面右上角的图标开关、助手这三处说的是同一件事。
  - **产物存放**（独立一张卡）：「产物自动存本机」「优先用本机文件」两档开关、本机已存产物占多少盘的实况、
    以及「另存到指定文件夹（按类型）」那一整块。以前这些全都混在「外观与界面」底下 ——
    那张表（`UI_PREFS.rows`）是平的，画出来就都落在同一栏；助手那边也会把它们一律冠成「界面 · 产物自动存本机」。
    现在**一项归哪张卡只在那张表里点一次名**（`group` 字段），助手取名跟着 `UI_PREFS.groupName()` 走 ——
    归属写在表里，页面只声明「这张卡收哪几个组」（`UI_PREF_CARDS`），两边都不再自己猜。
  - **润色指令那一栏默认折叠**（`set_fold_polish`，开合状态跟着整包设置走），标题右侧是展开按钮；
    十一条「文字 AI 改写」指令（①–⑪）逐条带「恢复默认」，默认文本只有 `assetlib.js` 的
    `TextAI.DEF` 那一份；短剧那五条（故事完善 / 拆剧本 / 角色与场景图 / 视频提示词 / 逐位定音色）里要求返回
    JSON 的两条，提示里写明了「改这条时请保留 JSON 格式要求」，占位符只认程序传的那几个名字。
    最后一条 ⑪ 是「润色前要不要先反问」（交给 AI 判断 / 强制先问 / 从不问）。
  - **导出 / 导入设置**：把接口地址、分页、润色指令、**拍短剧那几项（`dr_` 前缀）**导出成 JSON
    （可选是否含密钥），换电脑时导入即可；
    **恢复默认**会清掉这些设置（主题、列表视图与短剧页两个折叠面板的开合偏好保留；生成历史、资产、收藏不受影响）。
  - 文字 AI 接口地址现在允许 `http://`（内网 Ollama / vLLM 可用）；填了非法地址会明确提示，不再静默丢弃。
  - 清除目录时会连旧的兼容键一起清，四个目录行为一致（以前清了图片目录、视频还会存进老文件夹）。
