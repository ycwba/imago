# 我的收藏 —— 重设计稿（浅色主题）

> 这一稿**只出稿子，没有动产品代码**（`web/` `server/` `tools/` 全部原样）。
> 这一稿要回答的问题只有一个：**「我的收藏」这一页的布局该怎么重排**。
>
> 这一稿是**浅色稿**，但**夜间版不用另外设计**：产品令牌里的深色档一换主题就成立，
> 这一稿的深色档就是**同一个稿子把 `data-theme` 换成 `dark`** 自动派生出来的
> （深色覆盖见 `web/styles/tokens.css`）。
>
> 稿子里的内容**取自真机**：名字、大小、格式、日期、类型、来源、缩略图都是从这台机器的
> `.data/` 里读出来的（取数过程见文末「数据从哪来」）。
> 唯一编出来的是**备注文案**（真机那一条收藏的备注是空的）—— 文件里标得清清楚楚。

## 0. 怎么看

- 直接双击 `index.html`（纯静态，不取任何外部数据，`file://` 就够）。
- 或起一个本地预览：`node design/favorites-layout/serve.cjs 8099`
  → http://127.0.0.1:8099/design/favorites-layout/index.html
- 真品在收藏页 →（`/shell.html#favorites.html`）。

稿子右上角那枚 **`新版 / 现状`** 开关是**对照用的**：两边是**同一批内容**，
「现状」那一档是照抄真机现有排版的复刻（`web/styles/spa-pages.css` 里 `.fav-page` 那一族），
用来一眼看清前后差别 —— 不是新设计。

## 1. 改造前的四个问题（都指到真品）

### ① 卡里的信息顺序是反的

产品自己的 AI 挑素材规则写着（`web/pages/favorites.js` 第 414 行）：

> 优先级：备注（备注写的是用途）> 名称/描述 > 类型。

也就是说，**备注是这一页最要紧的一栏**。但在今天这张卡上，备注是最下面那个
34px 高的灰文本框，提示词是上面 12px 的两行小字 —— 真正决定「这条有什么用」的东西，
视觉上最弱。

### ② 每张卡三个常驻按钮，其中一个是红的

`复用 / 下载 / 移出收藏` 全都常驻，「移出收藏」还是**红色描边**（`.ghost.danger`）：
页面把**破坏性操作**放在了最强的视觉位置。50 条收藏 = 150 个按钮。

### ③ 页面不知道自己有什么

「本机 / 云端」是这批收藏最要紧的事实 —— 本地优先的产品里，
**这条的字节还在不在本机，决定它还能不能用**。今天它只是每张卡 meta 行里
`·` 分隔的一个小徽标（`.srcbadge`），页面上更没有任何概览。
「15 条里有 3 条只剩外链」这件事，用户要点开每一条才知道。

### ④ 两道工具条不在同一条基线上

第一行「筛选芯片 + 搜索 + AI 找素材 + 计数」，第二行右边孤零零三个按钮
（视图切换 / 存回本机 / 上传本地文件）。视线要来回折，第二行那三个按钮
与第一行的控件没有任何关系，却摆在同一个页头区里。

四条结构改动：

1. **页头收成一行。** 「找东西」的东西（搜索 / AI / 上传）都在页头一行；
   「摆法」与「页面级动作」收进下面那一行。视线不用来回折。

2. **多了一条概览条。** 这批收藏的字节有多少真在这台机器上 ——
   一条**按条数分的比例条**，左段是本机、右段是云端，两头各写清数字。
   这一条是本地优先的产品该有的第一眼事实，今天页面上没有。

3. **主体从「卡片网格」翻成「摘录行」。** 一行五段：
   **帧 ｜ 摘录 ｜ 字节在哪 ｜ 来源与规格 ｜ 动作**。
   同样的内容压进一条 150px 的记录，扫一列就能读完。

4. **备注从「卡里的一个灰文本框」升成「行里的主位」。**
   它是签名元素，下一节单说。

## 3. 视觉签名：摘录带（跟着文字长度走的荧光带）

**只花力气的地方是摘录那一列**，其余保持产品现有的安静卡片风。

备注不再是一个 34px 的灰文本框，而是**一条跟着文字长度走的强调色荧光带**：

```text
▎「便利店雨街的霓虹底子，要的那种湿漉漉的反射」
 ↑ 左边一道 3px 强调色竖条，带子多宽就是这条备注有多长
```

为什么是它：

- **这一页最该一眼看到的事，就是「这条收藏是干什么用的」。**
  荧光带把十几条备注变成**一列可以扫的带子**；改造前要滚过十几张卡、
  逐个点开十几个灰框才拼得出来。
- 带的宽度跟着文字走 —— 这不是装饰，是**排版手法**：它说明「这一条有一句理由，
  理由在这」。
- 没写备注的那几行留**一条虚线空位**（`＋ 写备注`）。空着也是一条信息：
  这条还没被你认领。稿子里 15 条有 6 条是空的（真机上的收藏基本没写备注）。

## 4. 几个设计决定（含取舍）

- **不换字体。** 产品 §3.4.1 规定令牌是唯一取值出处；这一版的性格来自**结构与信息顺序**，
  不来自装饰字体（与 `design/settings-layout` 同一判断）。
- **令牌照抄产品的浅色档。** 稿子直接引产品的 `web/styles/tokens.css` / `ui.css` /
  `sidebar.css`（只读引用），颜色、圆角、按钮、芯片、徽标与产品里现在跑的完全是同一套。
  真落地时不抄，直接用那三份。
- **徽标仍是产品那枚。** 「本机 / 云端」用的是 `badge-state.js` 那一份
  （`.srcbadge.local` / `.cloud` / `.both`），这里只把它从卡里的 meta 行**挪到独立一列** ——
  一列竖着的绿/灰小标签，扫一眼就知道哪几条的字节还在本机。
- **破坏性操作收进 `⋯`。** 常驻只留 `复用` / `下载` 两颗次要按钮；
  「移出收藏」进 `⋯` 菜单。破坏性动作不该是页面上最显眼的那颗按钮。
  （真品里它还要走 `Confirm.ask` 二次确认，稿子里只画位置。）
- **摘录行 vs 缩略墙：两档，不是两页。**
  同一批 15 条、1440 宽下**实测**（`shots/` 里的稿子量出来的，不是估的）：

  | | 一条多高 | 15 条总共多高 | 首屏能看到几条 |
  | --- | --- | --- | --- |
  | 现状 · 卡片网格 | 249px（4 列） | 1062px | 12 |
  | **新版 · 缩略墙** | 180px（4 列） | **751px（矮 29%）** | 16 |
  | **新版 · 摘录行** | 151px（1 列） | 2266px | **5** |

  - **缩略墙**：比现状那张卡矮约 29%，而且**多显示了备注** ——
    现状每张卡里 34px 的灰文本框 + 三个常驻按钮占掉约 70px，新墙里这两样都没了。
  - **摘录行**：一条一列，**它比现状高，也比现状首屏少 7 条** ——
    这是要认的代价：一列一列换来的是「每条都能读」。
  - 换句话说：**密的那一档是缩略墙，读的那一档是摘录行。**
    默认档选了读的那一档（这一页是「我挑过的东西」，不是「浏览素材」）。
- **列表这一档的帧统一裁成 16:9。** 这一批真机收藏**大多是 9:16 的竖图**
  （缩略图实测 288×512），塞进横框要么留大片黑边、要么把上下切掉。
  产品今天在卡片里是**完整显示不裁** —— 新版在**列表这一档**裁，
  灯箱与详情那一层仍给全图。这是要认的取舍：
  **列表里那一格的作用是「认得出是哪一条」，看画面是灯箱的事。**
- **空态分四种说**（搜索无果 / 筛选为空 / AI 挑完没有 / 真的还没有收藏），
  沿用产品现有口径（`web/pages/favorites.js` 里那四句）——
  一律写成「还没有收藏」时，用户会以为自己把收藏弄丢了。
- **页头那枚 `新版 / 现状` 开关是稿子自己的对照工具，真品里没有。**
  真品对应的是设置页「列表分页」那一栏里的默认摆法（`dir_fav_view`）。

### 4.1 明确没做的

- 没改任何产品代码（这一稿是纯静态稿）。
- 没**单独设计**夜间版 —— 夜间档是同一份稿子切 `data-theme="dark"` 自动派生出来的。
- 没做「按用途分组」（收藏页没有分组这个数据维度）。
- 没做排序（收藏只有 `ts` 一个可靠的时间字段，产品今天也没有排序）。
- 没做多选与批量操作（产品今天的收藏页也没有）。

**取值上的坑（落地时要先解决）**：

- **「本机 / 云端」今天只有逐条的一个读法**（`AssetLocal.stateOf(it)`，徽标走
  `badge-state.js`）。页头要的是**汇总**（本机几条 / 云端几条）。
  这个聚合必须收进公共层（例如 `AssetLocal.summaryOf(list)`），
  **不许在页面里现算** —— 否则徽标与概览条会各说各话，那正是产品 §3.4.4 要避免的。
- **备注的写入口不变**（仍是 `Fav.setNote(key, note, {silent:true})`），
  只是位置与形状变了：原来在卡里的 `<textarea>`，现在在行里的可编辑荧光带。
- **档位名是一份**（`window.VIEW_MODES`，全站三页共用）。
  收藏要「摘录行 / 缩略墙」这两个名字，就是给那份表加两档 ——
  **不许在收藏页另抄一份**（§3.4.4）。

## 6. 数据从哪来

| 稿子里的东西 | 真机出处 |
| --- | --- |
| 15 条收藏（12 本机 + 3 云端） | `.data/local-assets/index.json`（本机资产账，362 条）、`.data/sparkcine_gallery.json`（平台画廊，120 条）、`.data/fav_items.json`（真收藏，1 条） |
| 每条的名字 / 大小 / 格式 / 日期 / 类型 | 同上（逐字取真值） |
| 每条的缩略图 | `.data/cache/thumbs/`（本机那批取真缩略图；云端那批经本机代理 `/asset/<id>` 取真字节，再用 ffmpeg 压成小图） |
| 「本机 / 云端」归属 | 本机资产账里有的 = 本机；平台上收藏但本机没有字节的 = 云端（真机那 1 条真收藏就是云端） |
| 应用外壳（侧栏、账户余额） | **真机页面上取下来的结构**（`design/favorites-layout/sidebar.html`，由 `shoot-real.cjs` 从真机 `<div class="sidebar">` 原样取出） |

取数脚本：`node design/favorites-layout/dump-data.cjs` → `data.js` + `assets/`
（只读真机 `.data/`，**一个字节都没写回真机**）。

⚠ **备注文案是稿子专用的**（真机那条收藏的备注是空的）：写的是「这条收藏是干什么用的」，
单放在 `data.js` 的 `FAV_NOTES` 里，文件里标得清清楚楚。
每种类型里六成写备注、四成留空 —— 留空的那几行就是虚线空位那一档。
