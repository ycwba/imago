# 我的收藏 —— 卡片同形 + 详情就地展开（设计稿）

> ✅ **这一稿已经落到产品代码里了**（2026-10-25）：
> - 去掉的是**「文件」那一颗筛选芯片**（芯片写「其它」、卡面写「文件」，同屏两种叫法）：
>   类型档只剩 全部 / 图片 / 视频 / 音频。
>   **本地上传的入口没有去掉** —— 「上传本地文件」按钮、拖文件进窗口、
>   `Fav.addLocalFile` / `typeOfName` 都在（用户已明确纠正过一次：去掉的是芯片，不是入口；
>   上传进来的图片 / 视频 / 音频按扩展名分到对应那一档）。
> - 增加了**多选**（公共件 `Wb.multi` + 公共 `.bulkbar`）：已选几项 / 全选 / 取消选择 /
>   批量下载 / **移出收藏** / 退出多选；卡上的勾选框是资产库那一件（`.pick`）。
> - **筛选补上了平台▾ + 时间▾**（与资产库一样的两种）：原来只有「类型」一个维度。
> - 视图只留**两档**（列表 / 紧凑），与资产库同一份 `VIEW_MODES`；列表档是**一行一条**。
> - **不显示本机 / 云端 / 只剩外链**：卡上的 `.srcbadge` 拿掉了，概览条没做。
> - 详情**就地展开**（公共件 `.exp`）：清单档 = 那张卡自己长高；紧凑档 = 行下面一条整行宽的带子
>   + 一根量出来的连线（网格档显式分行）。
> - 备注升到主位（标题上面，带子形状，就地可编辑）；列表档的图**裁成 16:9**（竖图不裁就是两条黑边）。
> - **卡面上有「移出收藏」**（用户实机看过之后要求的：破坏性动作收进展开区这一条，
>   在这一页不成立 —— 要看得见才点得到）。它仍走 `Confirm.ask`。
> - **多选条上的那颗「取消收藏」**：这一页的每一条都已经在收藏里，所以批量条上只有
>   「取消收藏」（= 移出收藏，走公共件那一份收藏动作）；
>   不摆一颗永远按不动的「收藏」。资产库与工作台右栏那两处则两颗都有。
>
> 落地的公共件在 `web/styles/ui.css` 与 `web/ui/workbench.js`，与资产库那一稿**共用同一份**。
>
> 这一稿**先出的稿子，后来落了产品代码**：`web/` `server/` `tools/` 都按这一稿改了
> （页面与公共件那一部分）。这一稿回答两个问题：
> **① 各种收藏（图片 / 视频 / 音频 / 文件 / 平台的 / 本地上传的 / 只剩外链的）怎么和普通那一张长得一样宽、一样形**
> **② 点开一条的详情怎么在原界面里就地展开，不另起一层**

> 这一稿是**浅色稿**，但**夜间版不用另外设计**：产品令牌里的深色档一换主题就成立
> （见 `shots/06-深色派生-1440.png`）。
>
> **内容是真机取出来的**：前 15 条的名字 / 大小 / 格式 / 日期 / 类型 / 缩略图都取自这台机器
> （取数过程见 `design/favorites-layout/DESIGN.md` §6）；后 2 条是**稿子专用的演示状态**

## 3. 改造前的三个问题（都指到真品）

### ① 收藏页今天**没有详情展开** —— 想看细节只能开灯箱

真品的卡（`tools/vue-templates/favorites.html:18-34`）是：缩略图 / 标题 / 来源行 /
备注框 / 三颗按钮。**没有「详情」**。
点缩略图与点标题都是 `openLb(it)` —— **灯箱是另起一层**（遮罩 + 全屏舞台）。
后果是：灯箱里那一栏只能给很少的字（`web/pages/favorites.js:447-459` 的 `detailCfg`
只给来源 / 类型 / 格式 / 大小 / 时长 / 备注 / 收藏时间），**代价、任务号、资产号、提示词全文都没有**；
而灯箱一关，页面又回到那张只有一行来源字的卡。

### ② 破坏性动作常驻，而且是红框红字

真品每张卡三颗按钮：**复用 / 下载 / 移出收藏**，最后一颗是 `.ghost.danger`（红框红字）。
50 条收藏 = 150 颗按钮，**其中 50 颗红框**。破坏性操作不该是页面上最显眼的那颗按钮。
（上一稿已经说过这句：破坏性动作收进 `⋯`；这一稿是同一个结论的另一条路 —— **收进展开区**。）

### ③ 这一页的状态是「字节还在不在」，而它今天散在三个地方

- 每张卡 meta 行里一枚小徽标（`.srcbadge`）—— 要逐张点才知道哪几条只剩外链；
- 页面上没有概览 ——「15 条里有 3 条只剩外链」这件事，用户要点开每一条才知道；
- 今天的**卡片形状**跟着内容变：有图的是图，没图的（音频 / 视频 / 文件）是一块空白；
  「只剩外链」的那张则是**一张裂图**（外链过期了）。

## 4. 新的做法

### 4.1 一张卡就一张卡：同宽同形

**骨骸是产品公共那一副竖排卡壳**（`.card` + `.card-shell-media/body/actions`），
状态只换**媒体格里的内容**与**多出来的一行**：

| 这一条 | 媒体格里是 | 字里多一行 |
| --- | --- | --- |
| 图片 / 视频（有画面） | 画面 | —— |
| 音频 | 状态牌「音频 / OGG · 96s」 | —— |
| 视频（没有缩略图） | 状态牌「视频 / MP4 · 15s」 | —— |
| 文件（本地上传的 txt） | 状态牌「文件 / TXT」 | —— |
| **只剩外链** | 状态牌「只剩外链 / 外链已过期」（琥珀） | —— |
| 平台的（云端） | 画面 | —— |

于是**一屏 17 张卡是同一种东西**：左边一格、右边一列字。
**状态牌**用的是公共件 `.plate` —— 形状与资产库的「生成失败」那一块一模一样，
底色跟状态走（琥珀=要注意，中性=只是没有画面，紫色渐变=音频，与产品 `.timg.audio` 同一副骨架）。

**徽标不另造一档**：「只剩外链」在徽标那一层仍然是**云端**（它确实只在平台上），
坏在哪由媒体格里的琥珀牌与展开后的诊断块说。

### 4.2 详情就地展开（两档，同一份公共件）

- **清单档**：点「详情」→ **那张卡自己变高**（字列从摘要换成详情），下面几行顺移，别的卡不动。
- **网格档 / 紧凑档**：格子长高会把**同一行**别的格子底下留出空洞 —— 网格最怕这种。
  所以**那一行保持原样**，展开的内容接在**它那一行的下面**，成一条**整行宽的带子**，
  一根**量出来的**连线从带子上沿指回那个格子。

展开区里是什么：**这一条的账**（字节在哪 / 来源 / 外链 / 类型 / 格式 / 大小 / 时长 /
收藏时间 / 任务号 / 资产号）+ **完整提示词** + **备注** + **动作**。

### 4.3 移出收藏：卡面上就有一颗（这一条按用户的要求改了）

卡面上是 **复用 / 下载 / 详情 / 移出收藏** 四颗。
「移出收藏」**回到卡面上**：这一稿原先把它收进展开区（理由是「破坏性动作不该是页面上
最显眼的那颗按钮」），但用户实机看过之后明确要它在卡上 —— **看得见、点得到**，
不用先猜「这条要展开才找得到」。它仍然走 `Confirm.ask`（红框 + 二次确认），
展开区底部那一颗是同一个动作的另一个入口，不是第二套实现。
「存回本机」「回源换新地址」还是展开区里的动作：**用得上才点**，不用常驻。

### 4.4 备注是主位（上一稿的结论，这里接着用）

产品自己的 AI 挑素材规则写着（`web/pages/favorites.js:414`）：

> 优先级：备注（备注写的是用途）> 名称/描述 > 类型。

所以**备注在卡上排在标题上面**，做成一条**带子**（左边一道 3px 强调色竖条 + 文字），
**就地可编辑**（敲字它就长高；没写备注的留一条虚线空位「＋ 写备注」）。
写入口仍是 `Fav.setNote(key, note, { silent: true })` 一个。

### 4.5 概览条：从两段扩成三段

上一稿定了「本机 / 云端」的比例条。这一稿加第三段 —— **只剩外链**：
那一类既不在本机、也不能直接看，是收藏页最该被看见的一档（它现在是一张裂图）。

```
● 本机 13   ● 云端 3   ● 只剩外链 1     [本机▓▓▓▓▓▓▓▓▓▓░░░░云端▓░只]
```

**汇总值不许在页面里现算**（上一稿的坑）：徽标是 `AssetLocal.stateOf(it)` 逐条读的，
概览条要的是汇总 —— 这个聚合必须收进公共层（例如 `AssetLocal.summaryOf(list)`），
否则徽标与概览条会各说各话。

### 4.6 网格里的图裁成 16:9

这一批收藏**大多是 9:16 的竖图**（真机实测 288×512）。产品今天在卡片里是
`object-fit: contain` 完整显示 —— 塞进 96px 高的横框，两边就是大片黑边，
**一屏看过去全是黑框**。这一稿把那一格裁成 16:9 铺满（`cover`）。

**要认的取舍**：那一格的作用是「认得出是哪一条」，**看整张图是灯箱的事**。
（上一稿已经量过同一个取舍，结论一样。）

## 6. 落到产品里要做的事

1. **公共卡片件先落地**（两页共用，见 §2.1）：
   `web/styles/ui.css` 加 `.plate` / `.exp` / `.led` / `.why` / `.diag` / `.exp-acts` /
   `.band` / `.sec-hd`；`web/ui/workbench.js` 加 `Wb.expand` / `Wb.close` / `Wb.closeAll` / `Wb.anchor`。
   **资产库那一页与收藏页这一页一起改**，别只改一页 —— 两页各写一套，两边早晚会长歪。
2. **收藏页的模板**（`tools/vue-templates/favorites.html`）：
   - 卡面上加一颗「详情」按钮（`data-kit-toggle`）；
   - 卡里加展开区（`.exp` / `.exp-in` / `.exp-body`）；
   - 备注从 `<textarea rows="2">` 改成**带子里的 textarea**（`.fv-note`）；
   - **「移出收藏」从卡面那一排移进展开区**；
   - 改完 `npm run build` 重新预编译（生成物别手改）。
3. **网格档要显式分行**：真品现在是 `auto-fill` 自动分列（`spa-pages.css:13`）。
   展开要插在**它那一行的下面**，就必须**先分好组**：
   JS 按容器宽度算出一行几格 → 显式分组 → 展开插在行下面 → 量出连线位置。
   清单档不用（一张卡一行）。

## 8. 顺手发现的真品问题（不在本稿范围，只是记一笔）

### ① 「文件」这一档：值是 `文件`，芯片上写的是「其它」

`web/pages/favorites.js:14`：

```js
const TYPES = [['all','全部'], ['图片','图片'], ['视频','视频'], ['音频','音频'], ['文件','其它']];
```

**值与显示是分开的**：芯片上写「其它」，内部值是 `文件`；判据按 `it.type` 字面相等
（只有「音频」那一档用 `isAudioType` 兼容「音乐」）。

后果是**同一个屏幕上两种叫法**：筛选芯片写「其它」，卡面 meta 行写的是 `it.type`（「文件」）。
这一稿**照抄真品**（芯片显示「其它」、卡面写「文件」），让这处不一致在稿子里看得见。

顺带记下同一个概念的第三种写法：本机资产清点那边用的是「其它」
（`server/local-assets-store.js:563` 的 `usageKindOf`），而**资产库的筛选根本没有这一档**
（只有 全部 / 图片 / 视频 / 音频）。**三处三个写法**，改的时候要一起看。

### ② 「文件」这一档 today 只可能装着「本地上传的文件」

资产库的条目类型只有图片 / 视频 / 音频三档（平台 `kind` + 本机资产账的 `MEDIA_KIND_ZH`），
`Fav.fromEntry` 沿用 `e.type` → 从资产库收藏过来的东西**永远不会**落进这一档。
本地上传那条按**文件名后缀**判（`web/domain/fav.js:81-83`），其余后缀一律「文件」。

**字节在浏览器的 IndexedDB**（`fav_db/files` 表），不在本机资产库 ——
所以「存回本机」对这一批没意义（真品那句话已经写明「本地上传的那一批不算」）。

**这一稿给这一档画了状态牌**（`文件 / TXT`），因为它同样「没有画面」；
真品今天那一格是**空白**。### ③ 全项目没有一处声明 `color-scheme`

`web/styles/` 与 `shell.html` 里都搜不到 `color-scheme`。
UA 样式用 `fieldtext`，不看 `--txt` —— **深色档里的 `select` 是「深底 + 黑字」**。

这一稿里是这么绕过去的（`demo.css`）：

```css
html[data-theme="dark"] { color-scheme: dark; }
```

建议在 `tokens.css` 的深色档补这一句（一行，全站受益）。**本稿没有改 `tokens.css`。**

### ④ `color: var(--txt)` 在六个页面根类里各写了一遍

`shell.html` 已经写死了 `html, body { … color: var(--txt); }`，
但 `spa-assets.css:9`、`spa-chars.css:17`、`spa-director.css:7`、`spa-settings.css:21`、
`spa-studio.css:6`、`spa-usage.css:8` 又各写了一遍同一句 ——
正是 AGENTS §3.4.1 说的「同一个数的第二份拷贝，两边会漂开」。

**这一稿的 `body.demo-fv` 照着外壳那两行写**（不写的话，深色档里标题就是「深底 + 黑字」）。
**落地时更该做的是反过来**：把那六处删掉，只留 `shell.html` 那一处。
