## 1. 改造前的三个重复（都指到真品）

### ① 同一批 Skill 在一屏里列了两遍

一级菜单 `skillSlots` 已经按 contract 说了「每一处现在用的是哪一份」；紧跟着下面又是一份
**全量清单** `skillFiltered`（还配了 5 枚筛选芯片）。两处数据同源（都来自 `/skills` 的清单），
所以这不是「两个功能」，是**同一个东西画了两遍**。

### ② 12 个「使用地方」平铺，没按「在哪儿用」分组

`TextAI.PROMPTS` 里本来就分了三组（`gen` 通用润色 / `charpic` 素材库·出图 / `voice` 素材库·声音），
但 `skillSlots` 只从每条上取 `label` 与 `used`，**把分组信息丢掉了**。结果 12 行长得一样平铺，
用户看不出「工作台那五条是一类、导演台那四条是另一类」。

### ③ 变量表绑在「选中的某一份 Skill」上，但它其实是场景级的东西

- 说明的来源是**场景**：`SKILL_VARS` 按 contract 声明。
- 界面上却按**这一份**扫：扫正文找占位符，再回头对 `SKILL_VARS` 取说明。

结果是：想回答「这一步要喂哪些项目上下文」，必须先在清单里点中一份 Skill 才看得到。

### 附带：空档与冲突没有正经的说法

- 没有启用的 Skill 时，界面只能说「内置默认」，用户不知道那是什么、从哪来。
- 「两份都启用了」（`skills-store.js` 的 `conflict`）今天只是一枚 tag 混在行尾。

## 2. 新的信息架构（已落地）

```text
┌ 场景轨（左 292px）────────────┐ ┌ 场景详情（右）──────────────────────────────┐
│ ⌕ 搜场景 / Skill 名 / id       │ │  视频提示词润色            [添加新 Skill]    │
│                     [全部 14] │ │  生成工作台「视频」那一栏的「AI 润色」…       │
│                               │ │  [polish.video] [正在生效：视频提示词]       │
│ AI 助手            1           │ │ ─────────────────────────────────────────── │
│   ◌ AI 助手      11 份已启用   │ │  这一步会拿到什么                          │
│                               │ │  （没有变量时：这一步不需要项目上下文…）     │
│ 生成工作台          5           │ │ ─────────────────────────────────────────── │
│   ■ 视频提示词润色      内置   │ │  这个场景的 Skill      同一时刻只有一份生效   │
│   ■ 图片提示词润色      内置   │ │  ▎视频提示词 video-prompt · v1              │
│   ■ 配音稿润色          内置   │ │   正在生效 内置(只读) 已启用 …               │
│   ▫ 图片片段拆分        空档   │ │   [停用][查看正文]（内置只有这两颗）         │
│   ▣ 再改一版            冲突   │ │  Skill 只补充写法，输出格式由机器契约管…    │
│                               │ │                                                │
│ 导演台              4         │ │                                                │
│ 素材库              2         │ │                                                │
└───────────────────────────────┘ └───────────────────────────────────────────────┘
```

三条结构改动：

1. **一级菜单 = 使用场景**。按「在哪儿用」分四组：AI 助手 / 生成工作台 / 导演台 / 素材库。
   分组不是新造的数据 —— `PROMPTS` 已经在分，只是以前被丢掉了；现在写在自己的
   `SKILL_SCENES` / `SKILL_SCENE_GROUPS` 里（场景名与「用在哪」仍然沿用 `PROMPTS`，不抄第二份）。
2. **点一个场景 → 右边给这个场景的三件事**：① 这一步会拿到什么（变量表，**场景级**）
   ② 这个场景的 Skill（谁在生效、冲突没有、怎么接管）③ 边界说明。
   「场景内的相关 Skill」不再散在全量清单里 —— 它就住在这个场景下面。
3. **全量清单降级**：保留能力，但退到「全部 Skill N」这一个二级入口，不再与一级菜单并排重复。

## 3. 视觉签名：工序轨 + 槽位灯

**唯一花力气的地方是左栏那一列灯**，其余保持产品现有的安静卡片风。

为什么是灯：contract 就是一个**插槽**，服务端硬约束「同一时刻只能有一份 Skill 占着」
（`skills-store.js` 的 `setEnabled`）。所以这一页最该一眼看到的事就是「这个槽被谁占着」。

| 灯 | 含义 |
| --- | --- |
| 紫实心 | 我的一份在用 |
| 灰实心 | 内置的在用 |
| 虚线空心 | 空档 —— 现在用的是内置默认正文 |
| 红框 | 两份都启用了（冲突，得停一份） |
| 圆点虚线 | AI 助手 —— 它不占固定位，是按触发词挑 |

原来是每行挂 2~3 枚 tag（「内置·视频提示词」+「contract 冲突」），12 行下来全是标签，
状态反而扫不出来。灯把状态压成**一列**，标签留给右栏详情区去说清楚。

## 4. 几个设计决定（含取舍）

- **不换字体。** 产品 §3.4 规定令牌是唯一取值出处、这一页跟别的设置卡共用一套排版；
  这一版的性格来自**结构与密度**，不来自装饰字体。
- **变量表放在场景详情最上面，而不是跟着 Skill 走。**
  变量的主人是场景（`SKILL_VARS` 按 contract 声明），换一份写法不改喂料方式；
  先说「这一步要什么料」，再说「谁在写」，顺序才对。
- **多露出一条今天看不见的坑。**
  生效中的那份正文如果用了场景说明里没登记的占位符（稿子里 `我的角色图` 的 `{mood}`），
  界面要说一句：「程序不会填这个位置，AI 会当成要自己补的空位」。
- **助手单独一行、不给灯。** 它的语义是「按需挑，最多两份」，不是「一个位置一份」。
  它那一行只给「N 份已启用」。
- **空档要有话说。** 「空档 · 用内置默认正文」比一枚「内置默认」tag 多说清了两件事：
  现在跑的是谁、它住在哪。

### 4.1 落地时追加的两条（2026-10-24）

- **「复制为我的 Skill」与「导出」两条整族删除。**
  前端函数（`copySkillToMine` / `cloneSkillText` / `exportSkill`）、
  `web/ui/skills.js` 的 `exportOne`、服务端 `/skills/:id/export` 路由，一并没了。
  内置 Skill 只读；要改就自己写一份（下面那条）。
- **「导入本场景的 Skill」→「添加新 Skill」，在浏览器里写。**
  点开就是一张表单（id / 名字 / 它管什么 / 触发词 / 页面 / 正文），frontmatter 由表单生成，
  正文自己敲，落盘走 `POST /skills/install`（新建）或 `/skills/:id/update`（改）。
  contract 预填当前场景并只读 —— **一份 Skill 永远属于一个 contract**，助手那一项不占固定位，
  所以从那儿进不来。

## 6. 这一稿没做的事

- 没改 Skill 的加载与匹配逻辑（`web/ui/skills.js` 的 `match` / `activeFor` / `prime` 一行没动）。
- 没动服务端那套 contract 互斥与启用状态机（只改了报错文案）。
- 没**单独设计**夜间版 —— 夜间档是同一份稿子切 `data-theme="dark"` 自动派生出来的。
- 没做「导入向导」与「正文编辑器」以外的编辑能力（比如多文件管理、references 的增删）。
