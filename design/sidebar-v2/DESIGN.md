## 3. 这一稿的核心：窄形态**认得出**

56px 里放得下两个字（11.5px × 2 ≈ 23px），所以**短标签常驻压在图标下面**：

| 页面 | 窄形态下的短标签 |
| --- | --- |
| 导演台 | 导演 |
| 素材库 | 素材 |
| 生成工作台 | 生成 |
| 我的收藏 | 收藏 |
| 资产库 | 资产 |
| 用量与余额 | 用量 |

这一条把「收起就认不出」这件事**从根上解决掉了**：

- 悬停**不再**是唯一的信息来源 —— 它只负责**补全全名**（窄形态下悬停「生成」才告诉你它叫「生成工作台」）。
- 也就是说：**功能在，收起也在**，不用挨个点一遍试。

## 4. 几个设计决定（含取舍）

- **只有两个形态，不做第三档。** 上一稿那套「轨 / 列 / 架」是过度设计：中间那一档
  （有名字但没余额明细）在真机上没有真实使用场景，加进来只是多一份要维护的分支。
  这一稿只留「读得全」和「让得开」两个真的会被用的状态。
- **导航行不带任何数值。** 上一稿每行右边那个「4 场 / 2 / 4 / 1 / 362 / 287 次」
  看着热闹，但它是**另一份会漂开的数据**（散在各页逻辑里），而且它把导航行变成了一个
  「状态表」，抢了「这里是什么地方」这件事的分量。去掉之后导航行回到它该干的事：
  只回答「有哪些地方、我现在在哪」。
- **当前项在两个形态里换一套语言。**
  满形态：淡紫底 + 紫字 + 贴着内边缘的 3px 紫条。
  窄形态：**实心紫方块** + 白图标 + 紫标签。
  —— 56px 里再没有比一块实心色块更认得出的「你在哪」。
- **收 / 展的开关是左上角那块品牌砖**（像原来那样，点它收展）——
  侧栏里**没有第二样收展标识**：不画箭头、不画拉片。品牌块是品牌，不是控件，
  所以它做成「点它收展的那一块」，而不是另加一颗控件。
- **两个形态里是同一块砖**（30px、离左边 13px、同一行高）：手指不用记位置，
  收展开时侧栏里也没有任何东西上下跳。变的只有两件事：导航项从「图标在左、名字在右」
  变成「图标在上、名字在下」，余额那块从整张卡变成压缩版。
- **两个形态共用同一套垂直节奏**：顶行 58 / 导航行 42 / 底部行 36。

  | | 满 232px | 窄 56px |
  | --- | --- | --- |
  | 顶行高 | 58 | 58 |
  | 导航行高 | 42 | 42 |
  | 底部行高 | 36 | 36 |
  | 品牌砖 | 30×30 · 离左边 13px | 30×30 · 离左边 13px（正中） |

- **窄形态的「此刻」区是同一份内容的压缩版。**
  余额：家数（`◈ 3`）+ **每家一个状态点** —— 实心紫 = 这一家取到了，
  空心红 = 这一家取不到（悬停能读到是哪一家、为什么）。
  56px 里放不下三个平台名，但放得下三个「各家怎么样了」——
  这比一个孤零零的数字有用得多。
  落盘进度：一条 3px 的进度条 + 旁边的 `3/5`（和满形态同一条，窄了而已）。
- **落盘进度不再贴侧栏最底边。** 上一稿把它做成最底边一道 2px 的线 ——
  那是「一个记号」，不是「一件东西」。这一稿它在两个形态里都在「此刻」区里，
  满形态在卡里、窄形态在压缩块里，位置对应、样子一致。
- **「此刻」卡是这一形态里唯一一块「信息」。** 别的都是入口，只有它会自己变
  （余额在变、落盘进度在动）。所以它被收成**一张卡**，而不是三张带描边的小卡加一块进度条。
  余额一行是「名字 + 金额」，下一行是「冻结 + 单位」；**取不到的那家不藏** ——
  原因直接摆到行面上（红色、单行省略），全文在 title 里。
- **落盘进度在窄形态退成侧栏最底边一道 2px 的线。** 收起时也要看得见「机器正在忙着往本机存东西」，
  但不能占地方。
- **竖向分配没动。** 余额区仍钉在栏底、导航仍吃剩余高度 —— 真机现有的「导航优先」规则
  （AGENTS §11.1），动它是另一轮重排，不在这一稿的范围里。
- **不换字体。** 产品 §3.4.1 规定令牌是唯一取值出处；这一版的性格来自**结构与密度**，
  不来自装饰字体。图标几何直接用产品的 `ICONS`。
- **令牌照抄产品的浅色档**，值逐字一致（`demo.css` 顶部那一段）。深色档照抄
  `tokens.css` 的 `html[data-theme="dark"]` 那一段 —— 所以夜间版是派生结果，不是另设计的一版。

### 4.1 明确没做的

- 没改任何产品代码（这一稿是纯静态稿）。
- 没**单独设计**夜间版 —— 夜间档是同一份稿子切 `data-theme="dark"` 自动派生出来的。
- 没做**拖拽**改宽度 —— 两个形态是按钮切的，拖拽要处理边界、窄窗浮层与内容区让位。
- 没动窄窗（≤1100px）那条「展开 = 浮层盖在内容上」的规则。
- 没动页面的路由、页面池、主题切换、余额的取数逻辑 —— 那些一行没动。
- 没有把「最近使用」之类的功能塞进左栏。
- 没做「悬停飞出整份菜单」那一套 —— 窄形态已经认得出了，不需要再飞一块浮层。

这一稿**已经落到真品**（`web/` 改了，判据也重写了）。下面是当时的改动清单 ——
文档不许说谎，落地后改了哪儿就记在这儿。

| 文件 | 改了什么 |
| --- | --- |
| `web/styles/tokens.css` | 新增两枚宽度令牌（`--sbw:56` / `--sbw-full:232`）；令牌是唯一取值出处 |
| `web/styles/sidebar.css` | 重写：两个形态的宽度、导航项的两种摆法（横排 ↔ 竖排）、「此刻」卡、窄形态的压缩版与状态点、`.bal-exp` 那几条高度分配 |
| `web/ui/sidebar.js` | ① 品牌砖当收/展开关（**没有另加收展标识**）；② 画两字短标签（`.sh`）；③ 窄形态的悬停名牌仍念全名；④ 余额卡收成两行；⑤ 窄形态的压缩块（家数 + 状态点 + 进度条）；⑥ 本机产物行挪到卡**底** |
| `web/core/routes.js` | 每一项加一个 `short` 字段（两字短标签）—— **放在路由表里**，侧栏不许另抄一份 |

| `web/features/chat.js`（悬浮球） | 窄窗浮层那处写死的 `200` 改成读 `--sbw-full` 令牌 —— 侧栏改宽它自己跟着改 |
| `tests/e2e/sidebar-balance.cjs` | 判据重写：两形态的宽度、品牌砖当开关、短标签常驻、状态点、进度条、卡两行、弹窗、高度扫描、来回切形态 |
| `tests/spa.cjs` | 首屏重量的登记跟着长（侧栏是首屏同步脚本，涨的 1.9KB 记在那一段里） |
| `AGENTS.md` | §3.4.3 补上侧栏的两个形态；§7 唯一实现清单补「侧栏导航项与文案 = 路由表那一行」；§11.1 整段改写 |

**落地时踩到的三处**（都已修，记在这儿免得下次再踩）：

- **`.bal-exp` 那几条高度分配不能丢。** 「就地展开」靠它把「唯一可缩可滚」那份额度只落在
  `.sb-bal-cards` 上（导航退回自然高）。重写样式时漏掉它，矮窗里展开会把导航挤掉。
- **品牌字要分行。** `.sb-name` / `.sb-sub` 是两个 `span`，不给 `.sb-brand-txt` 竖排
  它们会并成一行（「AI 创作工作台本地优先 · 数据留在本机」）。
- **窄形态里单位要藏。** 「家余额」三个字在 56px 里会竖排 —— `.sb-bal-sum .u` 那一档要 `display:none`。

**当时留下的两个坑**（下一个接手的要注意）：

- **窄形态的点击靶**：整项 42px 高、图标 26px，够手指点；**品牌砖在窄形态里是 30px**
  （两个形态同一块砖，见 §4）—— 比真机当年那个 36px 小一点，但它是整个侧栏最大的一块砖。
- **窄窗（≤1100px）那条「展开 = 浮层」的规则**没动：窄窗里点品牌砖，满形态那一栏
  浮在内容上、内容不让位（`--sbw` 仍是 56）。这一档与两个形态的关系**这一稿没重定**。
