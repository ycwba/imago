## 1. 改造前的四个问题（都指到真品）

### ① 只有两档宽度，中间那一档根本不存在

真机实测（1440×900）：收起 **67px**、展开 **201px**（`--sbw` 是 66 / 200，另加 1px 描边）。

66px 里只剩六个图标；200px 里塞得下名字，但余额卡只摆得下 **2 家**
（`BAL_CAPS` 那张表按窗口高切 3 / 2 / 1 / 0 张卡）。

于是「**想看清自己在哪**」和「**想给内容让位**」成了互斥的诉求，今天只能二选一：
要么认不出那六个图标，要么内容区白白少掉 200px。

### ② 唯一的开关，长得像一个 logo

真机代码里写得很直白（`web/ui/sidebar.js`）：

> `// 折叠 / 展开：只保留左上角 AI 头像方块（点它切换），原来的箭头按钮已移除`

那个方块是**品牌标志**，不是控件。用户要么不知道它能点，要么点下去才发现侧栏变了。
原来那枚箭头按钮是被拿掉的 —— 这一稿把它**加回来，而且给足形状**。

### ③ 收起之后，六个图标认不出来

产品自己的注释就写着这件事（`web/ui/sidebar.js`）：

> 「66px 的带子里 .lb 是 display:none，六个页面只剩图标……光看形状分不出哪个是哪个」
> 「『左栏收起后好多功能用不了』说的就是这个：**功能还在，但认不出来**」

现在的补救是悬停弹一个 `.sb-tip` 小浮标，**只有名字**，而且是个 tooltip —— 它回答了
「这一项叫什么」，没回答「这一页是干什么的」「现在什么状况」。

### ④ 展开时，余额区与导航抢高度

`BAL_CAPS` 按窗口高切 3 / 2 / 1 / 0 张卡；≤660px 时整区退成一行摘要；
展开态要是家数多，还得靠 `.bal-exp` 让「卡列表自己滚」才不至于把第 7 条导航顶出去。

一个 200px 宽的栏，要同时装：六条导航 + 两个分组标题 + 余额卡 + 落盘进度 + 设置 + 换背景 ——
每一件都只够看个大概。

## 3. 视觉签名：刻度拉片

**只花力气的地方是侧栏右边缘那一枚小拉片**，其余保持产品现有的安静卡片风。

```text
        ┌─┐  ← 架 256（最长那档）
   ╭────┤─┤
   │ ▬  │ │  ← 当前档：强调色，粗一档
   │ ▬▬ │ │  ← 列 196
   │ ▬▬▬│ │  ← 轨 60（最短那档）
   ╰────┴─╯
```

它是一枚**立着的梯子**：三根长短不一的横档，**长度就是那一档的宽度**。
当前那一档是强调色、也粗一档；点任一档直接跳过去，点当前那档在「架 ↔ 轨」之间翻。

为什么是这个形状、这个位置：

- **位置**：侧栏与内容的**边界上**，一半在里一半在外 —— 它是这条边界本身的一个把手，
  不用「找」。原来的开关藏在左上角那个 logo 后面，是这一稿要解决的第一件事。
- **形状**：三根长短不一的横档**把「有几档、每档多宽」画出来了**。
  用户看一眼就知道侧栏不是两态，而是三档。
- **它不是图标**：产品里「设置」用的那枚齿轮本身就像太阳，再加一枚图标只会更像装饰。
  横档是量出来的，不是画出来的。

配套的**预告卡**是轨态的补丁：轨态里没有名字，就让悬停**飞出一张卡**，
卡上有三行 —— 名字、这一页是干什么的、现在什么状况。

```text
╭───────────────────────────────╮
│ ✦                             │
│ 生成工作台                     │
│ 图片 · 视频 · 音频 · 文字       │
│ ─────────────────────────────  │
│ 4 个平台已接入密钥              │
╰───────────────────────────────╯
```

它跟现在那个 `.sb-tip` 的差别不是「好看一点」，是**答的题不一样**：
tooltip 只答「这一项叫什么」，预告卡答「这一页是干什么的、现在什么状况」。

## 4. 几个设计决定（含取舍）

- **为什么是三档，不是两档。** 真机的问题不是「收起 / 展开」两个不够用，是**中间那一档被砍掉了**：
  既要名字又要让位的诉求今天没有对应状态。三档把它补回来。
- **拉片为什么在边缘，不在左上角。** 边缘那个把手是**看得见的**，而 logo 那个方块
  是**长得像别的东西的**。收起/展开是这一栏上最高频的动作之一，不该需要「找」。
- **轨宽 60 而不是 56。** 60px 里：logo 30px 居中（中心在 30），图标列 22px 也居中（中心在 30），
  拉片 20px 骑在右边缘（50–70）—— logo 右边缘 45 与拉片左边缘 50 之间留 5px 的缝，
  两者不会挤成一团。**logo 与图标列同一条竖线**这条沿用真机已有的做法。
- **每一行右边那个数（值速记）。** 导演台 4 场、素材库 2、生成工作台 4、我的收藏 1、
  资产库 362、用量与余额 287 次 —— 眼睛从上往下扫一遍就知道这台机器什么状态。
  这个手法与 `design/settings-layout` 的「值速记轨」是同一套语言。
- **余额卡从三行收成两行。** 真机那张卡是「名字 / 可用 / 冻结」三行、每行带描边，
  加上标题行一共四行高；这一稿收成「名字 + 金额（右对齐）」「冻结 + 单位」两行，
  同样的高度里能多摆一家。**失败的那一家不藏**：原因直接摆到行面上（红色），全文在 title 里。
- **落盘进度在轨态退成侧栏最底边一道 3px 的进度条。** 收起时也要看得见「机器正在忙着往本机存东西」，
  但不能占地方。
- **不换字体。** 产品 §3.4.1 规定令牌是唯一取值出处；这一版的性格来自**结构与密度**，
  不来自装饰字体（与 `design/settings-layout` 同一判断）。图标几何直接用产品的 `ICONS`。
- **夜间版不是另设计的一版。** `demo.css` 里照抄了产品 `tokens.css` 的深色档覆盖，
  稿子右上角那颗钮切一下 `data-theme` 就换档 —— 同一份稿子、同一套结构、同一批令牌，
  只是语义色换成深色那一套（`shots/after-dark-*.png` 就是这么渲的）。
  **所以出稿只出浅色一份**：夜间档是派生结果，不是待办。
- **令牌照抄产品的浅色档**，值逐字一致（`demo.css` 顶部那一段）。真落地时不抄，
  直接用 `web/styles/tokens.css` 那一份。
- **竖向分配没动。** 余额区仍然钉在栏底、导航仍然吃剩余高度 —— 这是真机现有的「导航优先」规则
  （AGENTS §11.1），动它就是另一轮重排，不在这一稿的范围里。

### 4.1 明确没做的

- 没改任何产品代码（这一稿是纯静态稿）。
- 没**单独设计**夜间版 —— 夜间档是同一份稿子切 `data-theme="dark"` 自动派生出来的。
- 没动竖向分配（余额区仍钉底、导航仍吃剩余高度）。
- 没做**拖拽**改宽度 —— 三档够用了，拖拽要处理边界、窄窗浮层与内容区让位，是另一件事。
- 没动窄窗（≤1100px）那条「展开 = 浮层盖在内容上」的规则。
- 没碰页面的路由、页面池、主题切换、余额的取数逻辑 —— 那些一行没动。
- 没有把「最近使用」之类的功能塞进左栏。

## 5. 落到真品要改哪几处（**这一稿没做**）

| 文件 | 要改什么 |
| --- | --- |
| `web/styles/tokens.css` | 新增几枚尺寸令牌：`--sbw-rail:60` / `--sbw-column:196` / `--sbw-shelf:256`、`--sb-peek-w`、`--sb-ic`（令牌是唯一取值出处） |
| `web/styles/sidebar.css` | 三档宽度（替掉 66 / 200 两档）、刻度拉片、预告卡、两行余额卡、轨态的进度条 |
| `web/ui/sidebar.js` | ① 档位状态从 1 bit 变 2 bit（`sb_open` 的 `'0'/'1'` 要兼容旧值）；② 画拉片并接三档切换；③ 预告卡的内容与定位（替掉 `.sb-tip` 那一小块）；④ 每一行的值速记 |
| `shell.html` | `#app` 的 `left/width` 现在**写死了 `200px`**（`html.sb-open:not(.sb-narrow) #app`），要改成跟着 `--sbw` 走 |
| `web/features/chat.js`（悬浮球） | 已经监听 `sb:toggle` 按新的 `--sbw` 避让 —— 宽度从 66/200 变成三档后要确认这一条仍然成立 |
| `tests/e2e/sidebar-balance.cjs` | 判据要重写：现在盯的是「这一档摆得下几张卡」，三档之后要盯「每档摆了什么」 |
| `AGENTS.md` | §3.4.3 补上侧栏的三种形状与刻度拉片；§7 唯一实现清单补「预告卡」 |

**取值上的坑（落地时要先解决）**：

- **值速记现在没有一个统一的取值接口。** 「导演台几场」「素材库几个角色」「收藏几条」
  「资产库几份」「本月几次调用」散在各页自己的逻辑里（`workspace.json` / `char_lib.json` /
  `fav_items.json` / `local-assets` 索引 / `ai_usage.json`）。
  落地前要先把这些收成**一份「每行一个当前值」的读取函数**，
  否则侧栏上会出现第二份会漂开的数据 —— 那正是产品 §3.4.4 要避免的。
- **档位是 2 bit，旧的 `sb_open` 是 1 bit。** 旧值 `'1'` 该落到哪一档要定死
  （这一稿的建议：`'1'` → 列，因为它离真机今天的样子最近）。
- **窄窗浮层那条规则与三档的交互**：≤1100px 时展开是浮层，盖在内容上。
  三档之后，「架」这一档在窄窗里要不要也允许浮出来，要一起定。
- **预告卡要挂在 body 上**（跟现在的 `.sb-tip` 一样用 `position:fixed`），
  因为 `.sidebar nav` 是 `overflow-x:hidden`，写在侧栏里会被裁掉。
