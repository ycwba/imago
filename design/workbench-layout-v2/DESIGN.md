## 0. 这一稿改了什么（第一稿的反馈）

第一稿把参数做成了**可折叠的配方轨**。反馈是：**不要那么多折叠项，生成的各种参数应该默认展开**。

所以这一稿：

- **取消了全部折叠** —— 页面上一个能折的东西都没有。参数永远摊开。
- **改了栏数**：两栏（写 | 看）→ **三栏（描述 | 参数 | 结果）**。

第二点是第一点的后果，不是顺手改的：
**参数一旦全展开，左栏就装不下了**（提示词 + 输入模式 + 素材槽 + 5 个型号参数 + 平台开关 + 费用，
一栏里就是一条 900px 长的表单，又回到「改一个参数要滚到底」）。
把「写提示词」和「调参数」拆成两条竖栏之后，**两条各自都装得下，一屏看完，都不用滚**。

三栏**自左向右就是操作顺序**：写 → 调 → 看。

| 栏 | 装什么 | 为什么不跟别的挤在一起 |
| --- | --- | --- |
| 描述 | 提示词 · 输入模式 · 参考素材 | 写提示词要一块整的、不被打断的地方 |
| 参数 | 型号参数 · 平台开关 · 费用 | 参数是**要一眼扫过去对比**的东西，摊开才看得了 |
| 结果 | 当前这一条（舞台）+ 历史墙 | 写完就要看，写和看分开放不互相挤 |

### 几处具体的处理

- **参数网格**：型号参数两列一排（标签在上、取值在下），一屏能看完 5 个。
  窄窗（≤1024）自动改成单列。
- **每节标题那一行右边带当前值**（`提示词 · 128 字` / `画面参数 · 4 项已设`）——
  不折叠了，但值依然一眼可见。
- **估价不只在提交坞**：参数栏末尾也有「费用」一节（4 张 × ¥0.15 = ¥0.60），
  提交坞上再给一个总计。两处是同一份口径，不是两份数据。
- **提交坞常驻**：估价、上一条回执、主按钮永远在屏幕底部 —— 这是「参数全展开」能成立的前提
  （否则左栏一长，提交按钮又沉底了）。
- **舞台**：暗底片窗 + 这一条的信息（状态 / 提示词 / 它是用什么配方做的 / 放大·下载·以此为参考）。

## 3. 与第一稿的差别（一张表）

| | 第一稿（配方轨） | 第二稿（三栏作业台） |
| --- | --- | --- |
| 栏数 | 两栏（写 \| 看） | **三栏（描述 \| 参数 \| 结果）** |
| 参数 | 6 组可折叠，收起只留摘要 | **全部摊开，永不折叠** |

| 舞台 | 上半区（片窗在上、信息在下） | 右上（片窗在左、信息在右） |

**留下的**：作业头、舞台、历史墙、提交坞、令牌纪律。
**去掉的**：折叠能力、配方轨的摘要行（收起的值不再需要写回标题行）。

## 5. 要拍板的事

1. **参数栏摊开后，字段多的型号会不会撑破？** 这一稿假设「一个型号的参数 ≤ 6 个」能一屏铺下。
   真的多起来（有些平台的 `shapeFields` 有十几个）怎么办 ——
   是**换行铺开**（栏变高）还是给这一栏单独留滚动？这条得看真实注册表才知道。
2. **描述栏要不要再宽一点？** 提示词是这一页的主要输入，320px 偏窄（第一稿在 300px 的轨里也一样）。
3. **结果栏的舞台要不要更大？** 现在片窗最高 240px，右边是信息栏。
   若「看」比「扫」重要，片窗可以再高，历史墙相应矮一屏。

## 6. 这一稿没解决的

- 三种类型的参数差异只做了版式示范；真实的字段集仍然由 `Capabilities` 声明驱动，这一稿没碰那一层。
- 多选、拖拽、拆分片段生成是**示意**（可点、样子对），不是真实现。
- 窄窗只做到 900px 以下单列，没有做手机形态。
