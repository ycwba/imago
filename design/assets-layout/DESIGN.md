## 1. 改造前的六个问题（都指到真品）

对照图：`shots/before-现状-资产库.png`（1440×900，侧栏收成 56px，与新稿同一个取景）。

### ① 四行筛选占掉第一屏，而且没有一处计数

真品从上到下是：标题 → `.frow`（大类型 + 搜索 + AI 检索）→ `.frow`（日期预设 + 日期区间 +
清除日期）→ `.frow`（API 平台）→ `.frow`（状态 + 多选 / 刷新 / 取消全部 / 视图）→ 才轮到卡片。

`web/styles/spa-assets.css:19` 的 `.filters` 是 `flex-direction: column`，四行叠着。
1440×900 里这四行 + 标题吃掉约 250px，用户第一屏看到的是控件，不是自己的产物。

更要紧的是**四行里一处计数都没有**：`web/pages/assets.js:1068` 给公共 `Wb.filterBar` 传的是
`cnt: false`，于是「大类型 / 图片 / 视频 / 音频」四颗芯片分不清哪一档有 64 条、哪一档只有 3 条；
平台芯片（`assets.js:847` 的 `Chips.render(fProvEl, uniq('providerName'), …)`）同理 ——
本机现在是 3 家，就画 3 颗；等接入 9 家，就是一行 9 颗芯片把整行撑开。

### ② 「状态」是筛选项，不是结构

正在跑的任务与排队中的任务，和已经入库的产物**混在同一批分页里**。
想知道「还有什么在跑」，得先切到「生成中」这一档芯片才看得见 —— 而这一档芯片本身没有计数，
切过去是空的还是有 2 条，全靠猜。

真品其实已经把状态算得很细了（`assets.js` 的 `ST_MAP`：已完成 / 生成中 / 排队中 / 失败 /
**结果未知**），而且对「结果未知」这一档格外谨慎（`assetCardHTML` 里的 `unc` 分支专门写了
「那次提交很可能已被平台受理、钱已经扣了」，`assetSig` 里也单独带了一位标记）。
**这么重要的一件事，却藏在第五颗芯片里。**

### ③ 缩略图 132×96 —— 资产库的主体价值是画面本身

`web/styles/spa-assets.css:82`：`.task .timg` 是 `var(--sz-tile)` × `var(--sz-thumb-h)`，
也就是 **132×96**。素材库里同样的图有整张卡那么大；资产库这一页的全部价值就是这些画面，
却挤在一条 96px 高的小方块里 —— 一眼看不出这张好不好，该不该用。

### ④ 每张卡六颗按钮

真品的卡上一排是：详情 / 预览 / 下载 / 收藏 / **删除本机文件** / 复用。
一屏 5 张卡 = 30 颗按钮，其中「删除本机文件」是红框红字（`ui.css` 的 `.ghost.danger`）——
**每一张卡都用最重的语气喊着一颗最危险的动作**。按钮多到互相干扰，真正常用的「下载」淹在里面。

### ⑤ 时间只是卡片右上角的一行字

日期印在卡的右上角（`assetCardHTML` 里的 `<span class="date">`），于是「今天做了哪些」「昨天做了哪些」
只能靠扫时间戳，拼不成结构。翻页又只能一页页往前翻（`tools/vue-templates/assets.html:55-60`
的 `.assets-pager`，计数也在页底 `assets.js:703` 的 `cntText`）。

### ⑥ 详情在卡内就地展开，把网格撑坏

「详情」那颗按钮把 `Wb.detail` 渲染进卡里的 `.cdet`（`assets.js` 的 `bindAssetCard` 里
`detBox.style.display = 'block'`）。一条产物的详情一展开，卡会长到几百像素，
把整片网格的几何撑坏 —— 素材库那边已经为这件事修过一轮（`spa-chars.css` 里给
`.grid.view-list .card.open .thumb` 专门钉高度），资产库这边还留着同一个毛病。

墙里每一格就是产品现在那张 `.task` 卡 —— 直接用 `ui.css` 里那一份
（`.task` > `.timg` + `.tmain` > `.meta1` / `.tprompt` / `.meta2`），
只把缩略图那一格换成 4:3 的大画面：

  <div class="tmain">

## 5. 详情：不另起一层，就地展开 —— 而且接在那张卡上

真品的展开方式：点「详情」→ 在卡里 `.cdet` 追加一个盒子 → 那一格长到几百像素，
整行被撑成一个高洞，别的格子旁边留一块空白。**这就是要改掉的地方。**

这一稿的展开方式：

- **不另起一层**。没有右侧抽屉、没有遮罩、没有浮层 —— 详情还是出现在这一格附近。
- **展开成一条整行宽的带子，插在它那一行的下面**：图在左，信息在右（两列参数一行放齐）。
- **和那张卡连着**：开着的那一格带强调色边框与**左侧强调条**；
  从这条强调条的下端，**一根同色的竖线顺着缝隙落下来，落到详情条的上沿**，
  落点正上方有一个**朝上的小三角**指着那张卡。
- 同一行里别的格子不动，下面的行整体下移一行；一次只开一条，再点一次收起。

「连着」这件事是靠量出来的，不是靠猜的：详情条画完以后，JS 量一下开着的那一格
与详情条的矩形，把竖线的横坐标与缝隙高度写进两个 CSS 变量
（`--as-anchor` / `--as-tether`），竖线与三角就正好落在那一格的左边缘上。
**换成第 2、第 3 列，线也跟着挪。**

为什么不是「整格展开成 1/-1」：那会让这一行只剩一格，两边留白；
为什么不是「卡内追加盒子」：那就是原来的毛病（一个高洞）。

**落地上有一处实现前提**：一行几格必须**先分好组**，展开才能插在它那一行的下面。
所以稿子里「一行几格」是 JS 按容器宽度算出来写进 `--as-cols` 的，行是显式分组的
（`demo-assets.js` 的 `columns()` 与 `renderWall()`）；窗口变宽变窄要重算。
这一条比真品现在的「`auto-fill` 自动分列 + 卡内追加」多写一点代码，
换来的是**网格的列宽与别的格子的位置都不动**。

## 6. 状态与异常怎么表达

同一个状态，在三个地方用**同一套说法**（在制台 / 问题台 / 墙里那一格）：

| 状态 | 在哪 | 长什么样 | 能做什么 |
| --- | --- | --- | --- |
| **生成中** | 在制台 | 琥珀色呼吸点 + 缩略图上一道走动的进度条 + 已跑时长 | 取消 |
| **排队中** | 在制台 | 空心圈（灰）+ 队列位次 | 取消 |
| **失败** | 问题台 + 墙里那一格 | 红色左边缘 + 红点 + 「失败」 + **平台原话** + 已经扣了多少 | 去平台看这条 / 重试 / 取消这条 |
| **结果未知** | 问题台 + 墙里那一格 | 琥珀色左边缘 + 琥珀点 + 「结果未知」 + 「可能已经受理并计费」 | 去平台看这条 / 重试 / 取消这条 |
| **已完成** | 墙里 | 产品那一套：绿点 + 「已完成」+ 本机/云端徽标 + 时刻 | 下载 / 拿去做生成 / 存回本机 / 收藏 |

两条刻意的做法：

1. **「重试」那颗按钮上直接写清要再付多少钱** ——
   「重试（会再扣 6 币）」。平台已经受理并计费的情况，写成「重试（可能重复扣费）」。
   真品的 `cancelTask` / `retry` 已经分得这么细（`assetCardHTML` 的 `unc` 分支、
   `Wb.bindActs` 里的重发确认），这一稿只是**把它提到按钮上**，不让人事后才发现。
2. **异常块是三行，不是一行** —— 第一行说是什么（状态 + 提示词 + 提交于何时），
   第二行说平台原话与任务号，第三行说代价与三个动作（代价在左，动手在右）。
   真品现在把「失败原因」塞在卡里一行小字里（`assets.js` 的 `failMsg`），
   挤在一屏六颗按钮中间，等于没说。

## 7. 令牌与公共件：这一稿没有另起一套

稿子里的颜色、圆角、间距、字号**全部来自产品真文件**：

稿子自己的样式只有「这一页的排版」：`demo-assets.css`，全部挂在 `.as-*` 这类

--as-head-h: 60px;   /* 页头高 */

## 8. 落到产品里要做的事

1. **在制台 / 问题台的数据来源**是现成的：真品里 `assets` 数组本来就同时装着
   `kind === 'task'` 的任务与 `kind === 'asset'` 的产物（`assetCardHTML` 里那一刀），
   `Wb.stLive` / `Wb.stBad` / `Wb.isUncertain` 也已经把状态分好了。
   这一稿只是**把同一批数据按状态摆到不同的地方**，不新增任何取数。
2. **计数从现算的同一份真相取**：类型 / 平台的条数用 `applyFilters` 之前的那一遍统计
   （真品的 `tally` 已经在数总数了，`assets.js:1105`），不要另存一份状态。
3. **卡片信息层直接用公共 `.task` 那几行**（`meta1` / `tprompt` / `meta2`）——
   这一稿已经把信息层整个交还给 `ui.css`，落地时只要把卡壳换成竖排的，
   **不要另写一套提示词与来源行的样式**。
4. **详情条复用公共 `Wb.detail`**（真品卡内展开用的就是它），只是把它从卡内挪到行下面；
   「删除本机这一份」那颗重语气按钮也一起进详情条。
5. **墙要显式分行**（§5）：真品现在是 `auto-fill` 自动分列 + 卡内追加 `.cdet`。
   改成「JS 算出一行几格 → 显式分组 → 详情插在行下面 → 量出连线位置」，
   需要给这一页写一份自己的行分组；素材库那边若也要就地展开，同一份分组逻辑应当收进公共件，
   不要各写一套。
6. **勾选框要扩到新的卡壳**：公共 `.pick` 现在是 `.task .pick`（`ui.css`），
   竖排卡壳（`.as-cell` 这一类）还没有 —— 要么把 `.pick` 的选择器放开，
   要么新卡壳也带上 `.task`（跟素材库的做法对齐）。
7. **本机 / 云端徽标**：真品的 `assetBadge`（`assets.js:437`）**只在设置页开关打开时才画**。
   这一稿默认就画 —— 「这条字节在本机还是只在平台上」是资产库最要紧的一句，
   不该藏在设置开关后面。（开关若要保留，它应该管的是「要不要自动补存」，不是「要不要显示」。）
8. **翻页改成「加载更早的」**：真品的 `Wb.pager` 是分页器（`more` 档交给哨兵续拉）；
   按天分槽之后，分页器与按天分槽**只能留一个** —— 留分页器，分槽就是假的。
9. **视图切换的两档要重画**：真品是「列表 / 紧凑方块」（`spa-assets.css:69-81`），
   这一稿是「片墙 / 清单」。落地时 `Wb.viewToggle` 的图标与档位名要一起改，
   而 `Wb.viewToggle` 的结构（`assets.js:1097`）保持不动。
10. **判据**：视觉回归（`tests/e2e/ui-visual.cjs`）要加这一页的档位：
    在制 / 常态 / 详情展开 / 多选 / 清单 / 窄窗，各浅深两档。

## 9. 顺手发现的两个真品问题（不在本稿范围，只是记一笔）

### ① 深色档下，原生控件（`select` / `input` / 滚动条）的文字是黑的

UA 样式用 `fieldtext`，不看 `--txt`；**全项目没有一处声明 `color-scheme`**（`web/styles/` 与
`shell.html` 里都搜不到）。深色档里的 `select` 是「深底 + 黑字」。

这一稿里是这么绕过去的：

```css
html[data-theme="dark"] { color-scheme: dark; }
```

建议在 `tokens.css` 的深色档补这一句（一行，全站受益）。本稿**没有改** `tokens.css`。

### ② `color: var(--txt)` 在六个页面根类里各写了一遍

`shell.html:22` 已经写死了 `html, body { margin: 0; height: 100%; background: var(--bg); color: var(--txt); overflow: hidden; }`
—— 文字颜色本来就从外壳继承下来，任何页面都不会因为漏写而变黑。

但六个页面根类里**又各写了一遍**同一句：
`spa-assets.css:9`、`spa-chars.css:17`、`spa-director.css:7`、`spa-settings.css:21`、
`spa-studio.css:6`、`spa-usage.css:8`（第七个 `fav-page` 没有写）。

七份里六份的同一行 —— 正是 AGENTS §3.4.1 说的「同一个数的第二份拷贝，两边会漂开」。
它今天没出事，是因为外壳那一行一直在；但**换主题或者调整 `--txt` 的语义时**，
七个根类里有一个忘了改，就是一处黑字。

这一稿的 `.as-page` 也照着写了这一句（跟真品的页面一致）；**落地时更该做的是反过来**：
把它从六个页面根类里删掉，只留 `shell.html` 那一处。

## 11. 这一稿没有回答的问题

- **筛选的组合**：稿子里的类型 / 平台 / 时间是**同时生效**的（AND），但没有芯片那种
  「点一下就切」的往返成本。真品那套芯片是单选的 —— 重排时这一层的交互怎么留，值得单独议。
- **日期槽与翻页的关系**：这一稿选了「往下长」（加载更早的），前提是条目按天聚拢。
  真品的条目是**按平台一批批取回**的（`fetchMore` / 游标），跨平台混排时同一天未必取全 ——
  落地时这一槽的完整性得靠「取到没有」来说明，不能假装它是全的。
- **在制台不吸顶的代价**：这一稿让筛选行吸顶、在制台往下滚（次序是「先筛，再看状态」）。
  代价是滚到下面时看不见「还有什么在跑」。若要两边都在，筛选行就得让位 ——
  或者把「在制 3」做成筛选行里的一个计数入口（点它把墙筛成在跑的那几条）。
- **清单档**比真品的「列表 / 紧凑」更简单（没有每行六颗按钮），但没有回答
  「一行放不下那么多字段时，先放哪个」。
- **导演台的引用关系**：稿子里没有画「这条产物被哪一镜用了」这一层
  —— 真品里这一页也还没有，但资产库一旦接上导演台，它多半该长在格面上而不是详情条里。
