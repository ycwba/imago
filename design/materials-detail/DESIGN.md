## 1. 真品原来是怎么做的

- **新建 = 一个弹窗 + 一张半成品占位卡**。`Chars.Lib.newForm()` 开 `PromptForm` 收七个字段
  （名字 / 类型 / 分组 / 外貌 / 预览图 / 一句话人设 / 时段），然后 `chars.js` 的 `newChar()`
  走 `onlyFields: true` 那条路 —— 表单只交回字段，页面拿它去出图、定声音，
  让用户在**素材台当中间态**里挑图挑音色，挑完才 `commitForm()` 建档。
- **编辑 = 卡内就地展开**。`editHTML(c)` 把基本信息 / 描述 / 画面 / 角色资产 / 身份锚点 /
  使用关系 / 声音七八块全塞进一张卡里，卡会长到一千多像素，网格被撑坏
  （`spa-chars.css` 里那几条 `.card.open .thumb` 的补丁就是这事的症状）。

## 2. 现在的结构：一张整屏层，两个入口

```text
┌ 应用侧栏 ─┬────────────────────────────────────────────────────────────────┐
│            │ ← 返回素材库   林晚 [角色][校园篇]  ■■□□ 缺1项  已存到本机·刚刚存过│
│            ├───────────────────────────┬────────────────────────────────────┤
│            │  预览图（大，吸顶）        │  基本信息（名字/类型/分组/只出声）  │
│            │  出图[型号▾][张数▾][重出]  │  描述（外貌 / 一句话人设 / 时段）   │
│            │  照「外貌」这一句画         │  角色资产（加一张 + 每一行自己的）  │
│            │  身份锚点（挑一张）         │  声音（型号 + 条数 + 定声音的方式）  │
│            │  预览图候选（挑/删/再出）    │  使用关系（被引用过才有）          │
│            ├───────────────────────────┴────────────────────────────────────┤
│            │ [从库里删掉]      改完就地存      [拿去生成][找相似素材]         │
└────────────┴────────────────────────────────────────────────────────────────┘
```

- **入口一**：素材台头栏「＋ 新建素材」→ 空的骨架（还没建档）。
- **入口二**：卡片上的「编辑」或检查器里的「打开详情」→ 同一副骨架，带着这一条的全部内容。

### 为什么是整屏层，不是弹窗，也不是新路由

| 选法 | 为什么没选 |
| --- | --- |
| 弹窗 | 弹窗收得了字段，收不了「挑好的那张图」。真品的出图挑选是**一屏**（几张候选 + 音色试听 + 资产），塞进弹窗就回到老路。 |
| 新路由（`/material.html?id=…`） | 能直达、能分享一条素材 —— 这是它的好处。但它要动全站唯一那份路由表（`web/core/routes.js`）、要进页面池、要处理「从哪儿来回哪儿去」，是**产品级决定**，不该由一页替它定。 |
| **整屏层**（这一稿） | 盖住素材台，头尾都还在；关掉之后素材台**原地不动**（筛选、滚动、选中态都没丢），「改完一条再改下一条」这个工作流是连着的；不动路由表。 |

**代价**：一条素材没有自己的地址（发不出链接给同事看某一位）。这一稿没解决它。

## 3. 类型决定画什么

判据仍问数据层那三份（`isVoiced` / `isSceneItem` / `isPropItem`），页面不另立一套：

| | 角色 | 场景 | 道具 |
| --- | --- | --- | --- |
| 预览图 / 候选 / 锚点 | ● | ● | ● |
| 名字 / 类型 / 分组 | ● | ● | ● |
| 外貌 · 场景描述 · 道具描述 | ● | ● | ● |
| 一句话人设 | ● | ● | ● |
| 时段 | — | ● | — |
| 角色资产 | ●（只出声时没有） | — | — |
| 声音 | ●（只出声时没有） | — | — |
| 使用关系 | 被引用过才有 | 被引用过才有 | 被引用过才有 |

**空的那一档不画** —— 场景没有「角色资产」，摆一个空框只会让人以为功能坏了。

声音那一块还要再分一层：「这一位怎么定声音」（预设音色 / 写声音描述 / 复刻参考音频）
决定下面摆什么 —— 音色胶囊、描述输入框、参考音频，三样只画一样，
且只列**这一家真有型号的方式**（`Chars.Pipe.ttsWays`）。

## 4. 每个生成位自带型号与数量

真品原来把「出图型号 / 出图张数 / 语音型号」放在素材库页的一行工具条里，**全页共用**；
于是预览图、角色资产、声音三处共用同一档设置，想给角色资产换一个型号，
得回工具条改，而那一改会把预览图一起改了。

现在每一处生成位前面有一条**生成条**（`.gen-bar`）：型号 ▾ · 数量 ▾ · 动作 · 一句「依据什么」。

| 生成位 | 型号 | 数量 | 依据 |
| --- | --- | --- | --- |
| 预览图 | 这一处自己的 | 这一处自己的 | 照「外貌 / 场景描述 / 道具描述」这一句画 |
| 角色资产（加一张） | 这一处自己的 | 这一处自己的 | 照同一句画 · 拿预览图当参考 · 出完是追加，不顶掉选中的那张 |
| 角色资产（每一行重出） | 这一行自己的 | 这一行自己的 | 同上（模板是这一张自己的） |
| 声音 | 这一处自己的 | 这一处自己的 | 照「一句话人设」这一句定音色 |

取值全部现读，界面上不写死：

- 型号 → `Chars.Pipe.modelSelectHTML`（**按平台分组**的下拉）
- 数量（出图）→ 型号声明的 `max_outputs`（`Chars.previewCap`）
- 数量（声音）→ 设置里的「候选张数」（`Chars.candCount`）

每一处单独选的型号，在**这一处**发请求时生效（`Chars.Pipe.drawPreview` / `drawCharAsset` /
`voiceCands` 都吃一份自己的 `opts`）—— 不改全页的那一份。

### 4.1 后续修正（2026-10-25）：「用本页默认」与左轨那块一起撤掉

落真品时把「本页默认」这个概念整个撤了 —— **页面上不再有任何一处「默认面板」**：

- 左轨那块「本页默认」（出图型号 / 出图张数 / 语音型号）**整块删掉**，
  生成条上那颗「用本页默认」链接也删掉；
- **默认值改由设置页「素材库」那张卡管**：新增「默认生图型号」「默认语音型号」两项，
  「角色 / 场景 / 道具 一次出几张候选」改名「默认一次出几张候选」并说明它是**默认值**；
- 页面上每一处生成位**仍然能当场换型号与张数**，换的那一次只管那一处；
- **不再往本机存「上次用的型号与张数」**（旧的 `char_opts` 键已停用并在开页时清掉）。

为什么：面板名叫「默认」，可它做的其实是**共享状态** —— 改一处、影响别处，
还把「上次用的那个」记在本机里，于是每次出图都在按上次的设置跑。
把默认值放到设置页（全局、明确、可预期），页面只留「这一次用哪个」的选择，
这一层就没有第二份真相了。

## 5. 角色资产那一节

角色的资产是**一个扁平列表**（`[{ id, name, tpl, src, propIds }]`）——
不是「三视图 / 表情表 / 服装」三个格子，而是**任意多张、每张自己一个名字**。
所以界面上分两处：

**加一张**（区块头上的一条生成条）：

| 那一格 | 是什么 | 来路 |
| --- | --- | --- |
| 叫什么 | 填了就按它画；留空用模板名 | `assetname` |
| 模板 | 三视图 / 表情表 / 服装 / 手持道具 / 自定义 | `Cast.assetTplsOf` + `Cast.assetLabel` |
| 选「自定义」时要画什么 | **只有选了自定义才用得上**（别的档是灰的） | `assetwhat` |
| 型号 + 张数 | 这一处自己挑的 | `modelSelectHTML` / `previewCap` |
| 自己传一张 | 不靠生成 | `AssetPicker` → `AssetTransfer` |

**已有的每一张**（一行的生成条 + 那一行的动作）：

- 缩略图（点开看大图）、名字（可改，空了会被拦）、模板标签；
- **它带着哪些道具**（勾选框：这一张图上出现的道具，出图与拍摄时按它发参考图）；
- **这一行自己的重出参数**（型号 + 张数）—— 选了要真的算数，不能还走区块那一档；
- 重出这一张（**换掉**这一张）、拿去生成、去掉这一张。

三条容易做错的地方，这一版都补上了：

1. **「自定义」那一档必须有一格能写「要画什么」** —— 少了它，选了自定义就必然报错走不通；
2. **行内的型号 / 张数要真的生效** —— 看着能选、重出却走的还是区块那一档，等于没做；
3. **出图失败的原因要落在看得见的地方** —— 真品写在那一行上，详情层里也照做。

## 6. 存盘口径

- **改完就地存**：改一个字段存一次（名字改了要问「导演台里有 N 处引用，回填吗」）。
  那一页**没有「保存」按钮**，回执在头栏右侧：「已存到本机 · 刚刚存过」。
- **新建时出出来的东西一起存**：出好的预览图、角色资产、声音试听与挑中的音色，
  在「建好这一条」那一下一起写进库（`Chars.Lib.commitForm` 现在收 `assets` 与 `voiceCands`）。
  「起一条就建齐」是那一页的承诺，建档这一下就该把这一条身上所有的图与声音收齐。

## 8. 这一稿没有回答的问题

- **一条素材要不要有独立地址**（能不能发链接给同事看某一位）—— 见 §2 的取舍。
- **筛选的组合**：目录轨上「类型」与「还缺什么」两档是独立的，但**不能叠加**
  （「角色里缺声音的那几条」要另做一层组合）。
- **列表档与紧凑档的卡面密度**：紧凑档是 268px 的方块网格，列表档是一行一条；
  列表档那一行还塞不下「资产几张 / 声音是什么」这两样（它们只在检查器与详情层里）。
