# 设计稿 A —— 账户优先（一家一卡 + 等高卡 + 完整型号区）

> 位置：`design/provider-matrix/` · 打开 `index.html` 即可（纯静态、无构建、不取外部数据；已验过 file:// 双击能开）。
> 浅色主题；**夜间版由浅色稿按产品深色档自动派生，不另设计一版**（`shots/08-深色派生-1440.png` 可查）。
> **这一稿只改设计，不动产品代码。**（另一稿「能力优先 · 路由台」已按反馈撤掉。）

---

## 1. 主张

**一家供应商 = 一个账号 = 一把密钥。**

五件事同时解决：

1. **同一家多模态不再重复**：真品里一家同时做多种模态，注册表就拆成几条 provider 共用一个 `keyId`
   （`sparkcine` / `sparkcine-video`；`minimax-text` / `minimax-tts` / `minimax-video`；
   `siliconflow-image` / `siliconflow-video` / `siliconflow`）。这一稿**按账号归并**：
   一家一张卡、一把密钥、卡里列着它能开通的每一档 —— 不再出现卡底那句
   「同一把密钥也用于：视频（切上面那一档，看到的还是这一把）」。
2. **卡片等高**：上一稿按内容自然生长，做多种模态的那家比别的高出一大截。这一稿给卡片一个
   统一高度（`--acct-h: 424px`），多出来的行在**卡内可滚的一段**里滚 —— 外面的网格始终齐平。
3. **语音识别 / 联网搜索不再是另外两张卡**：它们既然和图片 / 视频 / 语音 / 文字是同一类东西，
   就该**是这家账号里的一行** —— 卡里多出「语音识别」「联网搜索」两行，
   顶着那家（单选）的那张卡里，**这一档的表单就画在那一行下面**（跟别的键值行同一种排法）。
   全局的那几项（走哪条路 / 浏览器内模型 / 本机运行包）也画在这里 ——
   与真品里「识图能力只画在当前作用文字 AI 那家的卡下面」是同一个做法。
4. **添加供应商也是一张普通卡片**：它不是单独一块表单，而是卡片流末尾的一张卡
   （虚线边）。挑一家预设供应商 → **这张卡就变成那家供应商**，并**自动多出一张新的「添加供应商」卡**；
   也可以在它里面展开「自定义（中转站 / 网关）」，加完同样变成那一家。
5. **每档能力自带型号**：自动取回（问一次它自己的 `/models`）、自己填、
   **逐个决定要不要出现在工作台**、以及这一档默认用哪个。
6. **没有的那一档不画**：卡顶那一排能力格**只画这家有的**（图 / 视 / 音 / 字 / 识 / 搜），
   不支持的档既不画图标、也不留空位 —— 横向排开，几格就是几档，一眼就知道这家会干什么。

## 2. 账号卡：等高、竖排

```text
┌────────────────────────────────────────┐
│ [硅] 硅基流动 SiliconFlow ↗ [密钥 ▾] [已填密钥]│ ← 铭牌 + 名字(点它开官网) + 密钥开关 + 状态牌
│ [图][视][字][识][搜]                    │ ← 能力格：只画这家有的那几档
│ ──────────────────────────────────────  │
│ 图 [在用] [FLUX.1 Schnell ▾] [型号 2/3]   │  ┐
│ 视 [在用] [Wan2.1 I2V 14B ▾] [型号 2/2]   │  │ 可滚中区
│ 字 [备用] [Qwen3 32B ▾]       [型号 2/2]   │  │
│ 识 [备用] [Whisper v1 ▾]       [型号 1/1]   │  ┘
│ ──────────────────────────────────────  │
│ ☑侧栏余额 ☐暂时不用            改完就存本机│  ← 固定
└────────────────────────────────────────┘
```

点名字右边的「密钥 ▾」，才在卡内出现**填写密钥的那一块**：

```text
密钥 [••••••••••••••••]  显示 清除 验证
```

- **等高**：`--acct-h: 424px`，网格 `align-items: start` 也不影响 —— 每张卡一样高。
  能力多的账号多出来的行在卡内 `.acct-mid`（`overflow-y: auto`）里滚，不把整张卡拉长。
- **名字自己就是官网链接**（后面跟一枚 ↗）：卡上**不显示网址、也不在名字下面再写一遍小字**。
- **密钥默认收起来**：卡上**什么都不显示**（没有「已填密钥」摘要行，也没有地址行）；
  点名字右边那颗开关，才出现填写密钥的那一块。展开与折叠**不改卡片大小**
  （密钥块在卡内那段可滚区里，展开只是把内容挤进滚动区）。
- **接口地址**：卡上**不显示、也不单独编辑** —— 官方地址点官网链接就到；
  **预设供应商一律走官方地址**（跟图片 / 视频 / 语音一样，不给「改地址」入口，文字类也不例外）；
  **自定义**供应商的地址在「添加供应商」那一步填一次（那本来就是你自己的中转地址）。
  > 真品里文字类供应商还有一条 `baseEditable`（可以把官方地址换成任意 OpenAI 兼容网关）。
  > 这一稿把它收掉了 —— 要保留的话，入口放进「编辑」，不常驻卡片。
- 卡里三段固定（头 / 密钥 / 底部动作）+ 一段可滚（中区）—— 滚的是型号与能力那一段，
  密钥与开关永远在原地。

### 能力格：只画这家有的

| 状态 | 画法 | 含义 |
| --- | --- | --- |
| 主位 | 实心强调色 + 白字 | 这一档归它管（作用文字 AI / 在线识别顶班 / 搜索渠道） |
| 在用 | 强调色淡底 + 强调色字 | 这一档开着 |
| 备用 | 白底 + 深字 | 有这家，但这一档不是主位（点一下就轮到它） |
| 停用 | 淡底 + 虚线边 | 这一档接上了但没开（或这家还没密钥） |

> 卡顶那一排能力格**只画这家有的那几档**，横向排开：不支持的档不画图标、也不留空位。
> 图例（`图 图片 · 视 视频 · 音 语音合成 · 字 文字对话 · 识 语音识别 · 搜 联网搜索`）
> 在清单上方教一次「哪个字是哪一档」。
> 筛选某档时，被筛的那一格会**多一圈强调色描边**（`.capcell.hit`）。

### 能力行：六档长得一模一样

```text
图   [在用]  [FLUX.1 Schnell ▾]  [型号 2/3]
视   [在用]  [Wan2.1 I2V 14B ▾]  [型号 2/2]
音   —        （这家没有这一档 → 整行不画）
字   [主位]  [MiniMax-M2 ▾]     [型号 2/2]
识   [主位]  [Whisper v1 ▾]     [型号 1/1]
搜   [备用]  [Tavily Search ▾] [型号 1/1]
```

- **状态牌本身就是选择器**（没有「让这一家顶着」那种按钮）：
  · 多选档（图片 / 视频 / 语音合成）：点一下 = 在用 / 停用（多家可同时开）；
  · 单选档（文字对话 / 语音识别 / 联网搜索）：点一下 = **这家上位**，原主位自动降为「备用」。
- **每张卡只画自己有的那几行** —— 别的档根本不出现。
- 顶着那家（单选档的主位）的卡里，这一档的**全局项**画在那一行下面：
  文字对话 → 识图能力（全局一项）；语音识别 → 走哪条路 / 浏览器内模型 / 本机运行包 / 地址 / 密钥 / 保存 / 测试；
  联网搜索 → 启用 / 搜索服务 / 结果数 / 密钥来源 / 地址 / 密钥 / 保存 / 测试。

## 3. 型号区：自动取回 + 各档选型 + **逐个决定是否出现在工作台** + 自己填

点某一档那一行的「型号 2/3」（分子 = 在工作台显示的个数，分母 = 总数），**就地展开**型号清单面板：

```text
型号清单  [已取回 12 个 · 840ms]        [取一次型号清单]
共 3 个型号 · 在工作台显示 2 个
                                    藏起来的那几个不出现在工作台的型号下拉里，历史任务照常能看。
──────────────────────────────────────────────
FLUX.1 Schnell
FLUX.1-schnell · 文生图 / 图生图
☑ 在工作台显示   [这一档默认]   [删除]
──────────────────────────────────────────────
SDXL 3.5
stabilityai/stable-diffusion-3.5-large · 文生图
☐ 在工作台显示   [设为默认]     [删除]      ← 藏起来的那一个，名字划掉
──────────────────────────────────────────────
自己填  [型号 id（逗号分隔可一次填多个）]  [添加]
```

- **自动获取**：`取一次型号清单` —— 用这一栏现在的密钥与地址问一次它自己的 `/models`
  （真品里只有声明了 `endpoints.models` 的平台给这条按钮）。状态四态：
  还没取过 / 正在取… / 取回 N 个（带耗时）/ 取失败（带原因）。
- **是否出现在工作台**：这是**逐个型号**的开关（真品里就是 `sk_model_prefs.json` 的 `off` 列表）。
  勾上 = 出现在工作台的型号下拉里；取消 = 藏起来，历史任务照常能看。
- **各档选型**：每一档能力有**自己的默认型号**（下拉里只列「在工作台显示」的那些）。
  真品里型号清单按家存（`.data/sk_model_prefs.json`，每家一份 `{typed, off}`）；
  「这一档用哪个」是这一稿新增的一层 —— 落地时在同一个文件里加一个 `pick: {image: '…'}` 即可。
- **自己填**：没有型号接口的平台手填 id（逗号分隔可一次填多个）。

## 4. 一张卡片流：六档能力是同一种行

```text
┌ 账户与密钥 ─────────────────────────────────────────────────┐
│ [硅] 硅基流动 …    [M] MiniMax …     [S] SparkCine …          │  ← 供应商卡（一格宽、等高）
│ 图 [在用] [FLUX.1 Schnell ▾] 型号 2/3                          │
│ 视 [在用] [Wan2.1 I2V 14B ▾] 型号 2/2                          │
│ 字 [备用] [Qwen3 32B ▾] 型号 2/2                              │
│ 识 [备用] [Whisper v1 ▾] 型号 1/1                            │
│ ＋ 添加供应商 …                                             │  ← 也是一张普通卡（虚线边）
└──────────────────────────────────────────────────────────────┘
```

- **图片 / 视频 / 语音合成 / 文字对话 / 语音识别 / 联网搜索，六行长得一模一样**：
  能力名 · 状态牌（就是选择器）· 这一档的默认型号 · 型号管理。
- **每张卡只画自己有的那几行** —— 不支持的档连行都没有。
- 单选档（文字对话 / 语音识别 / 联网搜索）主位那家的卡里，这一档的**全局项**画在那一行下面：

```text
识 [主位]  [Whisper v1 ▾]  型号 1/1
┌ 走哪条路   [自动 —— 浏览器模型就绪就本机，否则本地，最后在线] ┐
│ 浏览器内   [模型未下载] …                          [下载模型] │
│ 本机运行包 [不可用] …                                [重新检查] │
│ 地址 / 密钥 / [保存语音识别设置] [选一段音频测试识别]        │
└───────────────────────────────────────────────────────────────┘
```

- 换一家上位 → 那一档的表单搬到那家的卡里（全局项跟着搬）。
  这与真品里「识图能力只画在当前作用文字 AI 那家的卡下面」是同一个做法。
- 页面标题栏**没有「＋ 添加供应商」按钮** —— 添加只有卡片里这一条路。

## 5. 手动加一档能力（硬编码里没写这家能做的那一档）

真品的现状：**型号**可以自己填（`sk_model_prefs.json` 的 `typed`），但**「这家会哪几档」是注册表写死的
`kind`**（`server/registry-config.js`）—— 平台后来支持了新模态，界面上没有地方表达，
只能改 `proxy.js` 的 REGISTRY 再重启代理。这一稿给一个入口：

```text
┌ 手动加一档能力                          注册表里没写这家能做的那一档 ┐
│ [音 语音合成][识 语音识别][搜 联网搜索]                            │
│      （已经有了的那几档不列；文字对话不在这里加，见下面那张表）      │
│ 加进来的这一档只是声明：型号由你自己填。语音识别 / 联网搜索走这家   │
│ 自己的地址与密钥，加完就能用；图片 / 视频 / 语音合成要真能生成，    │
│ 还得在 proxy.js 的 REGISTRY 里补一条端点声明。                     │
└───────────────────────────────────────────────────────────────────┘
```

- 选一档 → 它出现在卡里（带一枚「手动」标记），**型号清单面板自动打开**，自己填型号 id 即可。
- 这一档在能力格上也占一格，跟着这家的其余能力一起被读；旁边有「撤掉」（只撤这份声明，不动密钥）。
- 生成三档那一行下面还会顶一句黄字，明说「注册表里没有它的端点声明」。

**落到真品时它对应什么（三条路，要说清）：**

| 你想加的 | 真品里的落点 |
| --- | --- |
| 一家**根本不在注册表里**的供应商做某一档（中转站 / 网关） | 走**添加自定义供应商**：声明 `kind` + 接口形状 + 地址 + 密钥 + 型号（`sk_custom`）—— 这条路真品已经有了 |
| 一家**内置平台**其实还做某一档（识别 / 搜索 / 生成） | **已落地**：卡里「＋ 手动加一档能力」→ 存 `sk_caps_<keyId>`；识别 / 搜索真能用（走这家自己的地址与密钥），生成三档只算声明，真出图还要 REGISTRY 一条端点 |
| 让某一家当**文字对话** | 不在这里加：`TextAI` 按 `kind: 'text'` 认供应商，加在别家身上不生效 —— 另接一家走「添加供应商」里的自定义 |

> 「手动加一档能力」不假装自己凭空造得出能力：它落成一份**本机声明**，
> 并把「这一档还差代理那边一条端点声明」写在那一行下面。

## 6. 添加供应商：一张会变成供应商的卡片

卡片流末尾那张虚线卡，**两个形态、同一张卡**：

```text
┌ 添加供应商                        待接入 8 ┐   ← 常态：列预设
│ [智] 智谱 GLM    文字对话 + 视频   字视 [添加]│
│ [V ] VGENV 视频   视频             视   [添加]│
│ …                                          │
│ [＋ 自定义（中转站 / 网关 / 企业部署）]      │
└────────────────────────────────────────────┘
                      ↓ 点「＋ 自定义」
┌ 添加自定义供应商               [返回预设] ┐   ← 同一张卡自己变成这个形态，**尺寸不变**
│ 接口形状 [OpenAI 兼容生图 ▾]              │
│ 显示名   [图片]                          │
│ 接口地址 [https://…]                     │
│ 密钥     [……………]  👁                    │
│ 能力档位 [图][视][音][字][识][搜]         │   ← 在密钥之后，与卡顶同一副图标，可多选
│ 型号     （清单 / 空态一句话）             │
│ 自己填 id [……]  [获取型号列表]            │
│ [添加这一家]  图片 · 合计已接 0 家         │
└──────────────────────────────────────────┘
```

- 挑一家预设 → **这张卡就变成那家供应商**（密钥那一格空着，填一把就能用），并**自动多出一张新的
  「添加供应商」卡**；已接的那家从剩下的清单里消失。
- 「自定义」不另起一层、不另起一张表：**这张卡自己变成「添加自定义供应商」**（标题换了、右上角
  是「返回预设」），字段就在卡里填，**卡片尺寸不变**（十几行在卡内那段可滚区里滚）。
- **没有「供应商」那一格** —— 要接内置那几家，就在上面那张卡的预设清单里点「添加」；
  这张表只做「我自己的中转站」，所以只有**接口形状**。
- **能力档位**是与卡顶那排能力格**同一副图标**的多选：第一个选中 = 主档（决定接口形状与这条
  自定义条目的 `kind`），其余记成 `sk_caps_<id>` 的「手动声明」（识别 / 搜索真能用，
  生成三档照旧会写明还差注册表一条端点）。

## 7. 筛选：芯片 + 摘要条 + 排序

- 芯片：**全部 / 图片 / 视频 / 语音合成 / 文字对话 / 语音识别 / 联网搜索**（数字是**账号数**）。
- 筛选后上方出现一条**摘要条**：`做「视频」的 3 家 · 在用 3 家` + 一句排序说明 +
  「看全部 N 家」。
- 排序：**在用 / 主位 → 备用 → 没接上**；同档里能力多的在前。
- 每张卡的能力格上，被筛的那一格**多一圈强调色描边** —— 一眼知道这家人是为什么被筛出来的。

| 现在 | 改成 |
| --- | --- |
| `settings.js` 的 `provGroups()` 按 `keyId` 归并，返回 `kindIds` | 归并结果换成「账号 + 能力清单」（`caps`），UI 直接画 |
| 一排模态分段（图片/视频/语音/文字 + 语音识别/联网搜索两个虚拟档） | 撤掉，连旧键一起撤（§14.6 不留兼容层） |

| 卡上直接显示官网网址 / 名字下面重复写一遍小字 | 去掉；**名字本身是官网链接**（带 ↗），下面不再写小字 |

## 10. 已知取舍

- **卡内那一段要滚**：卡高固定（真品 320px），能力特别多（比如一家同时做六档）的账号要在卡内滚。
- **「谁供哪一档」要逐张看**：能力格只画这家有的那几档，卡与卡之间不再上下对齐 ——
  换来的是「我买了几家、每家一把密钥」与列表顺序一一对应。
  能力筛选芯片 + 摘要条 + 圈出来的那一格，是这份代价的补偿。
- **能力格是新的图形语言**：全站没有第二处用这种小方格 —— 好处是它一眼就是「这一家的能力」，
  代价是要教用户一次（图例那一行就是用来教一次的）。
- **预设清单要人维护**：真品里注册表那份清单本来就有（`REGISTRY.providers`），
  「预设供应商」是同一份数据的另一个视图 —— 落地时直接从注册表来，不要维护第二份。
