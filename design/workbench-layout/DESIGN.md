## 1. 真机今天的样子（问题从哪来）

现状画面见 `shots/before-现状-工作台.png`（真机跑的，1440×900）。四条硬伤：

1. **生成按钮沉在左栏最底，首屏看不见。**
   左栏从上到下是：标题 → 类型/型号 → 提示词 → 输入模式 → 5 个素材槽 → 高级设置 → 估价 →
   生成按钮 → 状态行。900px 的屏里，「生成视频」在**折叠线以下**。用户改一个参数要滚到底，
   提交完再滚回顶上看结果。

2. **参数是一张长表单，不是「一份配方」。**
   视频档的字段有 20 个上下（档位 / 画质 / 时长 / 比例 / 条数 / 平台开关 / 顶部布尔 / 形状字段…），
   全平铺在一栏里，越靠下的越少被用（`studio.js` 里 `.adv-grid` 三段 + `#topBools` + `#shapeFields`）。
   素材槽又是竖排五个大块（开头画面 / 结尾画面 / 参考图 / 参考视频 / 参考音频），把提示词挤到很下面。

3. **右栏散着四条互不对齐的条**：类型筛选 / 搜索+多选+刷新 / 翻页 / 多选条。
   翻页行塞在搜索行下面（`spa-studio.css` 里 `.wb-pager`），视觉上就是第四层噪声。

4. **结果只有一种形态**：一堆同款大卡，没有「这一条」的落点。
   生成完要在几十张卡里找刚出来的那张；「它是用什么参数做的」在卡片上根本看不到。

5. **同一个维度两套控件**：上面切「视频 / 图像 / 音频」（做什么），
   下面筛「全部 / 图片 / 视频 / 音频」（历史里有什么）。两个都是类型，但一个在左一个在右，
   读起来像两件事。

## 2. 新结构：作业台

一句话：**把「左栏写、右栏看」两页并置，换成「一条竖向作业线 + 一面结果墙 + 一条常驻提交坞」。**

### 2.1 配方轨（左栏）：从「长表单」到「配方单」

- 每一组是**一行摘要 + 当前值**（`提示词 · 128 字` / `参考素材 · 3 项` / `画面参数 · 4 项已设`）。
  收起时**值仍然看得见** —— 折叠是降噪，不是隐藏。
- 点标题就地展开，改完收起，值写回摘要行（字数、模式、条数都跟着变）。
- 展开用 `grid-template-rows: 0fr → 1fr`，高度自己算，不写死行高。
- 轨头记「6 组 · 2 组待补」：**没填的那几组永远可见**（音频档的「音色描述 · 必填」「参考素材 · 0 项」）。
- 素材槽从竖排五个大块变成**一行紧凑缩略图**（参考图 ×1 / 参考视频 ×1 / 参考音频 ×1）。

> 风险说在前面：折叠式配方轨是这一稿最大的赌注 —— 惯例是「参数全平铺」。
> 缓解办法就一条：**收起时也带着值**，加上轨头的「待补」计数。

### 2.2 舞台（右栏上半）：给「这一条」一个落点

- 选中 / 最新的那一条放大看：**暗底片窗**（产品令牌里的 `--media-bg`，跟导演台的轨道区同一块黑底）
  + 提示词 + 状态 + **这一条是用什么配方做的**（输入模式 / 参考素材 / 画质 / 消耗）。
- 右下角那枚角标是画面规格（`16:9 · 1024 × 1024 · PNG`），像播放器里的机器信息。
- 下方是**历史墙**：一屏同款小卡，点哪一张哪一张上舞台。

### 2.3 提交坞（底部）：提交不再沉底

- 估价、消耗、预计、**上一条的回执**、主按钮，全在一行里，**永远在这一屏**。
- 提交后的回执**原地出现在坞里**（提交中 → 已完成），不用滚到右栏去找那张卡。
- 左栏因此不再有提交区 —— 估价、按钮、状态行全部搬下来，左栏只剩「配方」。

### 2.4 作业头：只留三件事

做什么（类型）、用谁（型号 + 能力来源）、能不能做（余额）。
型号下拉那一格现在显示的是 `base`（信息量为零），这一稿显示 `VGENV · base · 快速`，
下面一行是能力来源 —— 下拉里的选择**在头上看得见**。

## 4. 要拍板的三件事

1. **配方轨默认展开哪一组？** 这一稿默认展开「提示词」，其余收着。
   也可能是「上次动过的那组」—— 那要记状态，代价大一点。
2. **舞台常驻还是可收？** 这一稿常驻 280px。如果「历史墙」更重要，可以把舞台收成
   「最近一条」的横条（一条 48px 的带），把高度全给墙。
3. **提交坞吞不吞左栏底部？** 这一稿的建议是**整个搬下去**（估价 / 按钮 / 状态行三样都搬），
   左栏从此只有配方 —— 代价是左栏不再有「提交」这个动作的物理位置。

## 5. 这一稿没解决的

- 三种类型的**参数差异**只做了版式示范，真实的字段集仍然由 `Capabilities` 声明驱动，
  这一稿没有碰能力声明那一层。
- 多选、拖拽、拆分片段生成这些交互在稿子里是**示意**（可点、样子对），不是真实现。
- 窄窗只做到 900px 以下单列，没有做手机形态。
