## 1. 真机今天的样子（问题从哪来）

现状画面见 `shots/before-现状-助手.png`（真机跑的，1440×900，
从 `tests/fixtures/visual/actual/chat-src_1440_dark.png` 原样拷过来）。六条硬伤：

1. **所有东西都是气泡，层级是平的。**
   结论、执行轨迹、产物卡、来源、Skill 芯片、错误，全都画成 `.ac-bd` 那种圆角气泡，
   一条消息一个气泡（`chat.js` 的 `.ac-m` / `.ac-bd`）。用户分不清哪句是结论、
   哪句是工具在报过程、哪块是产物。

2. **产物被压到看不清。**
   `.ac-card-media .ac-img/.ac-vid` 是 `max-height:220px`，再乘上 420px 的面板宽 ——
   产品里图片是主角，在这里只是一张缩略图。

3. **执行闸与结论是分开的。**
   写动作（提交生成要花钱、写素材库、改设置）要用户点头，这是产品最要紧的一步
   （设置页那张卡写得很清楚：「一次生成在平台那边就是一条真任务，没把握就别勾」）。
   但现在确认卡（`.ac-run-card`）与结论气泡是**两条独立的消息**，
   用户得在消息流里上下找，才知道「刚才那步到底批了没有」。

4. **历史会话是一块盖在对话上的浮层，选中项只有一条左边条。**
   `.ac-hist` 是 `position:absolute; top:42px` 的一小块，列表项之间没有分隔，
   只能靠 hover 底色区分；关掉它要点别处，但界面上看不出哪儿能点。

5. **助手上方那条上下文带读不出「助手现在知道什么」。**
   `.ac-ctx` 里几个 `.ac-chip` 换行堆着，没有固定语法；
   里面装的是**宿主页面的状态**（生成工作台注册的类型 / 型号 / 素材槽那一类），
   跟「这一轮助手在干什么」没关系。

6. **按钮平铺在输入框下面，没有分工。**
   `.ac-row` 里 `+文件 / 清空 / 停止 / 发送` 四个挤在一行；
   「清空」是会话级动作，却和「发送」同排（只能靠 `margin-right` 拉开一档）。

## 2. 三个概念先说清楚（这一稿跟着真产品走，不自己发明）

### 2.1 「引用」= 引用**素材**，不是引用对话里的哪句话

真产品的完整机制（`web/features/chat.js` 的 `refs` / `addRefText` / `paintRefMarks`）：

| 一步 | 发生什么 | 代码 |
| --- | --- | --- |
| ① 拖起来 | 页面上可引用的卡片（素材库 / 资产库 / 收藏 / 生成工作台）带 `application/x-studio-ref` | `AssetRef.isRef(dt)` |
| ② 落到**悬浮球**上 | 球**点亮一圈虚线**（只有引用才点亮 —— 拖外部文件是上传，不是引用）；落下后写进输入框并打开面板 | `ballOver` → `ac-drop` → `addRefText` + `openPanel` |
| ③ 落到**面板 / 输入框**上 | 放行 drop（但**不**点亮上传高亮），同样写进输入框 | `p.addEventListener('drop')` |
| ④ 写进正文 | 在光标处插入一行 `[引用素材：名字]`（用 `setRangeText`，保住 Ctrl+Z 那个原生撤销栈） | `addRefText` |
| ⑤ **高光字** | 一个隐藏的镜像元素量出每个标记的矩形，往上层铺一块 accent 淡底（`.ac-ref-hl`，14%）画在文字**下面**；标记右边一个 ✕ 撤掉（`.ac-ref-x`）；悬停出缩略图与「类型 · 资产号」（`.ac-ref-tip`） | `paintRefMarks` |
| ⑥ 上限 | 最多 20 条（`REFS_MAX`），挤掉最早的要说清挤掉了谁 | `addRef` |
| ⑦ 发出之后 | 消息下方那一排芯片（`.ac-mfs`）记着这一条带的是哪些引用 | `.ac-mfs` |
| ⑧ 给模型 | 下一轮组装 `【这次引用的素材】` 清单 —— 模型要真看某一条，用 `asset_open` 按序号取 | `refBlock` |

**这一稿怎么画的**：

- **正文里那段高光字原样画回来了** —— 输入框里就是「照这版提示词生成一条 4 秒的视频」+ 一行
  `[引用素材：雨夜街道-候选 1]`，底下铺 accent 淡底，悬停出缩略图与「图片 · 资产 la_91b2 · 任务 task_7f21」。
  （真产品用「镜像层 + 绝对定位」画，因为 textarea 装不下标记；这一稿正文是静态的，
  直接画，视觉结果一样。）
- **那圈「[引用素材：…]」保留** —— 它是**识别用的**：`REF_MARK = /\[引用素材：([^\]\n]*)\]/g`，
  `markerRanges` 靠它把正文里的标记与 `refs` 队列对上（同名按出现顺序依次吃掉队列里同标签的那几条）。
  去掉它会让人看不出「这一行指哪一条」。
- **去掉了那个 ✕** —— 标记本来就是正文里的文字，**键盘选中那段删掉就行**；
  删了之后这条引用就**作废**（正文是真相，见 §7.3）。
- **发出去的消息里，引用也是正文里的一段高亮文字**（跟输入框同一个手法，
  底色按所在容器翻过来：灰底配淡紫高亮 / 紫底配白底 + accent 描边），悬停同样出缩略图与号。
  附件（文件）另算 —— 它不是正文的一部分，单独一排小芯片。
- **悬浮球也画了**（浮窗档那一形态看得见它，右下角，带未看计数点），
  拖资产到它上面时**点亮一圈虚线**（`ac-drop`）—— 那是「这里能落」的反馈。
- 输入框上方那一排改回**附件**（那是**文件**，真产品 `.ac-files`），
  素材引用不归它 —— 归正文里那段高光。旁边一句「拖资产卡到悬浮球或这里 = 引用，正文里会高亮」把入口说清楚。

### 2.2 「引用给模型的是什么」—— 号给了，助手自己去查

这一层**原稿一行没碰**，照原样保留（`chat.js` 的 `refBlock` / `shotRefs`，
`chat-tools.js` 的 `asset_open`）：

**发给模型的清单**（每轮开头贴一次）：

```text
【这次引用的素材】
0 = 雨夜街道-候选 1 · 图片 · 资产 la_91b2 · 任务号 task_7f21 · 地址 /asset/la_91b2
1 = 雨夜街道 · 场景 · 资产 la_7f3a
（这些是用户拖进来的引用。要真的看其中某一条，用 asset_open 按序号取；不要凭这段文字猜图里有什么。）
```

每一行是：名字 · 类型 · **资产号** · **地址 / 下载地址** · **任务号** · 本机文件 key；
一个都没有就写「只有号」。序号从 0 数。

**助手自己查**（`asset_open`）三种入口，取的是**字节并真的看**（`lookAtImage`）：

| 入口 | 写法 | 走哪条路 |
| --- | --- | --- |
| 按序号 | `{ "index": 0 }` | 引用清单里的第几条（从 0 数） |
| 按号 | `{ "id": "la_91b2 / 平台产物号" }` | 先在清单里找，找不到就按 `la_` / `http` 当成资产号 / 地址试 |
| 按地址 | `{ "url": "/asset/la_91b2" }` | 直接当一条地址取字节 |

取回来返回「引用 · 类型 · 资产号 · 任务号 · 型号 · 看到的」。
**取不到就照实说取不到**，不猜：

- 签名过期 → 先 `Api.healMedia` 续签一次，还不行就说「让用户从资产库重新拖一次」；
- 只有平台产物号、本机没字节 → 说「先在资产库把这一条存回本机」；
- 不是图片 → 说「本机没有读它的模型；要它参与生成就直接当素材用」。

**同一份、同一序号**：`ctxRefs()` 读的是这一轮真正发出去的那份（`shotRefs()` 发的快照），
`refBlock()` 与 `asset_open` 用的是**同一个下标** ——
模型说的「第 1 条」与 `asset_open` 取的必须得是同一条。

**真相是队列**：正文里那行标记只是队列的可视化。用户把标记改掉或删掉，
这一轮模型**仍然**按队列拿到它（回执会明说）—— 队列才是「用户指的是哪一条」。

**界面上给人看的是什么**：`.ac-ref-tip` 悬停浮层 = 类型 · 资产号 · 任务号（有的才显示）。
这一稿照抄了这一条，所以那条高亮标记悬停出来是
「图片 · 资产 la_91b2 · 任务 task_7f21」—— 界面上看得见号，
用户知道助手拿着什么去查；地址不给人看（那是给模型的）。

**发出之后**：气泡上挂住这一条带了什么（`carry.refs`，跟着消息落盘，刷新后还在），
就是界面上的 `.ac-mfs` 那排芯片。

**⚠ 拖进来的东西到底带不带号？带。** 拖动载荷的唯一出口是
`web/domain/asset-ref.cjs`（UMD，四个拖动源共用一份），字段白名单：

```text
kind / id / name / type / mtype / format / assetId / src / dl / fileKey / prompt / from
taskId / genId / status / model / provider / providerName / ts / localAsset / size
error / credits / tier / res / ar / dur / quality
```

即：拖**资产库里的卡** → 带 `assetId`（本机资产号 la_xxx）+ `src`（本机地址）+
`dl`（下载地址）+ `taskId`（平台任务号）+ 完整 `prompt`（不是前 40 字）+ 型号/平台/花费/时间；
拖**工作台里的产物卡** → 同上，外加 `localAsset` 标「已在本机」；
拖**收藏里的本机文件** → 带 `fileKey`；
拖**桌面上的图片文件** → 那**不是引用**，走**附件**（`K_FILES`：名字 / 类型 / 本机资产地址 / 文本快照），
没有 assetId（除非它本来就在资产库里）。

`label()` 拼人话标签时就已经把号带上了（资产号 > 本机文件 > 任务号，三选一）：

```text
雨夜街道-候选 1 · 图片（资产 la_91b2）
```

另有一份纯号单独写进 `application/x-asset-id`，老载荷只带号也认。

### 2.3 「Skill」= 这一轮**按什么规范写**

一份 Skill 是 `.skills/<id>/SKILL.md`：frontmatter 带 `id / name / description / triggers /
pages / contract`，正文是「这一类该怎么写」。内置 12 份（图片提示词、视频提示词、口播稿、
拆剧本、关键帧分镜、角色图、分角色音色、改分镜清单、分镜新素材判定、拆分片段、接着改一版…）。

- **怎么选**（`web/ui/skills.js` 的 `activeFor`）：按「当前页面 + 你这句话里的触发词」自动挑，
  最多两份预载；你点名（问题里写了它的 id 或名字）就**钉死**那份；
  回合内助手还能按需再读 2 份（约 1000 token 预算）。
- **界面上长什么样**：它出现在**那一轮的消息里** —— 一排芯片（`.ac-skills` / `.ac-skill`：
  名字 · v版本，还标「已停用」「下一轮生效」），点开看正文。
- 装 / 启用在设置页「Skill」那一张卡里。

**这一稿**：输入区那个「Skill」按钮删掉（产品里没有这个入口）；
改为在**这一轮的工单卡上**显示「这一轮带的 Skill」芯片 —— 它是这一轮的**前提**，
所以放在「你的指令」之后、「工序」之前。

### 2.4 助手上方那条带子：**整条删掉**

真产品那条 `.ac-ctx` 装的是**宿主页面的状态快照**（`__acPageCtx()`）：
生成工作台注册的是 类型 / 型号 / 提示词字数 / 输入模式 / 素材槽。
它是「你脚下那一页现在是什么」，不是「这一轮助手在干什么」——
助手自己每轮都会自动带上这份快照（系统提示词里就有），界面上再摆一遍只是重复。

**所以这一稿**：那条带子整条去掉，助手上方直接是工单流。
「在 生成工作台」留在顶栏（那是产品的 `ac-here`，本来就该有）。
余额同理：余额在侧栏「账户余额」区；助手要问余额是它自己去查 `credits`（联网打平台余额接口），
那是**它答出来的内容**，不是常驻显示的一格。

### 3.1 三处结构性改动

**① 一轮分两半：你发的那条 + 助手的回应。**

**你发的那条永远独立**（右对齐、淡紫底，与产品的 `.ac-me .ac-bd` 同一形状），
**引用的那一段在正文里是高亮文字**（跟输入框那一个同款手法，悬停出缩略图与号）；
附件（文件）另算 —— 它不是正文的一部分，单独一排小芯片。

**谁在左、谁在右**：**助手那侧一律靠左**（纯回答的气泡、工单卡，都 ≤340px，贴着栏的左边），
**你那侧靠右**。谁说的话，不用看颜色也一眼就分得出来。

真产品里那排芯片（`.ac-mfs`）**只写名字，号藏在 `title` 里**：

| 产品现在 | 这一稿 |
| --- | --- |
| `引用·雨夜街道-候选 1`（号在悬停提示里） | 正文里一段高亮的 `雨夜街道-候选 1`，悬停出缩略图 + 类型 · 资产号 · 任务号 |
| `文件·参考图.png` | `⊠ 参考图.png` + 小字 `文件` |

拖进来的东西到底带着什么号，**用户自己就该看得见**，不用去猜悬停提示里藏了什么。

**助手的回应有两种形态**：

- **纯回答**（这一轮没调任何工具）→ **一条气泡**（左对齐、灰底加细描边），下面一行「复制 / 重问」。
  **不套卡壳** —— 一段话就配一段话的容器，硬塞进一个空卡壳里只是把简单的事做复杂。
- **动过手的**（查了 / 写了 / 提交了 / 产出了）→ **一张工单卡**：
  左缘一条 3px 状态色带（绿=完成 / 琥珀=待确认 / 红=失败 / 紫=在跑），
  卡内从上到下是固定的五层：这一轮带的 Skill → 工序 → 结论 → 产物/来源 → 页脚。
  **卡里不重复你的话** —— 上面那条就是。

一屏里于是有三种形状：气泡、气泡、工单卡 —— **哪一轮动了手，扫一眼就知道**。
这比「所有轮次都套一张卡、卡里该空的就空着」更诚实。

**② 工序有脊。**
产品里这个助手真的在跑一串工序（`chat-tools.js` 的 `TOOLS` 只读查询 33 项、
`ACTS` 写入动作 17 项），所以工序的**顺序、状态、耗时**是这一层最有价值的信息。
现状把它摊成三种形状相似的浅底盒子（`.ac-run` / `.ac-turn` / `.ac-step`），
彼此分不清；这一稿把它收成一条竖脊 + 若干节点：
绿=做完、红=失败、蓝=在跑、琥珀=等你点头。
收起时每道工序只留「工序名 + 用时」（像一张工序表），
点「展开工序」才出细节（命中了什么、跑在哪、为什么慢）。

**③ 执行闸长在工序线上。**
要花钱 / 要写盘 / 要覆盖的那一步，不再是另一条消息 —— 它就是工序里的一个节点，
节点旁边直接挂着确认块：金额、平台、参数、不可撤回，再给「执行 / 算了」。
用户看的是**这一步在整串工序的哪个位置**，
而不是在消息流里翻找「刚才那步批了没有」。

### 3.1.1 宽度与把手

- 面板 **420px**（真产品 `--ac-w` 的默认值，范围 360–760），浮窗档 **400px**。
- 工单流左右各 20px，**一轮 = 一条 ≤340px 的窄列，居中放在流里** ——
  卡不撑满，右边那截余白是栏的余量（票据贴在栏上，不是把栏糊满）。
- 产物在窄卡里**一列**（两列会把图压到看不清 —— 那正是现状那个硬伤）。
- **宽度把手照旧在**：真产品左沿那根 `.ac-grip`，拖动改 `--ac-w`（360–760），
  记在本机（`ai_chat_w`），固定档时页面跟着收放；浮窗档另有下沿那根 `.ac-grip-b` 调高。
  这一稿把它**画出来**（产品那根默认看不见，鼠标摸到才知道能拖），
  并且**做成真能拖的**（实测：左拖 120px，宽度 420 → 540）。

### 3.2 历史会话：沿用原来的浮层布局，做优化

**结构照旧**（产品里是 `.ac-hist` / `.ac-hs`）：浮层，标题行 + 搜索行 + 列表项；
列表项 = 标题（两行截断）+ `fmtWhen(at) · N 条` + 右上角 ✕；
当前项左边 2px 强调条 + 底色；点一下切过去就收起；Delete 键删。

**优化六处**：

1. **入口放回顶栏那枚时钟按钮**（产品的 `acHist` 就在顶栏），不再是从内容里凭空冒出来。
2. **铺满整条面板、从顶栏下方垂下来**（产品是 `left/right` 各 8px 的一小块，
   顶栏与浮层之间还漏一条缝）。
3. **列表项之间加 1px 分隔线** —— 原来只靠 hover 底色，一列字扫不下去。
4. **当前项多一个「当前」标** —— 原来只有一条左边条，色弱。
5. **底下加一层淡遮罩，点别处收起** —— 原来也能点别处收起，但界面上看不出哪儿能点。
6. **计数摘要沿用产品口径**：「N 段 · 共 M 条（当前这段 K 条）」，搜索时「找到 X / Y 段」。

**不做的**：不按日期分组（产品没有这一层，加了就是第二份清单）。

### 3.3 另外三处

- **助手上方那条带子整条去掉**（见 §2.3）。
- **最新的在最上面**：这一层是工作台不是聊天记录 —— 用户看的是「现在这一轮」。
- **清空**从输入区挪走（它是会话级动作，不该和「发送」同排）。

### 3.4 空态

现状的空态是「一段介绍 + 一颗体检按钮 + 六颗示例问句」。
这一稿加了一层**能力清单**，而且按产品自己的分法分三组：

| 组 | 是什么 | 对应真产品的 |
| --- | --- | --- |
| **查** | 历史任务 / 本机资产 / 提示词归档、余额与用量、导演台时间线与字幕 | `TOOLS`（只读查询） |
| **改** | 改一项设置、新建或更新一条素材、剪时间线 · 改字幕 | `ACTS`（写入动作） |
| **生** | 提交一次生成（要确认）、导出成片、语音转写 | `ACTS`（花钱 / 落盘那几类） |

这三个动词不是装饰 —— 它们就是 `chat-tools.js` 里**只读查询 / 写入动作**的那条分界线，
「生」那组还标了「要确认」，先立规矩再让人用。

## 5. 判据

这一稿自己带的五条：

- **工序脊必须连得上**：一道工序一个节点，节点之间那条线不能断（否则读成两段）。
- **执行闸不能被折叠掉**：待确认的那一步在**收起态**也必须看得见金额与「待确认」三个字。
- **最新的在最上面**：工单流按时间倒序渲染（`data.js` 正序写、`demo.js` 里倒着显示）。
- **助手上方不许再摆那条上下文带**：它装的是宿主页面状态，与这一轮无关。
- **高光字不许丢**：拖进来的素材必须在正文里看得见那一段淡底高亮 + ✕ + 悬停缩略图。

判真品的时候，这五条分别对应：

- 工序节点（绿/红/蓝/琥珀）与脊线是否连成一条；
- `.ac-run` 那张确认卡是不是还挂在工序线上、金额与不可撤回写没写；
- 助手新一轮回答是不是出现在最上面；
- `.ac-ctx` 那一带是不是已经去掉；
- `.ac-ref-hl` / `.ac-ref-x` / `.ac-ref-tip` 三件套还在不在。

还有两条是审稿时补的：

- **「引用」「Skill」不许做成输入区的按钮** —— 产品里一个靠拖拽、一个出现在那一轮的消息里；
  做成按钮就是编了个产品没有的入口。
- **附件与引用不许混在一排** —— 附件是文件，引用是正文里那段高亮。

再补一条（2026-10-25 审稿时定的）：

- **纯回答不许套工单卡** —— 动过手的才配卡。硬把一段话塞进一个空卡壳里，
  是把简单的事做复杂；判据是「那一轮有没有工序 / 产物 / 要点头的动作」。
- **你发出去的那条不许被工单卡吞掉** —— 卡是**助手那侧**的容器；
  你那句永远独立显示（`.ac-me .ac-bd`），它带的东西（附件 / 引用）也跟着它走（`.ac-mfs`）。
- **号不许只藏在悬停提示里** —— 拖进来的东西带着什么号（资产号 / 任务号），
  在消息下方那排芯片上就要看得见。
- **助手那侧一律靠左、你那侧靠右** —— 谁说的话不用看颜色就分得出来。
- **引用不必写「引用素材」四个字** —— ⚠ **这条撤销了**：那圈字是**识别用的**
  （`REF_MARK` 正则），去掉会让人看不出「这一行指哪一条」；
  稿子里保留 `[引用素材：名字]`。
  但那个 ✕ 仍然去掉（标记本来就是正文里的文字，键盘能删）——
  ⚠ 并且**去掉了 ✕ 就要把语义补上**：删字即作废（§7.3），
  否则会出现「高亮没了、引用却还在、模型这一轮还拿到了」那个洞。

### 7.2 引用：**正文是真相**（这条改了产品的行为）

**改之前**：把那段引用文字改掉或删掉 → 高亮消失，但**引用还在队列里、这一轮照样发给模型**，
只弹一句警告（`refTextChanged` 里那句「但这条引用还在清单里…」）。

**改之后**：改掉或删掉 → 这条引用**作废**（队列里那条一起删、这一轮不再发给模型），
一句回执：「输入框里那段引用文字被改过了 —— 这条引用已经去掉，这一轮助手不会再拿到它：…。
资产库/收藏里的那一份没动。」

- 高亮上那个 **× 去掉**了：标记本来就是正文里的文字，键盘选中那段删掉就行。
- 对不上队列的标记（名字改了）**不再画高亮**（格式合法但对不上，就不是一条有效引用）。
- 发出时的快照（`shotRefs`）只取**正文里还对得上的**那些。

**代价（认下来的）**：新语义下「改字」与「想给这条引用换个说法」分不开 ——
改一个字就是删掉这条引用。好在它**看得见的**（高亮当场消失 + 一句回执），不是静默的，
Ctrl+Z 也能退回去。引用名要改，应该去资产库或那一页改。

**判据跟着改**：`tests/e2e/assistant-ref-open.cjs` 第 6 项从「点 ×」改成「改字」；
`tests/e2e/assistant-ref-drop.cjs` 从「必须有删除钮」改成「**不许**再有删除钮」。

### 7.3 引用发给助手时带哪些字段（默认全带）

设置页「AI 助手」卡上多一档（`ai_chat_ref_send`，默认 `all`）：
全带 / 只带地址 / 只带任务号 / 只带资产号 / 只带名字与类型。

- 它**只裁给模型看的那份清单**（`refBlock`）。工具侧（`asset_open` 按序号取）读的是这一轮
  真正发出去的那份完整记录，**裁了清单也不影响助手按序号把字节取回来**。
- 登记三处：设置页的 `EXPORTABLE`、同步侧的 `NOT_SYNC`（本机口味，不跟着 .data 走）、
  `tests/settings-schema.cjs` 的 `ASSIST`（判据⑤点名要看到助手那几颗键）。

| 输入框里那行高亮是手画的 | 产品的**镜像层 + 绝对定位**（真能跟着换行走） | 稿子是静态的，真机那套是活的 |

### 7.5 顺带发现并改掉的一个真问题：标记里塞着内部号

真产品里，输入框中那行引用标记是用 `refLabel()` 拼的，而 `refLabel` 带号：

```text
[引用素材：雨夜街道-候选 1 · 图片（资产 la_mvnjguyugslc）]
```

两个毛病：

1. **正文里一行字拖着内部 id** —— 又长又难看，用户要认的是「哪一条」，不是它的号。
2. **必须逐字一致才能对上** —— 标记里的名字要跟 `refLabel` 生成的**完全一样**（含类型与括号里的号）
   才能在队列里找到那一条。用户改一个字（哪怕只想改个错别字），这条引用就「对不上」了。

**改法**：`asset-ref.cjs` 里加一份**短名**（`shortLabel`：只有「这是哪一条」那部分），
标记用它拼，队列索引也用它；号留在两处真正需要它的地方 ——
**悬停浮层**（`.ac-ref-tip`：类型 · 资产号 · 任务号）与**发给模型的那份清单**（`refBlock`）。

改完之后标记是干净的：

```text
[引用素材：雨夜街道-候选 1]
```

号照样跟着走（悬停就能看到，清单里也有），但正文干净了，而且「改字即作废」这条新语义
也终于说得通：**短名对不上 = 这条引用作废**，不用再猜「是名字变了还是格式坏了」。

## 7. 将来要真改的那几处（这一轮**没动产品代码**，只记在稿子里）

### 7.1 引用给模型发什么：**默认全发**，设置里可裁

**决定**：默认把**图片地址 + 资产号 + 任务号**（以及名字、类型、本机文件 key）**全发给助手**；
设置页「AI 助手」卡上加一档，可以裁成「只发图片」「只发任务号」「只发资产号」「只留名字与类型」。

- **键名**：`ai_chat_ref_send`（新键）。
  ⚠ **不是** `ai_chat_refs` —— 那个是拖进来的引用队列本身，属于数据（`K_REFS`）。
- **默认值**：`all`（全带）。
- **设置页写法**（`web/pages/settings.js` 的 `SET_ROWS`，`card: 'assistant'`，
  照 `sk_polish_ask` 那一行的形状）：

```js
{ card: 'assistant', kind: 'sel', key: 'ai_chat_ref_send',
  label: '引用发给助手时带哪些', def: 'all',
  opts: [['all', '全带：图片地址 + 资产号 + 任务号（推荐默认）'],
         ['image', '只带图片地址'],
         ['task', '只带任务号'],
         ['asset', '只带资产号'],
         ['name', '只带名字与类型（最小）']] },
```

- **要动的位置**：

| 位置 | 改什么 |
| --- | --- |
| `web/features/chat.js` `refBlock()` | 按那一档过滤 `bits`（现在是无条件全带） |
| `web/features/chat.js` `shotRefs()` | 快照也要带上一档 —— 不然工具侧 `asset_open` 按序号取的那条，与发出去的清单对不上 |
| `web/features/chat-tools.js` `asset_open` | 工具描述要说明「清单里现在只带哪些字段」；取不到时的话术跟着改 |
| `web/styles/chat.css` `.ac-ref-tip` | 那一档裁掉字段时，悬停浮层里那几项也要跟着少显示（现在给的是 类型 · 资产号 · 任务号） |
| `web/pages/settings.js` `EXPORTABLE` | 新键要进导出名单（换机器导一次设置才带得走） |
| `web/ui/ui.js` `NOT_SYNC` | 登记「不跟云同步」 |
| `tests/settings-schema.cjs` `ASSIST` | 判据⑤点名要看到助手那几颗键，新键要加进去，否则判红 |

- **两条不许被裁掉的纪律**：
  ① 裁的是**给模型看的那份清单**，不是「哪几条引用算数」——
  「改字即作废」那条新语义见 **§7.3**（正文是真相）。
  ② `.ac-mfs` 那排落盘芯片（这一条带了什么）**不受影响** —— 那是给用户看的记录，不是给模型的。

### 7.3 引用被改字 = 这条引用作废（**正文是真相**）

**现状（产品现在）**：用户在输入框里把那段引用文字改掉或删掉 ——
高亮立刻消失（正则对不上了），但**引用还留在队列里、这一轮照样发给模型**，
只弹一句警告：

```js
/* chat.js 的 refTextChanged() */
note('输入框里那段引用文字被改过或删掉了，但这条引用还在清单里（这一轮助手仍会拿到它）：' + lost.join('、') + '。不想带它，用引用上的 × 移开。', 'warn');
```

**要改成**：**正文里没有了 = 这条引用就不算数** —— 队列里那条一起删掉，这一轮不再发给模型。
一句话回执：

> 输入框里那段引用文字被改过了 —— 这条引用已经去掉，这一轮助手不会再拿到它。

**为什么**：现在那套「队列是真相」有个洞 —— 用户看着高亮没了，以为自己没带它，
其实模型这一轮**还是拿到了**（还白花了一轮 tokens 看图）。
新语义下**看得见的即真相**：高亮在 = 带着，高亮没了 = 没带。少一个「以为删了其实没删」的坑。

**要动的位置**：

| 位置 | 改什么 |
| --- | --- |
| `chat.js` `refTextChanged()` | 不再只 `note()` 警告，改为把失配的引用**从 `refs` 队列里删掉**（`refs = refs.filter(...)` + `saveRefs()` + `paintRefMarks()`） |
| `chat.js` `paintRefMarks()` | `idx < 0`（名字对不上队列）的标记**不再画高亮**（现在照画 —— 格式合法就画） |
| `chat.js` `shotRefs()` / `send()` | 只发**正文里还对得上的那些**（`matchedRefs`），不是整个 `refs` 队列 |
| `chat.js` 回执话术 | 「这一轮助手仍会拿到它」这句要改掉 |
| `chat.css` `.ac-ref-x` | 若去掉 ✕，`paintRefMarks` 里挂它那一段与这条样式可以一并删 |

**代价（要认下来的那一条）**：新语义下「改字」与「想给这条引用换个说法」**分不开** ——
改一个字就是删掉这条引用。
好在它是**看得见的**（高亮当场消失 + 一句回执），不是静默的，而且 Ctrl+Z 就能退回去。
引用名（`refLabel` 取的是提示词/名字）本身要改，应该去资产库或那一页改，不该在这里改。

**与 §7.1 的关系**：不冲突，是两层 ——
§7.1 裁的是「一条引用**给模型看哪几个字段**」，§7.3 裁的是「**哪几条引用算数**」。

**稿子里怎么体现**：`shots/10-副驾台-引用失效-浅色-1440.png` ——
把标记改成缺一个右括号的样子，高亮当场消失，下面一句琥珀色回执。
稿子右下角「稿子控制」里有一颗「改坏引用」可以点着看。

### 7.2 「重构之后还能不能聊天」——能，而且聊天根本不进卡壳

一轮分两半：**你发的那条**（独立一条 + 它带的东西） + **助手的回应**。
没动手的轮次，回应就是**一条气泡**，不套卡壳：

- 你那句：右对齐一条，淡紫底（accent 淡底）—— 与产品的 `.ac-me .ac-bd` 同一形状；
- 它带的东西：附件（文件）与引用（素材）那一排芯片，跟着消息走、不可删 —— `.ac-mfs`；
- 助手那段：左对齐一条，灰底 + 细描边 —— 与产品的 `.ac-ai .ac-bd` 同一形状；
- 下面一行：复制 / 重问。

`shots/01-副驾台-固定档-浅色-1440.png` **顶上那两条气泡就是这一档**：
「「雨夜街道」这句提示词，别的平台也能用吗？」→ 三段回答 → 复制 / 重问。
再往下是「在跑」和「待确认」两张工单卡 —— **气泡与卡并排**，
一眼能分出「哪一轮只是聊了，哪一轮动了手」。

**「你发出去的那条」在工单那一轮也照常显示** —— 它永远独立，不会被工单卡吞掉：
`shots/01` 里「照这版提示词生成一条 4 秒的视频」下面挂的那排
「这一条带了 ⊠ 参考图.png 文件 / ⊞ 雨夜街道-候选 1 图片」，
就是这一轮发出去时带的东西（草稿里是输入框上的附件行与正文里的高光字，
发出去之后固化成消息下方这排记录）。

真产品里这一档就是两个 `.ac-bd` 气泡 + 一排 `.ac-mfs` 芯片，这一稿**照原样保留**，
只是把「动了手」的那一轮从一堆同形气泡里升格成了工单卡。
聊天没有被挤掉 —— 它本来就没被这套结构碰过。
