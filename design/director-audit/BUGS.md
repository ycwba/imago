### H-01 撤销 / 重做之后，视口被甩回第一场第一镜

- **位置**：`web/director/engine.js:360-374`（`restoreSnap`）、`:5523-5525`（`sanitize`）
- **触发**：在「场景 2 / 镜头二」上做一处编辑，按 Ctrl+Z（或 Ctrl+Y）。
- **现象**：编辑本身撤销了（名字恢复原样），但**整页跳回「场景 1 / 镜头一」**；
  重做之后名字回来了，视口**仍然停在场景 1**。长片子里在第 20 镜上改一处、撤销一下，就被扔回第一镜。
- **依据**：
  1. `snapOf()`（`engine.js:342-359`）在序列化时把 `curScene` / `curShot` / `curCand`
     三个键**整个剔掉**了（replacer 对每一层都生效）。
  2. `restoreSnap()` 把这份快照塞回 `WS.projects[at]`，然后调 `sanitize(); renderAll();`。
     快照里根本没有这三个键 → `proj.curScene` / `proj.curShot` 是 `undefined`。
  3. `sanitize()` 把它们兜到 0（`:5523-5524`），并**无条件**写 `proj.curCand = 0`（`:5525`）。
  4. 这一段自己的注释（`:344-349`）写的是：「剔掉它们之后……**撤销回去时视口停在当前这一镜**
     （restoreSnap 之后 renderAll 会照 proj.curCand 重画，指向的那一条仍然是它，因为那一镜的候选列表没变）」——
     **代码没有兑现这句承诺**。剔掉这三个键是为了让「翻看候选」不消耗撤销次数（这一点是对的），
     但顺手把「视口位置」也一起剔了。
- **实测**：

  ```
  改之前：{"场景":"场景 2","镜头":"镜头二","当前候选":"第 1 / 2 条","可撤销":0}
  改之后：{"场景":"场景 2 改名","镜头":"镜头二","当前候选":"第 1 / 2 条","可撤销":1}
  撤销之后：{"场景":"场景 1","镜头":"镜头一","当前候选":"第 1 / 2 条","可撤销":0,"可重做":1}
  重做之后：{"场景":"场景 1","镜头":"镜头一","当前候选":"第 1 / 2 条","可撤销":1,"可重做":0}
  ```

- **修的方向**（供决策，本报告不改）：把这三个键的**当前值**在 `restoreSnap()` 里显式存一份并还原，
  而不是让 `sanitize()` 兜底到 0；或者把这三个键留在快照里（但那样「翻看候选」又会消耗撤销次数，
  与当初剔除的理由冲突 —— 更像是「剔字段、但另外存一份视口」）。

### H-02 编辑完 500ms 内按 Ctrl+Z，横幅说「可撤销的已经用完了」

- **位置**：`web/director/engine.js:1278`（`scheduleSave` 压快照）、`:392-397`（`undo` 空栈分支）
- **触发**：改一处东西，**500ms 内**按 Ctrl+Z。
- **现象**：屏幕顶部弹出错误横幅
  `可撤销的已经用完了 —— 不是「没有可撤销的操作」`；
  而这时撤销栈里**确实有**那一步，改动也**没有**被撤销。
- **依据**：
  1. 普通界面编辑走 `scheduleSave()`：改动先落在内存里，`500ms` 合并窗口到期后才把
     **改动前**的那份（`lastSavedJson`）压进撤销栈（`:1278-1281`）。
  2. 窗口没到之前 `undoStack` 是空的 → `undo()` 走空栈分支，回一句「已经用完了」。
  3. 这个坑**代码自己是知道的**：`beginEdit()` 上方的注释（`:319-323`）写着
     「助手动作之后用户可能立刻说「撤销」，那时窗口还没到，栈里是空的，`undo()` 会回一句
     「可撤销的已经用完了」（**假话**）」——
     当时只为**助手动作**补了 `beginEdit()` 这条「当场压快照」的旁路，
     **普通界面编辑这条主路没有补**，假话还在。
  4. 附带的连带问题：这句话走 `ErrBanner`（顶部常驻横幅，要手动点 × 关掉），
     「撤销太快」会留一条常驻错误条在屏幕上，比它本来的分量重得多。
- **实测**：

  ```
  {"可撤销":1,"可重做":0,"场景":"场景 1 改名","镜头":"镜头一",
   "错误横幅":"可撤销的已经用完了 —— 不是「没有可撤销的操作」",
   "场景名":["场景 1 改名","场景 2"]}
  ```

### M-01 500ms 内连改两处，中间那一步永远退不回来

- **位置**：`web/director/engine.js:1266-1281`
- **触发**：500ms 内连续做两处独立编辑。
- **现象**：撤销一次直接回到**两处都没改之前**，中间那个状态退不回来。
- **依据**：`scheduleSave()` 的定时器在每次调用时 `clearTimeout` 重排（`:1265-1266`），
  窗口内无论改几次，最后只压**一份**快照（改动前的那一份）。中间状态没有任何地方留档。
- **实测**：

  ```
  连改两处之后：{"可撤销":2,"场景名":["场景 1 乙","场景 2"]}
  撤一次之后：  {"可撤销":1,"场景名":["场景 1 改名","场景 2"]}   ← 跳过了「场景 1 甲」
  再撤一次：    {"可撤销":0,"场景名":["场景 1","场景 2"]}
  ```

  这条本身是「合并窗口」的设计后果，不一定是 bug；但在 H-02 的背景下更难解释。

### H-13 「一家能力落定」那一下，右栏整栏重画，提示词框被换掉、焦点与光标全丢

- **位置**：`web/director/engine/panel.js:2100-2107`（`installCapRepaint`）
- **触发**：打开导演台后的头一两秒（能力接口一家一家回来），或者在右栏提示词框里打字的时候，
  恰好有一家平台的能力声明落定。
- **现象**：右栏整栏被重画，**提示词框那个节点被换掉了**：焦点丢了（后面打的字打不进去），
  光标跳到第 0 个字。文字本身还在（逐字输入已经同步进数据层），但用户会以为「框坏了」。
- **依据**：
  1. `installCapRepaint()` 监听 `wb:cap-ready`（`capabilities.js:1012` **每家平台落定就广播一次**，
     4 路并发），去抖 300ms 后直接调 `renderEditor()`（`panel.js:2105`）——**没有走 `renderSoft`**。
  2. `renderSoft()` 本来是有保护的：`engine.js:4943` 的
     `if (editingIn('#edCol')) renderPending = true; else renderEditor();`
     —— 正在右栏里编辑就先不画，等失焦再补。`installCapRepaint` **绕过了这道闸**。
  3. `renderEditor()` 会重建 `#edPrompt` 这个 textarea（节点整个换掉）。
  4. `renderSoft` 那条注释写得很清楚：「正在编辑的栏先跳过（**重建会把输入框换掉，焦点和光标全丢**）」——
     `installCapRepaint` 正好踩的就是这一条。
- **实测**：

  ```
  前：{"值":"原来的描述我正在打字","焦点在框里":true,"光标位置":10}
  后：{"值":"原来的描述我正在打字","同一个节点":false,"焦点还在框里":false,"光标位置":0}
  ```

### H-07 「导出 SRT」写的是候选源秒，不是成片秒 —— 全片字幕时间轴整体错位

### H-12 拖走一段之后，那句台词的落点会跳到另一段去

- **位置**：`web/director/engine.js:2877-2884`（拖走段的落点回落）、`web/director/line-point.js:30-32`（夹取口径）
- **触发**：把画面轨上的一段拖到别处（横拖 = 重排），而这一镜有台词落点。
- **现象**：台词落点（以及那个「待生成配音」占位块）跳到了**另一段**上，
  而它本来所在的那一段根本没动。
- **依据**：两种口径打架：
  1. `linePointClamp`（`line-point.js:30-32`）把秒数夹到这一段的选区 `[s.in, s.out-0.1]`
     → **`sh.lineAt` 是绝对源秒**。其余所有写入方（`lanes.js:868`、`:900`、`track.js:462`）都按绝对秒传；
     `voice.js:144-145` 也正是靠 `pt.at - s.in` 才换出段内偏移。
  2. `engine.js:2880` 却把它当**相对**算：`const abs = host.in + lpOld.at`（多加了一次 `host.in`），
     紧接着 `:2884` 又把 `abs - now[ni].in`（相对值）写回去，被 `linePointClamp` 按绝对区间夹一次。
  3. 举例：段 [0,10] 与 [10,20]，台词在第 2 段绝对 15 秒 → `lineAt=15`。
     把第 1 段拖到第 2 段后面 → `abs = 10 + 15 = 25`（应为 15）→ 找不到含 25 的段 →
     落到最后一段 → 写回 `25 - 0 = 25` → 被夹成 `9.9` → 台词落到**另一段**的 9.9 秒。
  4. 这一段自己的注释（`:2877`）写的是「台词落点按**绝对源秒**找回落点所在段」—— 注释说的与代码做的相反。
- **实测**：探针喂一份两段工程（框 [0,10] / [10,20]，台词在第 2 段绝对 15 秒），
  用 CDP 派发真实 pointer 事件把第 1 段拖到第 3 个位置 ——
  轨道确实重排成了 3 格（空段 + 段 2 + 段 1），状态条回执
  「✓ 第 1 段挪到了第 3 个位置，原位自动空出 10 秒黑场」，
  与上面推演的空段/次序完全一致。
- **交叉印证**：轨道剪辑那一路的走查独立发现了同一条（它评为「中」，本报告按后果定为「高」）。

### H-11 单文件 FCPXML 导出里，本机素材的 file:// 路径指向不存在的文件

- **位置**：`web/director/fcpxml.js:96`
- **触发**：点页头那颗「导出 FCPXML」（`bundle: false` 那一条），且某几段素材已存进本机资产库。
- **现象**：导入 Final Cut / 达芬奇后**全部本机素材显示离线**，用户要自己按名字重新链接。
- **依据**：

  ```js
  const p = assetsDir.replace(/[\\/]+$/, '') + '/' + la + '.' + ext;   // <库根>/la_xxx.mp4
  ```
  而 `assetsDir` 取自 `sys.目录.资产.路径` = `localRoot()`（**库根**）；

  ```js
  return { dir, file: zh + path.sep + file, abs: path.join(dir, file), ... };
  ```

  于是页面按自己的理解拼了一个错的。
  媒体包那条出口（`bundle:true`）走 `media/<名>` + 代理回源，不受影响 —— **只有「导出 FCPXML」这一颗坏**。

### H-08 / H-10 字幕与「当前候选 / 选用候选」的两把尺子对不齐

这两条是同一族：**「正在查看的候选」（`proj.curCand`）与「选用的候选」（`sh.selId`）各被当成了「当前」**。

- **H-10 本镜轨的几何用「当前查看的候选」，字幕数据却属于「选用候选」**
  - `lanes.js:253`：`renderTimeline(col, sh, cands[projOf().curCand] || cands[0]);` → 几何取**预览中**那条。
  - `sub-lane.js:229`：`mapToShot(sh, cur.entries, { cand: c })` —— `c` 是同一条预览候选，
    但 `cur.entries` 来自 `subCurrent(sh)` → `currentOf` → `chosenCandOf(sh)` = **选用**那条的源秒。
  - `sub-lane.js:90` / `:195`（拖动与改时间）又换回 `chosenCandOf(sh)` = **选用**那条。
  - **现象**：① 右栏字幕清单与本镜轨的字幕块按预览候选的几何折算，数据却是选用候选的源秒 → 时间点整体漂；
    ② 拖动字幕块松手那一刻用另一把尺子折回 → **块跳位**；
    ③ 紧挨着的配音轨用 `shotVoices(sh.id, c.vid)`（预览候选），字幕轨却拿选用候选的数据 → 同一排里两行说的不是同一条候选。
- **H-08 换「选用候选」后，手改 / 识别的字幕既不重映射也不清除**
  - `subtitles.js:160-174`：`source` 为 `manual`/`asr` 时走不到重派生分支，条目原样保留，
    而条目的源秒是**上一条候选**的时间轴。
  - **现象**：同一条字幕的成片时间整体平移或被夹到段首，**导出与烧录都不提示**
    （右栏「字幕」档有 stale 提示，但导出路径不看它）。
  - **实测**：切候选前 `stale=true`；切到段布局不同的 `v2` 后同一条仍是 `startMs:3000/endMs:5000`，
    但 `mapToFilm` 结果 `ok:false`（已被夹）。
  - 附注：派生源（`line+voice`）的字幕换候选后会整体消失重派生，这是设计内；出问题的是手改/识别那一份。

#### H-04 助手的「第 N 条候选」是活下标：check 与 run 之间候选一重排，就改到另一条

#### H-16 拖走一段补出来的「空段」不带倍速 → 成片总时长与黑场长度凭空变了

- **位置**：`web/director/engine.js:2869-2873`（造空段）、`:2888-2889`（回执）
- **触发**：把一段**倍速 ≠ 1**的画面段在本镜轨上左右拖到别处。例如一段源 0–10 秒、倍速 ×2（成片占 5 秒）。
- **现象**：回执说「原位自动空出 5 秒黑场」，但补出来的空段没有 `spd` 键 →
  `segSpd()` 读成 1（`web/director/segments.js:25-26`）→ 成片里这段黑场实际占 **10 秒**，不是 5 秒。
  成片总时长比用户预期多 5 秒，后面每一段在成片里整体后移，导出/烧录/字幕全部跟着偏。轨道上那一格也真的变宽了一倍。
- **依据**：`segsWrite → segsOf → segCarry`（`segments.js:43-65`）只在 `sp !== 1` 时写 `spd`；
  `tlFromShots` 用 `speed: segSpd(s)`（`projection.js:62`），`tlClipDur = (out-in)/speed`（`segments.js:8`），
  导出侧同样按 `(c.out-c.in)/c.speed` 累加（`engine/export.js:182`）。所以空段的 1 倍速直接改写了成片时长。
  同一段还带着 `spd=2` 时，回执的 `segFilmLen(me)`（÷2）与实际空段（÷1）就是两个数。

#### H-17 全片轨播放时播放头算错：剪掉片头后，针与插针读数整体偏一个「被剪掉的片头」

- **位置**：`web/director/playback.js:300-304`（`frameT`）、`web/director/plan.js:48/50`
- **触发**：在全片轨上把某一段的左把手往右拖（剪掉片头），然后在「全片」页签点播放。
- **现象**：播放刚开始，剪辑针就落在那一格的**中间**而不是开头；工具条「插针 N 秒」读出来的源秒
  比该段真正的入点多出「被剪掉的片头 × 倍速」。剪得越狠偏得越多（片头剪掉 6 秒、该段只剩 4 秒时，
  针直接跑到轨道末尾之外，`proj.cutAt` 被写成该段的 `out`）。
- **依据**：
  ```js
  frameT() {
    const c = this.plan[this.idx];
    if (!c) return this.t;
    return round1(c.fs + (c.in - c.fa) / c.rate + Math.max(0, this.t - this.starts[this.idx]));
  }
  ```
  `filmFrames` 的 `start`/`w` 是按**选区**排的（`timeline.js:104-106`，`w = d/sp`，`d = f.out - f.in` 是选区长），
  所以轨道那一排的轴 = 选区轴；但 `frameT()` 又额外加了一项 `(c.in - c.fa)/rate`，
  那是「框左沿到选区左沿」的差 —— 这是框基排版时代的遗留，现在等于把剪掉的片头**重复加了一遍**。
  对照：`filmPinT`（`lanes.js:1163-1166`）用 `srcToFrame(r, cutAt)`，是纯选区口径（对的），
  `filmApplyAt` 却拿 `nowT()`（= `frameT()`）去 `paintPin`（`lanes.js:1222`）——
  于是「静态针」和「播放中的针」永远差一个片头。

#### H-18 点图片段（静态图 / 虚拟坐标）时插针被夹回视频末尾 → 剪子剪的是另一段

- **位置**：`web/director/engine.js:3073-3083`（`setPin`）、对照 `web/director/engine/track.js:351-366`（`cutPin`）
- **触发**：在「本镜」轨上点一格**静态图段**（图片段的坐标是排在视频总长之外的虚拟秒，见 `image-seg.js` 顶上说明），
  然后按「切开 / 向左切 / 向右切」。
- **现象**：针不落在那张图上，而是被顶到视频的末尾；`proj.cutAt` 变成 `total`（视频最后一秒）；
  按「切开」时剪子把**视频的最后一段**切成两半，而不是切开那张图。
  图片段的「切开」（`cutSegs` 里有专门的 `imageTailSeg` 支路）实际上永远走不到。
- **依据**：`pinMeasure`（`lanes.js:396-402`）把图片段的虚拟秒原样交给 `setPin`，
  `setPin` 的 `total` 是 `candDur`（**视频**时长），于是虚拟秒被夹掉。

  只能退回读播放器的 `currentTime`（图片段处甲板是停的 → 读到旧位置）。两处夹取口径不一致。

#### M-24 识别进行中，按钮仍写「自动识别」—— 第二下其实是取消

#### M-26 成片指纹漏了图片段的 img/imgName/gap/vc，与时间线那一层的口径不一致

- **位置**：`web/director/engine/export.js:340` vs `web/director/projection.js:90`

#### M-27 「保留片段 __ – __」两框显示的是选用候选的秒数，写的却是当前候选

- **位置**：`web/director/engine.js:3153-3165`（读）、`web/director/engine/mid.js:746-774`（写）、`web/director/engine/mid.js:183`
- **触发**：这一镜有两条以上候选，只「用这条」选了候选 A，但当前在看候选 B
  （点候选缩略图即可，`engine.js:1692` 只改 `proj.curCand`）。此时轨道画的是 B 的格子，入出点两框里却是 A 的秒数。
- **现象**：在框里填一个数字并「应用」→ 改的是 **B** 的入出点，而框里刚才显示的是 **A** 的数字。
  用户以为改了 A，实际动了 B；回执也不提示是哪一条。

#### M-28 「删掉这一段」的回执报的是源秒，说的却是「成片里出 X 秒黑场」

- **位置**：`web/director/engine/track.js:416`（同一句里的另一个数）与 `:425-427`
- **触发**：把一段 ×2 的画面段「删掉」（变黑场）。
- **现象**：同一条回执里，一句写「这一条现在共 5 秒」（成片秒），另一句写「成片里出 10 秒黑场」（源秒）——
  两句自相矛盾；用户按「成片里出 10 秒」去对总时长对不上。
- **依据**：黑场段保留了原来的 `spd`（`track.js:301` 用 `Object.assign({}, s, {off:1})`），
  所以它在成片里占 `(out-in)/spd`；回执却用 `out - in`。
  正确的读法是 `segFilmLen(newSegs[grayIdx])`（同文件 `track.js:1146` 已经这么用了）。

#### M-29 联动把配音挪到下一段时，会往数据里写一个负的 `fa` → 配音的「可恢复框」被静默清掉

- **位置**：`web/director/engine/track.js:400-406`、同样写法在 `:242-243`
- **触发**：勾了「主轨联动 → 语音」，把主轨某一段变黑场；该段上有不在段首的配音（`v.at > 0`）。
- **现象**：配音挪过去了，但它的「框」被清成 `[0, dur/倍速]` —— 之后拖左把手再也放不回原来被切掉的那一截
  （提示里「往外拖把手能放回来」的那句变成假话）。数据里还留着一个负数 `fa`。
- **依据**：`voiceFrameOf` 在 `at` 被改成 0 **之后**才被调用，此时 `fr.fa = Math.min(fa, at=0) = 0`，
  于是 `v.fa = 0 - d = -d`。正确做法是先用旧 `at` 求 `fr`、再平移。
  `voiceFrameOf` 读的时候会把负 `fa` 当成坏数据重置（`voice-layout.js:47-51`），于是「放不回来」在界面上没有任何提示。

#### M-30 全片轨的插针读数与画面用的不是同一把尺子

- **位置**：`web/director/timeline.js:59-64`（`f0`/`fd` 与 `start`/`w`）、`web/director/plan.js:29-37`（注释与实现）
- **触发**：全片轨播放、剪辑、或点轨道。
- **现象**：`f0`（成片秒）与 `start`（轴秒）在当前几何下**数值恒等**（两者都是 Σ `(out-in)/spd`），
  代码却仍按「两根不同的轴」来算，多出来的那一项 `(c.in - c.fa)/rate` 就是 H-17 的根因。
- **依据**：`filmFrames` 的 `d = f.out - f.in` 取的是**选区**，`tlClipDur(cl)` 用的是 `cl.out - cl.in` = 同一段选区，
  所以 `w ≈ fd`、`start ≈ f0`。也就是说 `axisGray`（`timeline.js:79-84`）与 `filmLayGray` 现在其实是同一把尺子，
  只有 0.05/0.1 两个下限带来的微小差；`plan.js` 里那段「框基轴 vs 成片秒」的说明已经是过时的。

#### M-31 全片轨拖动把手时，中间态用「拖动前」的总长做分母 → 后面每一格在右端溢出

- **位置**：`web/director/engine/lanes.js:1258-1275`
- **触发**：在全片轨上拖某一格的手把（把这一格拉长/压短），拖动过程中盯着轨道右端。
- **现象**：拖动过程中后面的格子整体越过轨道右端（按旧总长排、按新几何算宽度），画面出现一条空白/溢出；
  松手整栏重画才恢复。
- **依据**：`total` 是 `bindFilmDrag` 进来时捕获的拖动前总长，而 `r.start/r.w` 来自拖动后的新几何
  （`tlSyncFromShots` 每次都重算）。代码注释说这是有意的（刻度尺中途不动），
  但结果是拖动中轨道右端看起来「炸开」。

## 5. 这次审计怎么做的（可重跑）

运行时探针用仓库现成的隔离 harness（`tests/e2e/harness.cjs`）：每个探针自起一个隔离代理
（独立的 `.data-probe-*` / `.assets-probe-*` 目录）与一个 headless Chrome，互不踩。

- **撤销栈四条（H-01 / H-02 / H-03 / M-01）**：喂一份固定工程 → 操作 → 读助手桥 `context()` 的
