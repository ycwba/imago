## ② 复查揪出的回归 / 漏网（全部已修）

这一节是本轮真正的产出：**完成报告说修了，复查发现修得不对或修出了新洞**的五个地方。

### R-1 「结算未落盘编辑」在 beginEdit 链上压了一份过期快照 —— 一次撤销退过头（高，已修）

- **位置**：`web/director/engine.js` 的 `settlePendingEdit`（H-02/H-03 的修复件）
- **触发**：beginEdit 链的编辑（切一刀、拖走一段……）之后 500ms 内按 Ctrl+Z。
- **现象**：一次撤销直接退到**上一次落盘**——比这次编辑更早好几步。
  `tests/e2e/director-image-track.cjs` 的「拖走自动空并撤销」当场抓住：拖走后段数 4，
  Ctrl+Z 一下退到 1 段（应该是 3 段）。
- **根因**：beginEdit 已经把「改动前」压进栈（`undoPushed` 亮着），而这条链的改动还没落盘；
  此时 `settlePendingEdit` 又把 `lastSavedJson`（**更早**的落盘态）压了一份到栈顶。
  撤销弹到的是那份旧状态，不是这次编辑之前的那一份。
- **修法**：`undoPushed` 亮着就不再结算（那条链的「改动前」已经在栈里）；只有纯 scheduleSave
  那一路（提示词 / 参数输入）才需要补压。恢复成功后把 `undoPushed` 归位，
  否则恢复之后 500ms 内的下一次输入编辑会被当成「已有链」跳过结算。

### R-2 老存档的「无主针」被归属闸全拒 —— 配音落点退回段首（中，已修）

- **位置**：`web/director/engine.js` 的 `ownPinToView`（新增）
- **触发**：升级前的存档只有 `cutAt` / `cutSeg`，没有本次修复新增的归属字段 `cutShot` / `cutCand`。
- **现象**：`tests/e2e/director-voice-lane.cjs` 当场抓住——种子里「插针停在 2.5 秒」，
  加一句配音却落在 +0 秒（针被当成别人的，回落第一段起点）。
- **根因**：M-19 的修复（针只在本镜本候选时才用）把**存量针**也拒了。
- **修法**：装配 / 恢复老快照时，把没有归属的针认给**当时看着的那一镜那一条候选**
  （它本来就停在那里）；此后归属只由 setPin 改写。这样判据里的「落针工作流」保住，
  M-19 的串台（换镜 / 换候选后拿旧针）照样拦住。

### R-3 台词时间读数在打字时退回「段起点」（中，已修）

- **位置**：`web/director/engine/panel.js` 的 `lineTimeFor`
- **触发**：M-18 修复后，整份重画那一路传了落点秒；但**打字时的就地重算**（`paintLineWhen`）
  还是两参调用——落点秒没有存进几何缓存，退回 `(r0.s).in`（段起点）。
- **现象**：落点挪到第二段之后，初渲染读数对，敲一个字读数跳回段首，失焦重画又跳回来。
- **修法**：落点秒存进 `lineGeoCache`（`geo.at`），`lineTimeFor` 缺省读它 —— 两路同一份数。

### R-4 桥的身份校验比错了对象（中，已修）

- **位置**：`web/director/engine/bridge.js` 的 `dirRun`
- **触发**：第一版 H-04 校验在 run 开头用 `candOf(curShot(), a)` 重算——op 用 `scene` / `shot`
  指向**别的镜头**时，take 是拿「当前镜」的候选列表验证的，可能误拒或误放；
  且 `set`（改片段 / 字幕）两条 check 结果没带 `pid` / `vid`，身份闸对它不生效。
- **修法**：pid 在 run 开头一次判完；vid 由各 op 分支在**按同一份参数重算出 plan 之后**
  与 `chk.vid` 比（plan 认镜认候选用的就是同一份参数，跨镜跨候选都不会比错对象）；
  set 的两条 check 结果补上 `pid` + `vid`。

### R-5 ASR 短条目只数了「太短」的，整句落在被剪区间里的照旧静默吞（低，已修）

- **位置**：`web/director/engine.js` 的 `subAsr`
- **修法**：中点不在任何保留片段里的条目同样计入 `droppedShort`，回执一句说清（L-07 的另一半）。

## ③ 遗留观察项（不构成 bug，记录在案）

这些是复查时读到的「行为要留心」，不修的理由各附一句：

1. **批量生成与提示词框在「翻看候选」时可能不同句**（M-04 修复的后果）：
   单发「生成这一镜」按**框里那句**发；「生成全部分镜」按**这一镜的描述字段**（`sh.prompt`）发。
   翻看一条旧候选时框里显示旧句、批量发的却是描述字段——批量审查弹窗里逐镜列出的就是要发的正文，
   用户看得见，所以不改。要彻底一致得给批量也走 `promptTextOf`，那是行为变更，留给产品定。
2. **媒体时长回填会压一步撤销**：播放器 `loadedmetadata` 把真实时长写回候选（`mid.js` 的
   `pl.onloadedmetadata`）走的是非静默 `scheduleSave()`——它确实改了工程数据，进撤销栈说得通，
   但它是自动发生的；量级（一条候选最多一次）可接受。
3. **`engine.js` 的 `subCurrent` 仍走 `voicesEnsure`**：首次渲染会在工程上建一个空 `voices: []`。
   桥与 track 的只读路径已改 `voicesRead`；这一处量级是「多一个空数组字段」，不影响撤销
   （静默保存不压栈），收尾留给下一次触碰这一片的时候。
4. **§4 疑点的复核结论**（BUGS.md §4 未列入正式条目的那批，本轮能闭的闭掉）：
   - #5 `setForceMid(true)` 的消费时机：轮询路径靠 `updateMidLive` 就地换媒体 + `filmEdited`
     的整栏重画兜底，`forceMid` 滞留无副作用——维持现状。
   - #10 「向左 / 向右切」对虚拟段：`cutSegs` 的 virt 分支经 `keep`（segCarry）把 a/b 一起写回，
     **实际生效**，与 H-19（把手）不同源——疑点闭掉。
   - #6 多标签页 `K_WS_UNLOAD` 救生包互踩：仍无互斥保护，维持「没有防护」的记录。
   - 其余各条维持原判（探针时序 / 需要产品决策）。
5. **FCPXML 导出同样静默跳过「没选用候选」的镜头**：M-13 只修了「导出成片」；
   媒体包 / 单文件 XML 的时间线里那几镜也不在，文件开头只有素材缺失注释。
   等真有人用 XML 那条路反馈再加同一句报数。
